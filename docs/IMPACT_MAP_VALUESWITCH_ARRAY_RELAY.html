Value Switch — conditional array relay

Make valueSwitch select between two NeighborIndex arrays on every compile target. Today JS does it for free; WASM & WebGPU reject it. This brings them into lockstep.

1 · The graph the user built (legal in the editor today)

NeighborIndex array (NI[ ]) scalar value Both If and Else are NI arrays → Result is an NI array.

2 · Compile status — before vs after

The error today: pickRandomNeighbor: input "indexes" must come from an array-producing node … — because isArrayProducer('valueSwitch') is false.

3 · Why it's tricky — Value Switch is dual-mode

Its output shape equals its input shape, which nodeType alone can't tell. A new context-aware predicate answers it (memoised, recursive for nested switches):

producesArray(node, ctx): if isArrayProducer(node.type): return true // filterNeighbors, joinNeighbors, … if node.type == 'valueSwitch': ifSrc = source feeding node:ifValue elseSrc = source feeding node:elseValue if !ifSrc || !elseSrc: return false // a branch is an inline scalar → scalar mode return producesArray(ifSrc) && producesArray(elseSrc) return false

Replaces the source-node isArrayProducer(...) checks (6 sites in WASM, ~10 in WebGPU) — the gate inside resolveInputArray plus the aggregate/groupOperator/setNeighbor*ByIndex disambiguators. One array branch + one scalar branch ⇒ the emitter raises a compile error (shapes must match).

4 · Per-target array-relay emit

JS  consumer fix

// producer: relays for free const _v_sw = cond ? _v_fnA : _v_fnB; // consumer: was [_v_sw] (wrong!) // now passes through: const _pickArr = _v_sw;

sourceYieldsArray() stops the isArray-input from wrapping the relay in a 1-element array.

WASM  zero-copy select

// both arrays already in scratch off = select(ifOff, elseOff, cond) len = select(ifLen, elseLen, cond) // Result ArrayRef points at the // chosen one — no element copy assert ifElem == elseElem

Bump-pointer scratch already holds both branches; pick the offset/len pair.

WebGPU  copy loop

var res: array<i32, MAXLEN>; var res_len: i32 = 0; if (cond) { for k<ifLen { res[k]=ifArr[k]; } res_len = ifLen; } else { … elseArr … }

WGSL fixed-size var<function> arrays can't alias, so copy the selected one.

Downstream, every array consumer reached through the shared resolveInputArray gate benefits uniformly — pickRandomNeighbor, arrayElement, arrayLength, forEachInArray, aggregate/groupOperator, setNeighborAttributeByIndex, …
