Vector attribute type + Orientation STEP 5c · branch absorb_old_automatosgt

A first-class stored vector attribute (a per-cell / per-agent 2D–3D direction), then the FOV facing heading source that reads it. The elegant bit: a vector attribute is lowered to scalar floats before any target compiles — exactly like a vector wire is today.

Principle. vector is already a wire type that expandComposites.ts lowers to scalars pre-compile. We give the stored type the same treatment: one vector attribute becomes N scalar float components <id>_vx/_vy/_vz — mirroring how color stores _r/_g/_b. Every downstream layer (all 5 compilers, the worker SoA, save/load) then sees only scalar floats — already verified on every target, 2D+3D. dims = is3d ? 3 : 2.

2 · Storage lowering — one vector attr → N scalar float buffers

Because the components are plain float attributes, no compiler/worker/fileOps layer needs a vector arm — they only ever see scalar floats. The lowering is the only vector-aware code, plus the UI.

3 · Node lowering — reuses the verified composite path

Set Vector Attribute mirrors it: vector wire → Break Vector → setAttribute(_vx/_vy/_vz). Two new nodes, zero new per-target emit.

5 · Risks & verification

Top risks
  • ATTR_TYPE_MAP silent float64 — a vector attr not expanded before save corrupts it. Mitigated: expand at the worker-init seam so file I/O only sees float components.
  • Cross-target divergence — mitigated by the lowering (components are plain floats; no per-target vector arm).
  • UI-vs-compiler list split — agentAttrsOf/cellAttrsOf feed BOTH; UI keeps the raw one-vector list, compilers/worker get the expanded list. Audit every caller.
Verification matrix
  • tsc + build.
  • Dev-harness compileAll — cell + agent vector model, JS/WASM/WebGPU, 2D+3D.
  • Real worker run per target — store & read back a vector via getState.
  • Save/load a .gcaproj/.gcastate with a vector attr.
  • JS↔WASM agent parity + a facing-vector → FOV heading synthetic.
  • Real-GPU WebGPU shader compile for the facing-vector FOV path.
  • Adversarial review workflow.

Out of scope (v1): model vector attrs, vector as a sub-attribute parent, vector→color mappings / aggregation.
