Macro Reference Export & Import Resolution

Illustrated plan — companion to docs/IMPACT_MAP_MACRO_REFERENCES.md. A .gcamacro carries the model elements its nodes reference; importing it asks, per element: Import as new · Remap to existing · Discard.

1 · The problem, in one shipped file

today

public/macros/Colorize From Neighbors number.gcamacro

"nodeType": "outputMapping",
"config": {
  "mappingId": "new_mapping_mo9xiuadam3"
}

An id that exists in exactly one model on earth. Dropped anywhere else: an amber badge and a manual re-point.

after

The same file, plus:

"references": {
  "mappings": [ { "id": "new_mapping_mo9…",
                  "name": "viz", "linked": true,
                  "linkedAttributeId": "alive", … } ],
  "attributes": [ { "id": "alive", … } ]
}

Import offers to create them, point them at what you already have, or discard — today's behaviour is the third button.

The governing property. Zero references ⇒ the file and the import path are unchanged. All-Discard ⇒ byte-identical to what ships. The new path is a strict superset, so it cannot regress the old one.

Default per row

  • id already in model B → not a row (resolved)
  • exact name + compatible type match → Remap, shown as a suggestion
  • otherwise → Import as new
  • Discard is never a default — but it is always one click, and it is today's behaviour

Warnings, never blocks

  • Bonds / Agents / Variegation capability off → element imported, marked inert
  • Remap target declares different input-mapping parameters → stale channel edges, reported by the compile gate
  • Tag options / tag names / categories with no counterpart → left as-is and reported, never clamped

5 · What “remap” has to rewrite — three passes, not one

The single sharpest edge. Two of the three reference carriers are not config values. A rewrite that only walks Object.entries(config) looks perfectly healthy and silently drops a bond's initial value — no badge, no compile error, no console line.

…and the values that are only meaningful relative to the remapped element

6 · Audit — what KEY_SPACE does and does not know

danglingRefs.KEY_SPACE is the closest thing to a registry of “which config key names which id space”. Collection extends it rather than widening it — widening changes the compile gate for models that run today.

presetIdpresetgapbadged; never carried — .gcapreset owns presets

Pre-existing bugs found in passing, recorded not fixed: a deleted bond attribute leaves its edge behind (no patchAllEdges in that cascade); the tag-reorder _port_value remap has asymmetric coverage across the cell / agent / bond paths; and REMOVE_MACRO, DELETE_PRESET and face-palette removal have no node cascade at all.

7 · Phases

M1
Collection, schema, export — import unchanged
Nested-def bundling (fixes a real pre-existing gap: a nested macro’s def is not in the file today) · macroReferences.ts · MacroFile types · export dialog · harness Tier A.
Files get richer; an older build ignores the new fields entirely, so this phase cannot regress anything.
M2
Import resolution — the feature
The dialog · the three rewrite passes · the by-name index/label remap · IMPORT_MACRO_BUNDLE (one atomic dispatch) · harness Tiers B–E · real-UI verification · docs.
M3
Reach and polish
Palette default-macro drops through the same path · tag-index straggler audit · optional “also enable the required capability” · re-export the shipped macros with references, turning three of them from “drops dangling” into “drops working”.

Deferred, with reasons

  • Cross-tab clipboard references — its localStorage payload is capped at 2 MB and shares the ~5 MB origin quota. Attributes are cheap; sprites are not. Paste keeps today's badge behaviour.
  • Presets — .gcapreset owns them.
  • Auto-enabling a capability on import — far larger blast radius than an import should have.
  • Name-based auto-mapping without a prompt — a name match is a suggestion, never a silent rewrite.
