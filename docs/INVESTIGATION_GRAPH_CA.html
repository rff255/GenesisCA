The finding that drives everything: on a variable-degree graph there is no fixed neighbor count and no canonical neighbor order, so a homogeneous rule cannot be positional. Every well-defined graph-CA rule must read neighbors through an order-independent, degree-tolerant aggregate — count, sum, density (sum÷degree), mean, threshold. GenesisCA's GetNeighborsAttribute → Aggregate idiom is already exactly this, and its hot loop already reads neighbors through an opaque index table — so a graph mode is an extension, not a rewrite.

01 A lattice is just a special-case graph

A classical CA is the tuple (D, Σ, N, τ) — a regular lattice D, state alphabet Σ, a fixed neighborhood template N, and one transition function τ applied everywhere. A regular grid is simply a degree-regular, vertex-transitive graph: every cell has identical local structure. Replace D with an arbitrary graph and that regularity — fixed arity, a canonical order, the same shape at every node — disappears.

02 The core problem → rules must be aggregate-based

Two properties any homogeneous graph rule must have: degree-robustness (well-defined across the degree distribution) and anonymity / permutation-invariance (independent of any neighbor ordering). The resolution the whole field converges on — from Marr & Hütt's "isotropy" to Grattarola's GNN message-passing — is identical: consume neighbors through an order-independent aggregate.

For d=2 the density taxonomy recovers exactly the 64 outer-totalistic elementary CA rules; a 0/1-exchange symmetry collapses them to 34 distinct rules, of which 14 are "topologically sensitive" and 4 (ECA 37, 108, 109, 133) change Wolfram class under rewiring — verified verbatim from Marr & Hütt 2009, and the ready-made demo seeds for §5.

04 The degree-normalization device

A raw count threshold means different things at different degrees: "3 live neighbors" is the whole neighborhood at degree 3 but a tenth of it at degree 30. Dividing by the local degree — ρᵢ = (1/dᵢ) · Σⱼ xⱼ — makes one rule portable across the whole graph. This is the single most load-bearing property of the feature, so a NeighborDensity node should be first-class.

05 The headline payoff — "hold the rule, swap the topology"

Because the rule stays formally fixed while the graph changes, dynamical change is attributable to topology alone. Running the same compiled rule on a ring vs. a small-world vs. a scale-free graph can move the system between Wolfram complexity classes. This is a genuine differentiator for a CA IDE and the natural MVP demo.

07 How to store varying neighborhoods — CSR adjacency

Today the engine builds a dense, uniform-stride table (total × nSz) — every cell has the same neighbor count. A graph needs a ragged structure: Compressed Sparse Row = a per-node offset array + one flat neighbor array. Node i's neighbors are colIndices[ rowOffsets[i] .. rowOffsets[i+1] ]. The SoA per-attribute state arrays are unchanged.

Today — dense & uniform

One Int32Array of size total × nSz per neighborhood. Every cell has the same count. Built by buildNeighborIndices() from (dr,dc) offsets + torus modulo. No way to express variable degree.

Graph — ragged CSR

rowOffsets[N+1] + colIndices[E], loaded from the model's adjacency. Variable degree, no padding. The hot loop already reads through an opaque index table — only the stride changes.

08 The compiler change (all three targets, in lockstep)

The neighbor read is already table-indirected, so there is no coordinate math in the hot loop to rewrite. The only grid coupling at the read site is the constant stride idx * nSz. It becomes a data-dependent CSR slice.

▼ Lattice — uniform stride

// every cell: exactly nSz neighbors
const _nb = idx * nSz_nbr;
for (let n = 0; n < nSz_nbr; n++) {
  const _ni = nIdx_nbr[_nb + n];
  sum += r_state[_ni];
}

▼ Graph — CSR slice (variable degree)

// each cell: its own neighbor range
const _nb = rowOffsets_nbr[idx];
const _ne = rowOffsets_nbr[idx+1];
for (let k = _nb; k < _ne; k++) {
  const _ni = colIndices_nbr[k];
  sum += r_state[_ni];
}
  • Scratch arrays (GetNeighbors/FilterNeighbors) size to maxDegree, not a constant — and maxDegree must be a derived-on-change single source of truth (stale value → memory corruption).
  • The "neighbor index" value type stops being a packed (dr,dc) offset and becomes a node id — resolved via colIndices[offset+k], not row±dr / col±dc arithmetic. WASM/WebGPU must bypass (not just swap) their baked grid-width/height literals.
  • Node ids capped below 0x80000000 so they never collide with the INVALID_NI "no neighbor" sentinel.
  • Exit gate: the existing cross-target byte-shape parity check (diff JS step code vs WASM bytes vs WGSL) on a small graph model.

09 Visualizing the graph — reuse the state buffer, replace the geometry

The lattice renderer's speed comes from blitting one ImageData for the whole grid — fundamentally incompatible with per-node drawing. But the worker's per-cell colors buffer (one RGBA per node) and the index-keyed inspect/paint protocol are reused unchanged. A sibling drawGraph() path is chosen by topology.

11 Silent-corruption hazards to pin first

From the adversarial review — these fail quietly (wrong results / memory corruption), not loudly, so they must be contracts decided up front.

maxDegree lifecycle

Scratch is sized to max degree. A stale value after Regenerate/Import overflows scratch — the exact class as the Amphiphile NI-poisoning bug. Make it derived-on-change, re-uploaded to the worker, re-baked into WASM.

node-id ⟂ INVALID_NI

INVALID_NI = 0x80000000 is a valid-looking i32. Cap node ids below it or the "no neighbor" sentinel collides with a real node (25M < 2³¹, so harmless in practice — but must be documented at the codec).

reinit guard

attrsStructurallyEqual decides full-reinit vs soft-recompile. Topology fields aren't in its compared set today — a "Regenerate" could soft-recompile and run the old CSR. Add topology to the guard.

graph .gcastate load

applySimulationState validates gridWidth/gridHeight before loading. A graph snapshot has nodeCount; mismatches must be rejected cleanly, not silently abort (no try/catch around deserialize today).

One source of truth for the mode: drive everything off graphTopology?.enabled (mirror variegatedCells); leave the dead topology enum derived/display-only. Add worker-side mutual-exclusion safety nets (graph ⟂ variegated, graph ⟂ WebGPU until later) for hand-edited files.

13 The ambitious tier — Structurally Dynamic CA

SDCA (Ilachinski & Halpern 1987) make the topology itself a dynamical object: a second "link rule" adds and removes edges as a function of cell states — a dual coupling between value dynamics and structure dynamics. This is a different beast and is deliberately scoped out of MVP.
