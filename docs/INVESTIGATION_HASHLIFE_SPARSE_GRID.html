1 · What already ships — the active set, drawn

SHIPPED — Skip Isolated Empty Cells
source cell (non-empty) ACTIVE (within range of a source) — stepped inactive — skipped entirely
The mechanism. Each non-empty cell dilates by the user's processing range (here Moore r=1, so a 3×3 square). The union is the active list; the compiled step iterates that list instead of 0..total. Reference-counted (nearCount), so it is correct when cells go empty again — and state-defined, not change-tracking, which is why it survives a load, a paint or a reset with a single rebuild.
GAP — the predicate is ONE value of ONE attribute

Wildfire: neither available choice works

The shipped Wildfire - Sierra Nevada has state ∈ {Unburned, Burning, Burned}. Burned is a terminal, non-empty, permanently static state — and the config can name only one value as “empty”.

Today — empty = Unburned
The scar is non-empty, so every burned cell is a source forever. The active set grows monotonically with the fire. 2.08× over 260 generations, degrading.
Proposed — stable = {Unburned, Burned}
Only Burning is a source. The active set tracks the front and stays at 1–5% for the whole run. 25.19× — 12× better than the best shipped option.

Measured work, 260 generations, 200×200 (shipped model, shipped landscape)

The generalisation is one Set<number> instead of one number inside activeSet.ts. The compiled step never knew what “empty” meant — it only ever receives _activeList and _activeCount. So no JS, WASM or WGSL emitter is touched, and byte-identity for every shipped model holds by construction.

2 · The predicate ladder — and its floor

Two readings that matter. (a) On Life the “stable” generalisation is worth ~1.7–2.0× — real, but not an order of magnitude, because what it unlocks is skipping still lifes (58.2% of the live population of a settled soup). The wildfire case above is where a value set is qualitative. (b) The dilation itself costs ~4× against a perfect oracle; that gap is irreducible for any conservative range predicate.

A fresh random soup is 99.1% active at generation 1. Sparse stepping is an asymptotic win as a pattern settles — never an opening-frame one, and never a win at all for a dense chaotic model with a huge neighbourhood (the documented MNCA case, where it is measurably worse).

3 · What HashLife actually is

(a) Hash-consing — repetition is free in space

Every node is canonicalised through a hash table, so identical subsquares anywhere in the universe are one object. This is where “don't allocate the void” comes from: the empty quadrant of any size is a single shared node.

(b) Memoised result — repetition is free in time

Gosper 1984. The exponential time jump is the headline — and it is also why the transport, the indicators, recording, end conditions and Stop Events all lose their meaning under it.

Measured: 8×8 tile dedup — the whole trade in one table

Exactly the published behaviour: pathological for chaotic input, spectacular for sparse structured patterns. A GenesisCA model with a float attribute has effectively zero dedup by construction — a float leaf key never repeats.

4 · O(active) memory — chunked storage

TODAY — dense
Each attribute is one dense total-length typed array at a baked offset in wasmMemory. idx is a flat index — used by the compiled loop, the NI codec, the brush, the clipboard, the inspector, the colour buffer and both renderers.
TIER B — chunk map + halo
Measured at 1024² after 2000 generations: 1.0× for a soup, 5.6× for an R-pentomino, 16.0× for a glider. The halo is expensive at 64² granularity — 10 occupied chunks become 46 allocated.

The win is a function of the grid-to-structure ratio, not of the technique. At realistic grid sizes it is 1×–16×. Its genuine value is only the limit case the brainstorm names — unbounded — where dense storage is not wasteful but impossible. That needs a third boundaryTreatment and touches the SoA layout, both CPU layouts, the WebGPU buffers, the flat cell index, save/load, the brush, the clipboard and every renderer. Milestone-sized.

⚠ The finding with the best effort-to-value ratio in the whole document

Exactly one shipped model carries a skipIsolatedEmpty config — the Accretor — and it is enabled: false, while its own Rule Description tells the user the 27M-cell volume “is practical because Skip Isolated Empty Cells is ON”. The same mismatch was flagged in PERF_REVIEW_LATTICE.md §6 on 2026-07-24 and is still there. The feature has zero users in the library, which is the practical reason it reads as unimplemented. Fixing one boolean (or one sentence) beats every tier above on effort.

6 · Why memoisation and GenesisCA's step disagree

GenesisCA's step is a compiled user graph, not a fixed rule. Anything that memoises “this neighbourhood ⇒ this result” bets on the step being a pure function of the cells in its read-neighbourhood. Where that bet loses:

featureactive set (A / B / D)HashLife (C)
getRandom, pickRandomNeighbor, aggregate.random…✅ fine⛔ fatal — not a function of the neighbourhood; the xorshift stream is global mutable state
setIndicator / updateIndicator / getIndicator✅ fine⛔ fatal — order-dependent shared accumulator, and a 2^k jump never visits the generations that write it
getModelAttribute, lookup tables✅ fine⚠ live sliders are the interaction idiom — every move invalidates the memo table
Stop Events / End Conditions✅ fine⛔ cannot fire mid-jump
Get Generation (cadence)⚠ breaks a dirty predicate⛔ time-varying rule
async mode · agents / field bridge · glyphs⛔ already excluded by the gate⛔ fatal
float attributes✅ fine⛔ dedup ≈ 0 — a float leaf key never repeats
neighbourhood radius > 1 (MNCA, Coagulation, Accretor)✅ fine⛔ the classic node algebra is r = 1
torus / constant boundary✅ fine⛔ HashLife assumes an infinite uniform background — neither shipped boundary is one
WebGPU⚠ Tier D closes it⛔ memoised recursion over a hash-consed pointer graph has no GPU form

Applying that gate to the shipped library — MEASURED, all 31 models compiled and their emitted steps tested: 3 of 31 pass, and all three are the same rule — Game Of Life, General 2D CA (Golly style) and GoL Replicate Statistics. 12 are agents-only (no grid at all); the other 16 are rejected.

The 16 rejections by blocker (a model can carry several): live model attributes 13 — the commonest, and the least surprising, since a live slider is exactly what GenesisCA is for — RNG 7, radius > 1: 4, async 4, 3D 2, indicators 2, float attributes 2, agents 2. Even Extended Wireworld, the “one other plausible candidate”, is stopped before its 4 states matter — by a model attribute and an indicator.

7 · The adjacent finding — Golly's other idea

Golly's Larger than Life algorithm makes big-radius totalistic rules O(1) per cell with cumulative / summed-area sums. GenesisCA's MNCA-class models are exactly that shape and are its worst measured lattice case — 229 ms/gen and a 693 MB neighbour table at 512² — and Skip Isolated Empty Cells is documented as measurably worse for them.

A compile-time recognition of “this is a sum or count of one attribute over a contiguous box or disc” → a prefix-sum pass would collapse that on all three targets (a prefix sum is trivially GPU-friendly, unlike everything else in this document). This is a much better fit for GenesisCA's actual model population than HashLife, and it deserves its own investigation.
