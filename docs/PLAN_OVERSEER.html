The Overseer — a third graph for experiment orchestration

The Cells graph and the Agents graph define what happens inside a simulation. The Overseer defines what happens around and across simulations: it is the experiment protocol — reset & prepare the board, set parameters, run, measure via indicators, collect samples, aggregate statistics, capture media, loop. The Cells/Agents graphs are the physics; the Overseer is the scientist. Full written plan: docs/PLAN_OVERSEER.md.

1 · Why — motivating scenarios

Statistical replication
Stochastic models (Chromatography, Amphiphile) are only meaningful in aggregate: repeat 30× with different seeds, report elution generation = mean ± std. Today: 30 manual runs + a spreadsheet.
Parameter sweeps
"How does gravity affect separation?" — for each value in {1, 2, 5, 10} run K replicates, chart the response curve. Compound/factorial sweeps (weather-model style) follow naturally.
Protocol automation
Mid-run interventions: prepare the column, run 500 gens, inject the solute band (a board write at gen 500), run until the detector Stop Event fires. InitEvent covers gen 0 only — this covers any time.
Evolutionary algorithms
A parameter vector is a genome: evaluate fitness from indicators, select, mutate/crossover, repeat. Loops + parameter writes + measurements are exactly the required primitives.
Unattended capture
"Record a WebM of run 3", "screenshot every 100 generations" — part of the protocol, not a human on the transport bar.

2 · The three-tier execution model

The key structural insight: the Overseer is not a compile target — it is the driver that CALLS the simulation, sitting exactly where the transport-bar play pipeline sits today (post a step batch → await stepped → decide). The CA keeps running on whichever target the model selects; the ALL-TARGET rule is satisfied by construction because there is no per-cell work in the Overseer to port.

Fig. 1 — The Overseer is an outer loop on the main thread, driving the untouched sim worker through the existing message protocol and feeding a results store.

3 · Core architecture decisions (D-OV-1 … D-OV-9)

D-OV-1 — Main-thread runtime, existing worker protocol. Every action maps to a message that already exists (reset, step{count}, updateModelAttrs, setRngSeed, importImage (has region), getState/loadState, stopEvent). Capture stays on the main thread where it already lives. Rejected: in-worker overseer — duplicates capture plumbing, couples the experiment to one grid, kills parallel replicates.
D-OV-2 — Compile to an async JS driver; reuse per-node JS compile() for pure value nodes. New small flow emitter (awaits actions, injects abort checks); value semantics stay in lockstep with the Cells/Agents compilers with zero duplication. Rejected: interpreter (semantic-drift risk across ~30 shared value nodes); it remains the documented fallback. Debug highlighting via optional O.trace(nodeId) emission.
D-OV-3 — Third ActiveGraphKind. 'cells' | 'agents' | 'overseer'; the entire Agents-graph swap machinery is reused (SET_OVERSEER_GRAPH, pill strip, clipboard tag, palette gating, singleton root).
D-OV-4 — Measurements flow through INDICATORS. The Overseer reads the existing, 3-target-verified measurement layer; it never scans the grid. Raw-state escape hatch deferred (v3+, if ever).
D-OV-5 — First-class seeding. Promote setRngSeed (exists today, DEV-only by convention) to supported; add a Set Random Seed node + per-run auto-seed policy (fixed / sequential / random). Within-target reproducibility is the guarantee (JS/WASM bit-reproducible; WebGPU statistically equivalent — existing documented stance).
D-OV-6 — Results are runtime artifacts. Series (Welford stats, CI) + Journal (text/images/tables/video), exported as CSV/JSON — never embedded in .gcaproj.
D-OV-7 — Parameter writes are runtime-only. Set Model Attribute behaves like the right-panel sliders (worker + panel UI), never dirties the model definition.
D-OV-8 — Parallelism is phased. v1 sequential on the visible worker (watchable, capture works); PR4 adds a headless worker pool for replicates, with the visible worker as "watch run #k".
D-OV-9 — EA: primitives first. Ship an EA sample + macro built from loops, variables, RNG, parameter writes and indicator fitness; dedicated EA nodes only if the sample proves primitives too clumsy (the SampleArrayByWeight lesson).

4 · A worked example — the Chromatography batch

Thirty replicates of the shipped Chromatography model, each run-until-detector (its Stop Event already exists), collecting the elution generation; then aggregate and log. This directly reproduces the paper's "average of 30 runs" methodology.

Fig. 2 — The Chromatography batch as an Overseer graph. Only the amber-bordered node and the white root are new node types in this picture; the rest reuses the existing catalogue.

What the compiler emits (D-OV-2)

// Experiment → Loop(30) → [SetSeed, Reset, RunUntilStop, CollectSample] ; DONE → stats + log
(async function experiment(O) {
  const _modelAttrs = O.modelAttrs;              // live view for reused getModelAttribute emits
  for (let _l1 = 0; _l1 < 30; _l1++) {
    await O.setSeed(1000 + _l1);
    await O.reset();
    const _v9 = await O.runUntilStop(5000);   // { atGeneration, stoppedBy, stopIndex }
    O.sample('elutionGen', _v9.atGeneration);
    if (O.aborted) return;                       // injected after every await + loop back-edges
  }
  O.log(`elution: ${O.stat('elutionGen','mean').toFixed(1)} ± ${O.stat('elutionGen','std').toFixed(1)} (n=${O.stat('elutionGen','count')})`);
})

Runtime rules that matter

  • Tab-hidden: experiments CONTINUE while the tab is hidden (the auto-pause only gates the play loop; the Overseer drives steps itself). Draw work stays skipped; capture nodes force a frame.
  • Mutual exclusion: transport controls disabled while an experiment runs; any worker reinit or recompile aborts the experiment cleanly.
  • Indicator freshness: reads are valid only after a run/reset ack (the graph wiring orders this naturally; the runtime awaits the post-reset stepped).
  • Snapshot budget: slots hold getState payloads; aggregate cap (~256 MB) with a journal warning instead of an OOM.
  • Seeding order: setRngSeed is always posted BEFORE reset so InitEvent randomization is governed by the run's seed.
  • Driver RNG: Overseer-graph Get Random uses a separate seedable stream owned by the runtime — experiment randomness never perturbs the simulation's stream.

9 · Risks & gotchas (top of the list)

SimulatorView sprawl. The runtime is its own module (overseerRuntime.ts); the panel its own component. Do not add another 1000 lines to SimulatorView.
Binary graph-kind assumptions. Sweep every ActiveGraphKind consumer for two-way branches before adding the third value (GraphEditor, palette, Attributes panel, NodeExplorer, modelerUiState, clipboard).
Cleanup cascades. Every patchAllNodes/clearDeletedId site must scan overseerGraphNodes — deleting an indicator/preset/model-attr must clear overseer node configs (the Agents graph shipped this bug class once already).
Message correlation. Add the reqId echo FIRST, not after the first heisenbug — a residual play-pipeline stepped must never be mistaken for an overseer batch ack.
  • Abort latency bounded by batch size; WebGPU until-stop overshoot within webgpuStopCheckInterval — report the actual stop generation.
  • Capture: reuse the extracted paths verbatim; never getImageData a live canvas (documented 6× de-opt).
  • Snapshot memory budget on 5000² grids; journal-warn instead of OOM.
  • Seed BEFORE reset so InitEvent randomization is governed by the run's seed.
  • Allowlist correctness is the safety boundary; hand-edited files get validation badges.
  • Macros with non-allowlisted internals are un-placeable on the Overseer graph (existing macro-scan path).
  • Docs consistency (CLAUDE.md / HelpView / README / NODES_REFERENCE) is part of every PR's definition of done.
