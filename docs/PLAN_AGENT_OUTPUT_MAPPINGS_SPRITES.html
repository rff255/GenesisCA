Playback is LOGIC-driven — the Set Agent Sprite node

No simulator transport. The agent's logic controls the sprite + playback through one node with independently-tickable facets:
Set Agent Spritedo → next
bird ▾
Frame input — jump to / reset (e.g. 0 on a state change).
Speed input — frames per step. Negative = reverse. 0 = hold.
Tick only the facets you want to change (swap the sprite but keep the frame/speed; or only change speed; or reset to frame 0). The engine advances frame += speed each simulation step — e.g. "while moving, set speed = 1; while idle, set speed = 0". Use it in an Agent Output Mapping graph (reads the agent's state) or directly in the Behaviour graph.

Data / control flow

  1. Behaviour + division run (JS/WASM/WebGPU).
  2. Agent OM pass (JS, worker) for the active agent viewer fills colors + (if model has sprites) spriteIds/spriteFrames.
  3. Snapshot ships those buffers (length-0 when no sprites → non-sprite models unchanged).
  4. Main thread resolves frame from playback state + decoded ImageBitmap[] and blits in drawAgentsOverlay.
