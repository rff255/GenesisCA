Hover highlight — a node, its wires, its neighbours

Editor layer only: one pure module (src/modeler/vpl/hoverHighlight.ts), a CSS block, and wiring on three <ReactFlow> mouse props the Rule Trace left unused. No compiler, no schema, no worker message — every emitted surface must come out byte-identical. Written plan: PLAN_HOVER_HIGHLIGHT.md. Status: proposed; the mechanism was prototyped live (section 6).

1 · The gesture — three zones on one node

The cursor's horizontal position over the node picks what lights: the left third asks "what feeds this?", the right third asks "what does this feed?", the middle just marks the node. The bands are computed from the node's screen box, so they are the same at every zoom; the boundaries carry hysteresis so a cursor resting on one cannot flap.

2 · Before / after — the three states on a real shape (Game of Life)

before · today

Nothing on the canvas reacts to the mouse except a reroute dot brightening. To learn what feeds the If node you read the wires by eye — and behind a dense region, or through a reroute chain, you follow them with the cursor.

after · LEFT third

The If node rings in its own hue (lightened); both wires INTO it re-stroke in that hue with a halo; Generation Step and Get Cell Attribute get a fainter ring — these feed what I'm pointing at.

after · MIDDLE

Only the node marks. This is the "just looking" zone, kept exactly as specified (alternative A2 — both sides faint — is listed in section 7).

after · RIGHT third

The THEN and ELSE wires and both Set Attribute consumers light; the incoming side stays as it was — this is what I'm pointing at affects.

One hue per gesture. Everything lit by one hover uses the hovered node's own hue, lightened — the peers fainter than the origin, so the source of the gesture stays obvious. The flow/value distinction is not lost: the port glyphs (triangle vs circle) still carry it. Alternative A1 (wires keep their own green/cyan, only brighter) is in section 7 and is the first decision for the user.

3 · Colour — why the raw hue cannot be the glow

The header fill is def.color, a hex literal per node definition. The --color-node-* tokens in tokens.css exist but nothing reads them. Those fills are deliberately dark and muted (the Blender compositor palette) — as a 2 px ring on the node's own border, which is already that colour, they read as no change. The prototype's first pass proved it: the raw #1b5e20 ring on the If node was invisible at 1×. The glow is therefore a lightened derivative, computed in TypeScript (hoverGlowColor(hex)) and written as one custom property --hover-c on each marked element.

4 · Reroutes, and the two refinements worth shipping with it

reroute chains are transparent

A reroute is an editor-only relay. Hovering B's left third walks the chain back to the real producer: every segment lights, every dot rings, and A is the peer. Hovering a dot itself lights both sides (no thirds on 16 px).

I2 · hovering a WIRE

The wire and both of its real endpoints light (through any chain), in the producer's hue. The 15 px interaction path already exists (interactionWidth: 15). This is the biggest win for long wires — the question there is always where does this go?

I1 · hovering a PORT narrows the set

The thirds are the coarse default; a handle is the precise one. Over the CHECK socket only its wire and its producer light — the answer to "which of these five inputs is that wire?". A CaNode <Handle onMouseEnter> publishes {nodeId, handleId} on a graphState channel; the editor treats it as a zone override. An unwired port lights the node alone.

5 · Timing — the interaction sequence

The node's own mark is immediate (a 120 ms shadow transition). The neighbourhood waits a short dwell so that crossing a dense graph on the way somewhere does not strobe every wire the cursor passes. Once lit, switching thirds is instant. Any gesture that owns the canvas stands the whole thing down.

6 · How it works — no React state, and what the prototype proved

control / data flow
layering — why the ring goes on the INNER element
Prototyped live (Game of Life, dev server, page console). A throwaway <style> plus data-hover / --hover-c written on the If node, its wires and its peers reproduced the left and right states above pixel-for-pixel in spirit; applying a degree-2 set cost 0.3 ms. Then addSelectedNodes([if]) forced a React Flow re-render of the wrapper (it gained z-index: 1000 and the selected class) and both the attribute and the custom property survived on the node and on the edge — the one claim the whole design rests on. The dark raw hue was invisible on the first pass; the lightened hue was not. Everything was removed afterwards; 0 console errors.

7 · Alternatives, improvements, and what is deliberately not proposed

I3 · Alt + hover = the transitive cone (v2)

With Alt held the left / right third extends to the full upstream / downstream closure (Blender Select Linked, Houdini upstream). Bounded BFS, cap 200 nodes, dots included. Valuable for "what does this eventually affect" — but a modifier-hover is a discoverability problem, so it ships after the basic gesture has been lived with.

I4 · dim everything else — NOT the default

Unreal-style focus dimming would make a dense graph very legible, but the trace doctrine is adds light, never greys the graph, and a transient dim on every mouse pass flickers the whole canvas. If wanted at all, it is the look of the Alt variant, decided after I3.
