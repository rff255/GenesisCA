Unified agent spawning — Create / Add work in both graphs

Retire the request-based Spawn Agent / Spawn Event. Instead, Create Agent + Add Agent To World work in the Behaviour Step exactly as in the Init Event — one idiom, handle-based full control, like Set Attribute works in both events.

1 · The problem: a redundant dichotomy

Before — two different ways

Init Create Agent → set-by-handle → Add To World  full control
Run Spawn Agent (request) + Spawn Event (configure elsewhere)  indirect, no handle

"A bird lays an egg" had to request the egg and fill it in a separate root. Cryptic + redundant.

After — one idiom, everywhere

Init Create Agent → set-by-handle → Add To World
Run Create Agent → set-by-handle → Add To World

Same as Set Attribute — works in Init and the Generation/Behaviour step. Full, direct control over the new instance.

The egg is fully formed + configured this step, but starts running its own behaviour next step (a newborn isn't born already running — it's allocated beyond the current loop bound). Overflow past Max Agents → handle -1 → the Set/Add no-op.

3 · Feasible on all three targets (the parallelism question, honestly)

TargetBehaviour loopCreate Agent mid-step
JSsequentialthe same host closures Init already uses, threaded into the behaviour loop ABI — trivial
WASMsequentialenv.agentCreate / env.agentAddToWorld host imports (write the new slot in the shared memory) — moderate
WebGPUparallelan atomic bump allocator atomicAdd(&spawnCursor, 1u) reserves a unique slot; the CPU reconciles after readback — the real work

Grow-only allocation on every target (append at highWater), so a newborn is beyond the loop bound and never double-processed. Consistent across targets. (v1 caveat: a kill+create churner with no Division grows the pool until Reset — documented; a later born-flag removes it.)

4 · What changes

+ Create Agent + Add To World compile under the Behaviour root (loop-ABI closures); Set-by-handle guard relaxed in behaviour like Init.
− Spawn Agent + Spawn Event nodes retired (already reverted; nothing shipped used them). No new node types — the catalogue count is unchanged.
◉ Population · Birth capability now gates whether Create/Add appear in the Behaviour graph (they're always available in Init — the core init-spawn path).
