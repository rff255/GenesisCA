## §0 — Mission, scope, and how to verify in this repo

### 0.1 Mission

Two unifying workstreams, executed as one ordered runbook:

- **(A) 3D agents.** Lift the Bond-Graph Agents subsystem — today **2D-only** ([CLAUDE.md "Bond-Graph Agents — Floating Cells"](../CLAUDE.md)) — into the `W×H×D` world the grid milestone already shipped: the AgentStore z-axis (`z`/`zNext`/`vz`/`forceZ`), the 3D spatial hash (3×3×3 stencil), 3D soft-sphere/bond-spring/integration math + 3-axis torus wrap, the **3-axis tension-axis eigensolve** (2×2 → 3×3 symmetric — the genuinely-new math), the bilinear→**trilinear** field bridge, and a **3D agent renderer** (instanced spheres + bond tubes) built ON the `gl3d.ts` camera/clip/pick/gizmo framework.
- **(B) Phase F.** Port the agent LOOP off hard-JS onto the fast targets: `compileAgentGraphWasm` (PR6) then `compileAgentGraphWebGPU` (PR7), wired through `agentTargetOf`. These ports 3-ify in lockstep with (A) — they target the **already-3-ified JS agent loop** as their mirror reference.

**The headline honesty (carried from the grid milestone, applied to agents):** *3D-is-incremental is true of the engine, not the renderer or the eigensolve.* The engine 3-ification is overwhelmingly additive — a z arm on every existing x/y arm, `total = W*H*D` already established by the grid, `worldDepth = gridDepth` (the agent world IS the grid frame 1:1). The two **genuinely-new** pieces are (1) the **2×2→3×3 symmetric eigensolve** for tension-axis division (a closed-form Cardano solve with stability clamps), and (2) the **wholesale-new instanced-sphere renderer** — `gl3d.ts`'s instance path decodes `x/y/z` from a flat **cell index** (`uW`/`uWH`); agents have **continuous** positions + per-agent radius and need a separate instanced pipeline (sphere impostors + bond lines), NOT the cube path. Treat "3D agents is a flag flip" as the half-truth it is.

2. **3D agent RENDERER** — instanced sphere impostors + bond lines in the reused `gl3d.ts` framework; the 3D agent brush (seed/kill/move/glue on a plane or in a volume) + the 3D agent inspector.

## §1 — Design recap (the verified facts you build ON — do not relitigate)

**The agent world IS the grid coordinate frame 1:1.** 3D agents inherit `gridDepth`/`dimension`/`boundaryTreatment` (torus) from the grid with **no new world schema** — `worldDepth = gridDepth` (B2). So the engine 3-ification is incremental (a z arm on every x/y arm); the eigensolve (B6) and the renderer (B5) are the only wholesale-new pieces — the exact 2D/renderer split the grid milestone called out.

**The current 2D-agent infrastructure you build on** (verified against source):
- **AgentStore** ([agentEngine.ts](../src/simulator/engine/agentEngine.ts)): a parallel typed-array SoA length `maxAgents` — Float64 `x/y/xNext/yNext/vx/vy/forceX/forceY/radius/targetRadius/age`; Int32 `type/lineage/bondCount/epoch`; Uint8 `alive`; the ragged bond store (stride `maxBonds`); the divide/kill/bond request buffers; per-agent RGBA `colors`; per-user-attr `attrRead`/`attrWrite` (single-buffer). `highWater` (loop bound) + `liveCount` + the free-list. `worldWidth`/`worldHeight` (overwritten by the grid dims in `initAgents`). **No `z`/`zNext`/`vz`/`forceZ`/`worldDepth` exist yet — clean slate** (engine dossier confirmed).
- **`runAgentStep`** ([sim.worker.ts:595](../src/simulator/engine/sim.worker.ts)): reset `forceX/Y` → build the spatial hash → run the compiled behaviour fn (queries the hash via Get Nearby Agents, adds to `forceX/Y` via Apply Force) → ONE fused neighbour pass (soft-sphere + bond springs + density) → velocity integration `v = momentum·v + (Δt/η)·F; x += v` into the xNext/yNext double-buffer → swap → growth ramp → the structural phase.
- **`runAgentStructuralPhase`** ([sim.worker.ts:766](../src/simulator/engine/sim.worker.ts)): the only place topology mutates — explicit FormBond/BreakBond → death (`freeAgentSlot`) → division (`divideAgent`) → division-event per daughter → opt-in auto-bond by distance → stale-bond sweep. **Serial graph + ragged-bond mutation — stays CPU/JS forever** (PR6 + PR7 both keep it CPU; this is correct, the GPU-particle-system-with-CPU-emission architecture).
- **`divideAgent`/`tensionAxis`/`principalEig2x2`** ([agentEngine.ts:461-590](../src/simulator/engine/agentEngine.ts)): the axis is the principal eigenvector of `M = Σ_k max(0, λ_k(l_k−L_k))·(r̂_k⊗r̂_k)` over the agent's bonds (closed-form 2×2 symmetric eigensolve); daughters at `centroid ± ½·r·m̂`, partner bonds partitioned by `sign(dot(offset, m̂))`. **This is the B6 site.**
- **`buildSpatialHash`** ([agentEngine.ts:617](../src/simulator/engine/agentEngine.ts)): CSR-style 2D bins + a 3×3 stencil, O(N), reused scratch; null for a tiny world → all-pairs fallback. Bin edge = `max(soft-sphere cutoff, neighbourQueryRadius)`.
- **The field bridge** (Decision D-FIELD): every cell attribute doubles as a diffusible morphogen field. The generation loop runs the **agent step BEFORE the cell step**: agents `SampleField` (GATHER, bilinear), behave, `AffectCellsUnder`/`SecreteToField` write the cell READ buffer (DEPOSIT, sequential many→one resolution), THEN the cell CA steps. The agent field arrays (`_field_<id>` = the cell read buffer, sized `total`) ride the agent-loop signature.
- **The compiler** ([compile.ts:2087](../src/modeler/vpl/compiler/compile.ts)): `compileAgentGraph` emits `{behaviourCode, divisionCode, initCode}` — a sibling of `compileGraph` that flattens macros / strips reroutes / runs CSE, finds the `behaviourStep` root, emits the per-agent loop via the shared `compileRoot`. The four ABI builders (`buildAgentLoopParams`/`buildDivisionParams` ↔ `buildAgentLoopArgs`/`buildDivisionArgs`) are the B1 mirror.
- **The agent node set** (all `requirements: { bondGraph: true }`): event roots (`behaviourStep`/`divisionEvent`), self reads (`getSelfPosition`/`getRadius`/`getBondDegree`/`neighbourDensity`/`getVelocity`/`getCurvature`/`sampleField`/`fieldGradient`/`readCellsUnder`), neighbour access (`getNearbyAgents`/`getAgentPosition`/`getAgentAttribute`/`getAgentRadius`/`getAgentOffset` — the Phase-2 PR1 primitive), flow (`setTargetRadius`/`applyForce`/`setAgentAttribute`/`formBond`/`breakBond`/`forEachBond`/`divideAgent`/`killAgent`/`affectCellsUnder`/`secreteToField`). Several already carry a **hidden z port** as a Phase-E placeholder: `getSelfPosition` (`hiddenPorts: () => ['z']`), `behaviourStep` (`['myZ']`) — un-hide them in 3D (B-PORTS, PR3).
- **The renderer framework** ([gl3d.ts](../src/simulator/render/gl3d.ts)): Z-up orbit camera (`Camera3D`/`setCamera`/`cameraBasis`/`panCamera`), clip/slice plane, scene overlays + clickable gizmo (`gizmoHitTest`), the line program (`LINE_VS`/`drawLines`), the pick FBO (`ensurePickFbo`/`pick`), `readPixels`, `pickOnPlane` (unproject a cursor ray to a slice), the hover/inspect cube cursors. **The world Z-up remap (the non-negotiable invariant):** `col→+X (right)`, `row→-Y (down)` (`world_y = uHalf.y - row`), `layer→-Z (into screen, layer 0 on top)` (`world_z = uHalf.z - layer`). Agents at continuous `(ax,ay,az)` map to `vec3(ax-uHalf.x, uHalf.y-ay, uHalf.z-az)` — so a sphere at `(c,r,l)` sits inside the voxel cube at cell `(layer=l,row=r,col=c)`.
- **Scale (the honest perf baseline):** the spatial hash keeps the JS engine O(N) — **2000 boids run at 174 steps/sec** (5.7 ms/step), interactive. So the agent loop is NOT a JS bottleneck for realistic counts; **PR6 (WASM) raises the ceiling past ~10k, it doesn't fix a bottleneck**, and PR7 (WebGPU) is a scale play that only wins past ~10k agents.

## §3 — Cross-cutting gotchas (the 3-target × 2-dim × 2-substrate matrix)

1. **The 2D fast path stays byte/behaviour-identical at EVERY PR (the regression guarantee, proven BY CONSTRUCTION — B-CONSTRUCT).** The discipline that makes "flawless" tractable. **Lattice byte-identity:** `compileAll(GoL/Gray-Scott/Life3D/snake)` on all 3 targets, string/byte-equal before/after each PR (the agent work never touches the lattice compilers — prove it). **2D-agent identity:** `compileAll(Boids/Tissue/Chemotaxis).js.agent.behaviourCode`/`.divisionCode` string-equal before/after each engine/compiler PR — this follows BY CONSTRUCTION from "the z-params push only when 3D → the 2D code path is literally unchanged" (the Phase-2 C-D3 discipline), AND from the always-zero-z invariant (PR1 — the 2D engine's numeric output is bit-identical despite the four extra always-zero arrays). 2. **The FOUR ABI mirrors + the FIFTH snapshot path (B1/B8/GAP-1).** `buildAgentLoopParams↔buildAgentLoopArgs`, `buildDivisionParams↔buildDivisionArgs`, and (the easy-to-miss one) the per-`stepped` render snapshot.
