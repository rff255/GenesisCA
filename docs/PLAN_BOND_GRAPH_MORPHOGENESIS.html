The build at a glance: bond-graph morphogenesis is an additive extension of the authoring model — the user composes rules exactly as they build a Game-of-Life rule today (read nodes → Compare/AND/math → flow nodes), hung off new event roots (a per-agent Behaviour step, a Division event, a Bond-Contact event, a Field step). The user owns every predicate and all attribute math; the engine owns all the irreversible geometry (the division axis, bond reattachment, force integration, diffusion). It is not free on the compiler/engine side, though — the agent loop on WASM/WebGPU, the structural engine phase, and the agent+bond serializer are genuinely new (§8).
The freedom you asked about: to make division depend on attributes you defined, you wire GetCellAttribute(yourAttr) → Compare → Conditional → DivideCell — and you choose the axis source (tension / random / field-gradient) and the daughter inheritance, but not the physically-impossible per-bond partition (that follows from the geometry of the cut). Environment couples in the same graph: a SampleField/FieldGradient read sits next to your attribute reads, so "divide only where nutrient is high, toward the gradient" is one wired predicate. The two demos below show this live in 2D and 3D.

01 How the user authors rules — the event roots

No new authoring concept is introduced. Today you hang rules off singleton "event" roots (Step, InitEvent, OutputMapping). Bond-graph morphogenesis adds four more, each a place to attach ordinary node-graph rules over your own attributes plus a handful of new sense nodes.

02 Influencing division with your own attributes

Your literal request: "divide when age > T and size > X, orient by tension, give daughter A more of attribute Q." Here it is as a wired graph — every connective node (GetCellAttribute, Compare, AND, Conditional) ships today; only DivideCell + the Division root are new.

03 Live demo — rules + environment drive morphogenesis

A 2D bond-graph model with a diffusing nutrient field (blue heatmap) cells consume. Division is gated by local nutrient and oriented by the chosen mode — so with the field on, the colony climbs toward the source and spreads into a front; with it off, growth is isotropic. This is the rule-authoring + environment coupling, live.

04 How the external environment couples in

Three environment channels feed the same rule graph as ordinary value reads — there is no special "environment phase." A cell's rule can read its own attributes, its bonds' state, and the field/global env all in one predicate.

05 Simulator interaction — brushing cells & bonds

Picking switches from floor-division (row*w+col) to nearest-agent hit-test behind a Picker seam — the one main-thread change. Then cells and bonds each get their own brush modes; the index-keyed paint/inspect message protocol is reused.

06 Live demo — the 3D cell + bond viewer (drag to orbit)

Drag to rotate, scroll to zoom. A 3D soft-cell aggregate that glues into a connected tissue and divides along its 3D tension axis — shaded, depth-sorted instanced spheres + depth-sorted bonds. "Slice" clips the front half so you can see inside the tissue. This is the navigation model the production WebGL renderer would deliver at scale.

07 3D visualization architecture & navigation

3D is honestly a wholesale new renderer — but it sits behind the same draw() / source-canvas seam the WebGPU OffscreenCanvas direct-render path already proves, and the per-agent colors buffer + index-keyed inspector are reused as-is.

08 What's genuinely new vs reused (honesty ledger)

The reusable part is the node-graph vocabulary + the index-keyed interaction protocol. The loop shape on WASM/WebGPU, the structural engine phase, and the serializer are new — costed honestly here so the roadmap is realistic.

The biggest risk, named

Do not cost the milestones against "verbatim template reuse." The single largest body of work — a non-lattice, free-list, continuous-position, ragged-bond agent loop on three targets + the structural engine phase + the serializer — is new. v1 ships JS-only to bound that (D-TARGET); WASM/WebGPU are explicit later milestones.
