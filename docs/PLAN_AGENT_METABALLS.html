Agent Metaballs — implicit-surface rendering for 3D agents

Illustrated companion to docs/PLAN_AGENT_METABALLS.md. Status: proposed. Render the agent population as a Blender-style metaball isosurface so nearby agents fuse into organic tissue instead of reading as a bag of marbles.

The “after” panel is itself a real 2D metaball (an SVG blur + alpha-threshold filter) — the same blur → isovalue idea the 3D implementation does properly with a scalar field.

2 · The one knob that matters: Influence

Influence scales each agent’s falloff radius as a multiple of its own radius (R = influence · r). Turn it up and neighbours’ fields overlap further, so the surface bridges the gaps — exactly Blender’s behaviour.

3 · Why they fuse — the scalar field

Each agent contributes a smooth falloff w(d) = (1 − (d/R)²)³ that is 1 at its centre and 0 at its influence edge. The fields sum. The surface is wherever the sum crosses the Threshold. Between two neighbours the two falloffs add up and stay above the threshold — so the surface never closes, and a neck forms.

Solid green = the summed field. Dashed = each agent alone. Amber dashed = the threshold isovalue.

Good default: pick T = (1 − 1/influence²)³ so an isolated agent’s metaball renders at exactly its own sphere radius — switching Metaballs on never resizes lone agents, and all the visual change comes from genuine fusion. (Influence 1.6 → T ≈ 0.226.)

4 · How it’s rendered — bake a field, then raymarch it

Blender polygonises with marching cubes. We can’t: WebGL2 has no compute or geometry shaders, and re-meshing every simulation step in JS is far too slow. Instead we bake the scalar field into a 3D texture (cheap — each agent only touches a small neighbourhood) and raymarch it in a fragment shader (cost is per-pixel, independent of agent count).

Sliders dim when Metaballs is off — the same convention as the Shadows / Occlusion rows. Resolution is the perf/quality knob (Blender’s Resolution).

Per-element Radius is already there. Blender’s per-element Radius maps onto each agent’s own radius — a real, graph-authorable agent property (Set Target Radius / the Body capability). So a cell that grows fuses more, straight from the rule graph. Only Ball elements are needed.

6 · What it must not break

FeatureHandling
Picking / brushing / inspect Keeps using the existing sphere pick FBO. Agents stay spheres logically — clicking the blob still selects the nearest agent. uploadAgents must keep running.
Cast shadows The shadow pass already draws sphere casters, and the union of spheres closely approximates the blob → keep as-is. The metaball shader just calls shadowFactor() and receives shadows.
Sprite agents Flagged by a negative radius. Excluded from the field; still drawn as billboards on top.
Bonds Drawn first; end up inside the blob and depth-hidden. Show-bonds toggle still governs.
Clip plane Clipped space is treated as density 0 → the blob is cut open (a nice cutaway of the tissue interior).
Occupancy AO · voxels · 2D · compilers · worker · schema Zero impact. This is a gl3d.ts render mode plus a panel.
Top gotchas (all learned the hard way in this renderer):
  • The Z-up remap must match exactly: world = (col − hx, hy − row, hz − layer) — row and layer are negated. Map all 8 AABB corners and take a component-wise min/max.
  • gl_FragDepth must use the identical formula to SPHERE_FS, or the blob z-fights the voxels.
  • precision highp sampler3D; is required in GLSL ES 3.00 — the same “No precision specified” error that failed the first sampler2DShadow build.
  • Texture units 0 (sprite atlas) and 1 (shadow map) are taken → use unit 2, and bind it after setLightUniforms() (which resets activeTexture to unit 0).
  • Changing Influence/Resolution must invalidate the baked field — otherwise the slider does nothing until the next sim step. (Same trap the occupancy AO’s re-upload trigger exists to avoid.)
