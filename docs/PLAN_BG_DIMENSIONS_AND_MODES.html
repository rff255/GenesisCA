Two orthogonal axes, one matrix: Dimension (2D / 3D) × Topology (Grid Cells and/or Bond-Graph Agents, ≥1). Vocabulary is now pinned: Cells = grid slots (a cell's position is its index); Agents = bond-graph nodes (an agent carries a float position, may float free). The environment is a normal CA over Cells; Agents are suspended on top and secrete into / consume from it — a closed stigmergy loop.
The honest sequencing (the critique's headline): 2D-Grid ships today; the two independent next steps are 3D-Grid and 2D-Agents, then combine. But "add the mode UI" splits into M0a (cheap: the Dimension radio + Topology checkboxes + schema + reducers — all the 3D-grid path needs) and M0b (the second Agent rule-graph, whose fork lands on ~20 graphNodes consumers — gate it behind the agent compiler). 3D-grid needs zero two-graph cost.

03 The mode UI + the Modeler split

Properties → Execution gains a Dimension radio and a Topology checkbox pair; the Modeler splits into two sub-tab graphs, each with its own palette. 04 The closed agent↔grid feedback (stigmergy)

Agents secrete into / consume from the grid; the grid CA evolves; agents sense the result and change behaviour — which changes what they secrete next. A closed loop, and agents coordinate through the grid (one agent's deposit steers another).

05 3D neighbourhoods — the live demo (drag to orbit)

The hard question: 3D CA doesn't auto-extend from 2D except totalistic rules — anything using a specific neighbourhood needs a 3D one, and "I can't imagine how it'd be edited." 06 Variegated-in-3D & RGBA transparency

Variegated cells in 3D — defer it

2D's 4 rotations + N/E/S/W faces become the 24 cubic rotations + 6 faces (or quaternions), and per-face interaction editing on a cube is genuinely hard UX. The research found no established standard for full per-face directional 3D cell-cell interaction — tools either ignore it or use continuous polarity vectors. Recommendation: variegation stays 2D-only in v1; 3D grids ship without it; a discrete 6-face / 24-rotation model is the later path.

RGBA — the channel already exists

The colors buffer is already RGBA; alpha is just hard-coded to 255 (colors[idx+3]=255). So the change is small: make alpha authorable (Set Cell Looks + colour mappings gain an alpha input, emit it on all 3 targets) and have the 3D renderer respect it. Default (§1.5 C4): lead with a clip/slice plane (cheap, correct, the industry-first norm) — never raw depth-sort, which sorts wrong exactly at division. Per-cell alpha is opt-in; OIT is the v2 upgrade.

Cross-target catch

The WebGPU present shader already unpacks alpha, but its canvas is alphaMode:'opaque' — it silently ignores alpha until that flips. The compiler-lockstep policy must reject that divergence.
