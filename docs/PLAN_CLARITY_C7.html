Why the GRA card does not use the socialGraph preset

socialGraph — what the name suggests

motion   static     // nothing moves
body     false      // no radius
collision off
bonds    data       // edges, no springs
charge   off        // no unfolding

A graph is created and then renders as a pile: the layout physics the L1 charge work exists for is entirely off. No shipped GRA model uses this.

P7 — the last unseeded draws join the seeded stream

Everything a rule does has been drawn from one seeded xorshift32 stream for a long time. Three engine paths were not — and two of them decide the initial condition and the visit order, i.e. the two things a reproducible run depends on most.

Where the draws land

setRngSeed(S)→ initGrid — cyclic order→ initAgents — scatter→ Init Events→ runStep — async order→ your rule's Get Random

One stream, one order. The JS step reads _rngState[0] at entry and writes it back at exit; the WASM path copies the same cell in immediately before each call and reads it back after — so a draw taken in worker JS before the step is seen by both engines and JS↔WASM parity holds by construction.

The honest behaviour change

Scatter layouts and async visit orders differ once from before. They were never reproducible, so nothing that was pinned becomes unpinned.

// before — a different board every time, seed or not
setRngSeed(7); reset() → board A
setRngSeed(7); reset() → board B ✗

// after
setRngSeed(7); reset() → board A
setRngSeed(7); reset() → board A ✓
setRngSeed(8); reset() → board C ✓

Two things deliberately unchanged

The session seed stays Date.now()-derived. A constant would make every user's first run of every stochastic model identical — a far bigger change than P7 asks for. Determinism is something you ask for.

Reset does not re-seed. The stream advances across Resets — which is already the documented behaviour of the cell Init Event's Get Random. Agent scatter now matches the cell side instead of contradicting it. Pinning is setRngSeed then Reset — the protocol the Overseer already uses.
