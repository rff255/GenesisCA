Flow pass-through port — NEXT on actions, DONE on control nodes

Every flow-input node gains a flow output so executions chain like UE Blueprints. Wiring it is optional — untouched graphs compile byte-identically.

Before / after — sequencing three actions

BEFORE — fan-out from one DO port
Three wires from one port. Order = wiring order — invisible on the canvas, easy to mis-read.
AFTER — chain through NEXT
A → B → C reads left-to-right. Compiles to the exact same code as the fan-out.

DONE on control nodes — runs after the construct

DONE fires whichever branch ran (or none). Loop / For Each / Switch: after all iterations / the matched case(s). Sequence keeps its THEN ports and gets no DONE.

Execution-order rules

  • Targets wired to one port still run in wiring order (unchanged).
  • A node's NEXT chain runs immediately after it, before the parent port's next sibling — depth-first, like UE.
  • No runtime cost: chains emit the same flat code the fan-out produced. Old models compile byte-identically.
