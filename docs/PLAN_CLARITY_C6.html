2 · The update-mode radios learn Principle 1

before
Synchronous All cells read from the previous generation and write to the next simultaneously. Classic CA behavior.
Asynchronous Cells update one at a time using a single buffer…

Nothing at the point of choice says which engines each mode can run on.

after
Synchronous (parallel — runs on all engines) All cells read from the previous generation and write to the next simultaneously. Classic CA behavior.
Asynchronous (sequential — CPU engines only) Cells update one at a time using a single buffer…

The same words the Compatibility readout uses, so the control and the verdict agree. The agent radio gets the matching pair with its own true consequence (below) — verbatim reuse there would be wrong.

radioSynchronousAsynchronous
CA grid updateMode(parallel — runs on all engines)(sequential — CPU engines only)
Agents agentUpdateMode(parallel — runs on all engines)(sequential — a cross-agent write needs a CPU engine)

Why they differ. An async grid is rejected by WebGPU at the model level, full stop. An async agent model does run on the GPU — Morphogenesis – Growing Tissue ships that way; what the parallel GPU cannot honour is a cross-agent OVERWRITE, whose landing order only the sequential CPU engines define.
