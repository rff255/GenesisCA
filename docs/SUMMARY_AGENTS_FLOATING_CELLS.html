GenesisCA · milestone + expansion

Bond-Graph Agents — Floating Cells

The largest net-new subsystem GenesisCA has added: a second, co-resident engine for off-lattice cells that float, sense each other, bond, grow and divide into tissue — the substrate for studying morphogenesis, flocking, bacterial colonies, and multi-species interaction. This summary covers the original Phases A–D and the follow-up expansion (neighbour access, graph-authored forces, the WASM-decoupled field, two compiler fixes, and three new samples) that surpassed three of the original assumptions.

In one sentence: the sim worker now runs a continuous-position agent engine alongside the lattice CA — agents sense each other, are pushed by graph-authored forces, glue into bonds, grow and divide along their tension axis with bonds inherited by geometry, and close the loop with the grid (the cell CA is the morphogen field they secrete into and sense). Authored entirely in the node editor (a new Agents rule graph), it runs at ~7000 steps/sec for hundreds of agents and ships four samples spanning the breadth: growing tissue, specializing tissue, flocking, and chemotactic aggregation. Phases A–D of the runbook are complete; a follow-up expansion added neighbour access + graph forces and surpassed three of the original assumptions (the force law, the JS-only target, and graph-driven bonding). Phases E (3D) and a full WASM agent-loop are deferred by design.

① What shipped

Six commits, one per phase, each tsc -b-clean with the lattice CA path proven byte-identical on Game of Life + Life3D (all 3 targets) so the agent tier is provably additive.

A Agent substrate

The free-list-holed SoA (maxAgents + alive-mask + highWater), the overdamped force integrator with a uniform spatial hash (O(N)) + a Δt stability clamp, the agent compiler (the behaviourStep loop, var = idx), and the two-graph Modeler split (Cells/Agents tabs behind one editor).

B Bonds

The persistent ragged bond store with the partnerEpoch dangling-bond ABI, the spring force, Form/Break Bond + For Each Bond + auto-bond (hysteresis), and the bond render layer + glue/cut brush.

C Division · growth · death

The headline: the tension-axis eigensolve (a glued cluster divides along its mechanical axis), geometric bond reattachment, Divide/Kill Agent + the Division Event root (asymmetric inheritance), and the growth ramp.

D Closed feedback

The cell-CA-as-field bridge: Secrete/Affect Cells (deposit before the cell step), Sample Field / Field Gradient / Read Cells Under (bilinear gather after) — agents secrete morphogens, the grid diffuses them, agents respond.

①½ Expansion — beyond the milestone (this round)

A follow-up pass that turns the engine from "amorphous blob" into a substrate for complex, interacting, specialized agents — and surpasses three of the assumptions below.

Neighbour access

Get Nearby Agents (radius → an agent-id array, via the spatial hash) + Get Agent Position / Attribute / Radius / Velocity + Set Agent Attribute. The agent analogue of Get Neighbors — agents now read and signal each other. Unlocks differential adhesion, contact inhibition, and graph-driven bonding (Form Bond finally has a target source).

Graph-authored forces

Apply Force + a velocity integrator with momentum (flocking inertia), maxSpeed, and customForcesOnly. The rule graph now authors the physics on top of (or instead of) the engine soft-sphere — surpasses assumption 1.

WASM-decoupled field

The cell field may now run on WASM while agents stay JS (the field is shared wasmMemory the agent loop reads directly). Field-heavy morphogenesis gets the fast diffusion path — surpasses assumption 2.

Two compiler fixes

Building boids surfaced two latent bugs in any "accumulate-in-loop, read-after-loop" pattern (all 3 targets): accessor-CSE merging a mutable getVariable, and the volatile-hoist mis-attributing a post-loop read to the loop via its next edge. Both fixed; lattice byte-identical.

Plus Get Curvature (membrane-curvature proxy), a seed pattern (compact/scatter), Local Variables in the agent loop, and three new library samples (below). 96 node types total.

🐦 Boids — Flocking

Separation + alignment + cohesion via Get Nearby Agents + Apply Force. Verified: velocity polarization climbs 0.008 → 0.99 — a disordered swarm self-organizes into one coherent flock.

🧫 Differential Tissue

Asymmetric division (one daughter self-renews, one differentiates) + a maturity clock + contact inhibition. Verified: 5 → 257 cells, 7 maturity stages, a stable stem pool, self-limiting growth — specialization, not a blob.

🦠 Chemotaxis — Aggregation

Slime-mould / Keller-Segel: agents secrete a chemical, the grid CA diffuses it (on WASM), agents climb the gradient. Verified: agents aggregate from spread (178 bins) into clustered streams (99 bins, 2× density).

② Challenges & how I overcame them

The agent compiler can't be a fork of the lattice compiler — they iterate differently.
The lattice loop runs idx<total with a _row/_col decode + a colour index; the agent loop runs idx<highWater with an alive-skip and none of that. I wrote a sibling compileAgentGraph that reuses the shared front-end (macro expand, reroute collapse, CSE) and the per-root compileRoot + analysis passes, then wraps the result in the agent loop. The loop variable is named idx (Decision D-IDX) so every existing attribute-read node lands on the agent SoA with zero node change.
O(N²) all-pairs forces would cap the agent count.
The runbook sanctioned an all-pairs first build, but you asked for no bottlenecks — so I built a CSR-style uniform spatial hash (reused scratch, no per-step GC) and fused the density + force into one neighbour pass. Result: 0.14 ms/step for 350 agents (~7000 steps/sec), with an all-pairs fallback only for a world too small to bin.
A recycled agent slot could silently re-point a bond spring at a stranger.
The dangling-bond ABI: every bond slot carries the partner's epoch stamped at form time; death bumps the slot's epoch and breaks all its bonds (both directions); the force loop + a per-step sweep skip any epoch-mismatched bond. Verified by killing an agent and asserting its partners' lists drop it + the epoch bumps.
Division is the riskiest single operation — overflow during bond reattachment could leave a half-rewired tissue.
The whole division is pre-checked (can a daughter slot be allocated? do both daughters' bond lists fit?) and rejected atomically on any overflow, leaving the mother untouched + surfacing a notice. The tension axis is a closed-form 2×2 eigensolve, verified exact: a horizontally-stretched bond divides along (1,0), a vertical one along (0,1), with partner bonds partitioned to the nearer daughter.
Switching the Cells/Agents tab mid-edit could write one graph's nodes into the other.
The 100 ms debounced write-back reads the editor at fire-time, but the tab swap had already loaded the other graph. Fixed with a synchronous flushSync before every swap (persist the current graph first), and by routing activeGraph through the existing scope-switch effect so clearHistory() fires on swap (no cross-graph undo) for free.
My own test harness lied to me twice.
"0 bonds formed" was actually a test reading getState (which serialises the bond store) instead of the render snapshot (which carries the flat bond pairs). And a stale Web Worker (model loads are soft-recompiles that reuse the worker; HMR doesn't reload workers) ran old code until a page reload. Both cost iterations — the engine was correct the whole time. Lesson re-learned: verify the field you're reading, and reload the page for fresh worker code.
Boids wouldn't align — and it turned out to be two latent compiler bugs, not tuning.
The boids accumulators (sum neighbour positions/velocities in a loop, read them after) silently produced garbage. Two root causes, both in the shared compiler (so they bit any lattice model with the same shape too): (1) accessor-CSE merged the in-loop getVariable(sum) with the post-loop read — but getVariable reads mutable storage (like getIndicator), so it must be CSE-impure; (2) the volatile-hoist walked a flow node's next continuation when deciding what a node "uses", so a value read after a loop was attributed to the loop and emitted before it (reading the accumulator at zero). Fixed both; the lattice baselines stayed byte-identical, proving the fixes are no-ops for non-volatile models, and boids' polarization jumped from 0.05 to 0.99. A genuine win for the whole compiler, found via the agent work.
Chemotaxis aggregated weakly until I reasoned about diffusion length.
Agents secreted and the field built (max ~30 on WASM), but they wouldn't clump. The field was saturating everywhere, so gradients were flat — and an agent sitting on its own secretion peak feels zero gradient. The fix was physical, not parametric: the diffusion length √(D/(1−decay)) must reach across the inter-agent spacing (~5 cells) so an agent senses its neighbours' peaks. Setting D=0.24, decay=0.99 gave a length of ~5 → real Keller-Segel aggregation (occupied bins halved).

③ Assumptions & decisions — three now SURPASSED

These are the judgement calls where the runbook was ambiguous, under-specified, or where I chose a pragmatic v1 path. Read these — they shape what the feature does today and where you may want to steer it.

1 · ✅ SURPASSED — the force law is now graph-authorable.

Originally: the soft-sphere repulsion + bond springs were an engine-owned integrator; the graph authored only per-agent behaviour, not the physics. Now: Apply Force lets the rule graph add any force vector (the engine integrates the sum), and Get Nearby Agents + Get Agent Position/Velocity give the per-neighbour data to compute it — so boids (separation/alignment/cohesion) and chemotaxis are fully graph-authored. The engine soft-sphere is still there by default (and can be switched off with customForcesOnly). Remaining nuance: Apply Force authors the net per-agent force, not a single reusable pairwise force curve — you write the loop over neighbours yourself.

2 · ✅ SURPASSED — the cell field can run on WASM while agents stay JS.

Originally: any agent model forced the whole model (agents + grid) to JS. Now: the agent engine stays JS, but the cell field may use the WASM target — its attributes are wasmMemory views the JS agent loop reads/writes directly (the field bridge shares the buffer with the WASM step), so a field-heavy morphogenesis model gets accelerated diffusion while agents stay JS. Verified end-to-end on the Chemotaxis sample. Remaining: WebGPU is still forced off for agent models (its attrs are GPU-resident, unreadable by the JS agent without a per-step readback), and the agent loop itself is still JS (a full WASM agent-loop port is Phase F).

3 · "Grid required" — there is no lattice-less branch yet.

Agents are additive on top of an always-present grid, and the agent world IS the grid coordinate frame (agent (x,y) are in cell units, 1:1). A pure agents-only model (no grid) was the most novel matrix cell and is deferred (the runbook's sanctioned scope trim). If you uncheck Grid Cells, the grid is still allocated under the hood.

4 · Daughter-daughter bond only when the mother was bonded.

The runbook says "add the daughter-daughter bond" unconditionally. I made it conditional on the mother having bonds: a tissue cell's daughters stay connected (the tissue grows as one sheet), but a free dividing agent (think bacteria) produces two separate daughters that drift apart under repulsion. This serves both model classes with one rule. If you want bacteria-like free division to also bond, enable auto-bond.

5 · Auto-bond is the primary bond-formation path; Form Bond is graph-limited.

The Form Bond node needs a target agent id, which the v1 node set can't easily produce (there's no "nearest agent" read). So in practice bonds form via the engine's auto-bond option (Properties › Bonds — bond by proximity, with hysteresis) or the manual glue brush. Form/Break Bond are wired and useful with For Each Bond's partner output (e.g. break over-strained bonds), but a graph can't conjure a bond partner from thin air. A future "nearest unbonded agent" node would unlock graph-driven bonding.

6 · Agent attributes are single-buffered; positions are double-buffered.

Agents read + write only their own attributes (no neighbour-attribute reads in the agent graph), so I made agent attrs single-buffer — a read-modify-write sees its write immediately (natural imperative semantics). Positions, by contrast, are double-buffered for synchronous force integration. The same cell-attribute id exists as both a per-cell array (the field) and a per-agent array (the agent attribute) — they're distinct storage sharing a name (Decision D-IDX makes this work).

5 · ✅ SURPASSED — Form Bond is now graph-usable.

Originally: Form Bond needed a target agent id the graph couldn't easily produce, so bonding was effectively engine-auto-bond + the glue brush only. Now: Get Nearby Agents supplies neighbour ids, so a graph can bond to compatible neighbours by type/state (Get Nearby Agents → For Each → if compatible → Form Bond). This also makes bondContactEvent unnecessary. Remaining nuance: the form-request buffer is one bond/agent/step, so an agent bonds incrementally over a few steps rather than all neighbours at once.

7 · Closed-feedback timing: a fused single pass with a one-step-stale gather.

The ideal is deposit→step→gather as three strict phases. I run the agent step (which both gathers and deposits) before the cell step: the gather reads the grid as of the previous cell step (correct "after step"), the deposit writes for this gen's cell step (correct "before step"). The subtlety: within one agent loop, agent j's Sample Field can see agent i's deposit from earlier this same generation (a one-gen intra-loop mixing). For diffusion-driven models this doesn't change the emergent dynamics; a strict "snapshot the field before any deposit" is a future refinement. Likewise, Neighbour Density reads the previous step's density (the cost of fusing density into the single force pass).

8 · Field sampling is cell-centered (cell i ≡ coordinate i), bilinear, 2D.

Sample Field treats a cell's centre as its integer index and lerps between neighbours; the 2D renderer draws cell i spanning [i, i+1), so there's a cosmetic half-cell offset between the two conventions (it does not affect dynamics). 3D / trilinear field sampling is Phase E. For Each Bond's current-length is the raw Euclidean distance (no torus wrap) — exact in practice since bonds are short.

9 · Environment: I installed Node myself.

The machine had no Node.js, so I downloaded a portable Node v24 LTS into ~/tools and ran the build/test loop from there (the user PATH doesn't propagate to the harness's shells, so each command prepends it). I also set a local git identity (rff255@gmail.com / "Rodrigo Castiel"). The Bash tool returned no output in this environment, so all shell work went through PowerShell + the preview MCP. Nothing was pushed.

④ What's deferred (by design)

Phase E — 3D agents

Extend the shipped gl3d.ts WebGL2 renderer to instanced sphere-impostors + bond tubes (reusing its orbit / clip / pick). The engine already carries a z; the force law / division / field sampling gain a third axis. Agents are 2D today.

Phase F — WASM / WebGPU agent loop

The cell field already runs on WASM (assumption 2). The remaining piece is porting the variable-highWater, free-list-holed agent loop + structural phase to WASM, then WebGPU. Measured perf says this is a ceiling-raiser, not a bottleneck fix: the spatial hash keeps the JS engine O(N) — 350 agents at ~7000 steps/sec, and 2000 boids (the heaviest per-agent work: a neighbour query + 7 accumulators + force) at 174 steps/sec (5.7 ms/step), comfortably interactive. WASM/SIMD/GPU would push past ~10k agents.

Smaller follow-ups

An agent inspector popover (the pick infra exists; the render snapshot carries geometry/velocity but not per-agent attribute values — needs a getState round-trip or snapshot extension); the .gcastate file-format agent persistence (the worker getState/loadState round-trip agents in-session; only the base64 file serialiser is pending).

Optional richness

A reusable per-pair force curve (Apply Force authors the net per-agent force today); a true agents-only no-grid mode; a strict deposit-snapshot for the closed feedback (the fused pass mixes same-step deposits intra-loop — harmless for diffusion-driven models).

Done this round (were deferred): Get Curvature, graph-authored forces (assumption 1), the WASM-decoupled cell field (assumption 2), graph-driven bonding / bondContactEvent obviated (assumption 5), and three breadth samples.

⑤ How to see it work

  1. Restart the dev server once (npm run dev) so the new library models are indexed, then open the Library and pick one of the four agent samples (or File → Load from public/models/).
  2. Morphogenesis — Growing / Differential Tissue: press ▶ and watch the cluster grow + divide; the Differential one colours cells by maturity (green stem → magenta terminal) and self-limits. Boids — Flocking: the scattered swarm aligns into a coherent flock. Chemotaxis — Aggregation: agents secrete a chemical (shown as a heat-map), diffused by the grid CA on WASM, and aggregate into streams.
  3. Use the Agent Brush overlay (top-left): Seed / Kill, Glue / Cut two agents, Paint Field, Clear all agents.
  4. Open the Modeler → Agents tab to see/edit each rule graph (note the neighbour-access + Apply Force nodes in Boids/Chemotaxis), and tune the physics in Properties › Bond-Graph Agents.

Verification used a headless harness (window.__simWorker + getState / the render snapshot) — flocking measured by velocity polarization, tissue by maturity-stage histograms, aggregation by spatial-bin clumping.
