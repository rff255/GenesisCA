Lattice GPU Render & Residency

Illustrated plan — CA grid performance, 2D + 3D, all three compile targets. Measurements: docs/PERF_REVIEW_LATTICE.md · Risk: docs/IMPACT_MAP_LATTICE_GPU.md · Runbook: docs/HANDOFF_LATTICE_GPU.md

Two rules govern every phase. Generality — gates key only on general model properties (dimension, depth, resolved target, topology, glyph usage, SIE flag, boundary, compiler usage flags); never on a rule shape or a shipped model. Feature preservation — the readback policy (free / frame / one-shot) is the only sanctioned way to remove per-frame CPU work: a feature may cost a readback while in use, never lose function.

2 · L1 — the 3D render round trip headline

Today — every 3D frame

After L1 — free mode

Free ⇄ frame — the readback policy (nothing loses function)

One-shot rule (unchanged, one place): any message that reads or mutates grid state while free mode is active blocks, pulls the GPU state down, then replays — so getState, paint, region write, inspect and save can never observe stale cells.

3 · L2 — the flat per-batch fence

Precondition. The 6.7 ms figure was measured in an occluded browser pane. L2 begins by re-measuring it in a visible pane. If the fence is really ~1 ms there, L2 is cancelled and recorded as not worth doing — a valid outcome.

Do not relax the asyncStepBatchInFlight message deferral. Concurrent batches were the P0 corruption bug in the agent arc: stale uploads racing fresh results, with zero errors reported. Only the GPU fence relaxes.

4 · L3 / L4 — dispatch and memory

L3 · sparse stepping reaches WebGPU

Measured on the CPU targets: 13.8× (Accretor 128³, 24.2 → 1.75 ms/gen). WebGPU ignores the feature today and reports sieActive: -1.

L4 · the CPU neighbour table

Measurement-gated. Is inline decode faster or slower than a table fetch on a CPU? Unknown — and JS aggregate fusion is disabled in inline mode. The phase opens with a throwaway A/B and stops if inline loses.

7 · Fundamentals vs scope

Genuine fundamentals — do not attempt

  • Async update mode on WebGPU — a write visible to a later cell in the same step is inherently serial.
  • Order-dependent indicator ops (toggle / next / previous) on WebGPU — non-commutative mutation of one accumulator by parallel writers.
  • SIE requires synchronous mode — the shuffled single-buffer order is incompatible with list iteration.
  • SIE excludes agent models — agents deposit into cell attributes outside the step, so the active set cannot observe those transitions.

f32-vs-f64 and per-cell-PCG-vs-shared-RNG are documented intentional differences, not limits.

Scoping limits — liftable

  • SIE excludes glyph models (a sparse glyph clear would lift it).
  • SIE on WebGPU → L3.
  • Inline neighbours on CPU → L4.
  • 3D never gets GPU direct render → L1.
  • Shadows / occupancy AO in free-mode 3D — frame-mode features in L1; a WGSL shadow pass could lift it later.
  • A display-resolution grid+agent composite (the world-resolution E2 version was user-rejected and is disabled) — an independent, still-open redesign.
