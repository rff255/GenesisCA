2 · The bisect falsified the threshold model

The shipped guard is VP9_444_MAX_WIDTH = 960 — “profile 1 only below width 960”. Bisecting the original 900 OK / 960 FREEZE bracket produced a different rule entirely: the failure tracks the coded width modulo 32, not its magnitude.

13 measurements, standalone probe (no app / no sim / no WebGPU), Chrome 148 · Windows 10. 640 and 864 and 896 freeze today — the shipped w < 960 guard lets all three through. Only the width matters: 912×928 is fast, 928×540 freezes.

The rule

cw = ceil(w / 8) × 8   // VP9 codes width in 8-px units
cw % 32 === 0  → FREEZE — renderer starved, never recovers
cw % 32 === 16 → FAST  — ~50 ms/frame, main thread responsive
cw % 32 === 8 or 24 → SLOW — ~800 ms/frame, ~1 s stalls

So the guard becomes a residue test requiring the one measured-fast class — not merely “avoid the frozen one”, because the slow class stalls the main thread for a full second per frame, which is the same harm in slower motion.

4 · How “never skip” works

draw() is synchronous and cannot await the encoder — which is why the drop policy exists. So the throttle goes where the loop is already asynchronous: the step chain.

It cannot hang

guardrole
LOSSLESS_HARD_CAP
= 8		 Unreachable in the play loop (the throttle holds it at ≤ 2). Exists so a burst of manual steps cannot grow the queue without bound.
LOSSLESS_STALL_MS
= 8000		 An order of magnitude past the worst measured per-frame encode. On expiry the run degrades to Skip mode and raises a one-time toast. Never flaps back.
REC readout⏳ waiting for encoder — a slowed run stays legible.

Does a skipped frame corrupt GOP 30?

No — and the reasoning is checkable. A skip happens before submission: encode() is never called for that frame. The encoder only ever sees the frames it was given, in order, and codes each delta against the previously submitted frame — so nothing references a frame that was never encoded.

The video simply jumps a few generations, exactly as under all-intra. Verified by decoding a with-skips GOP-30 file through VideoDecoder and asserting it yields exactly encodedCount frames with zero errors — a size or keyframe-flag check alone cannot tell “shortened” from “corrupt”.

5 · Capture-resolution caps

constantoldnewwhy
RECORD_MAX960912 912 ≡ 16 (mod 32) — the one measured-fast class. 5 % smaller than today, and unlike today it is genuinely 4:4:4 (960 ≡ 0 forces the profile-0 fallback, whose chroma subsampling bleeds 1-px colour transitions).
VP9_444_MAX_WIDTH960removed A max-width guard cannot express this failure — 640 freezes. Replaced by isVp9Profile1Safe(w) = ceil(w/8)*8 % 32 === 16.
RECORD_MAX_3D— (uncapped)1280 3D readPixels returns the whole drawing buffer: 23 MB/frame at DPR 2, 33 MB at 4K — the largest per-frame cost in the codebase, while 2D has been capped all along. 1280 ≡ 0 → profile 0, measured fastest of all (32 ms/frame). 3D therefore records in 4:2:0 — the documented consequence.

Margin, in the space the failure actually lives in

≡ 16 is the maximum possible distance from the frozen class, and every capture width is snapped to an exact multiple of 8 so rounding cannot drift across. That is a stronger guarantee than a linear margin — the failure is not linear in width. snapRecordWidth(w) lowers arbitrary widths (portrait canvases, tall grids) into the fast class, deriving the height from the same scale so the aspect ratio is preserved exactly; it engages only above 320 px, bounding the resolution change under 10 %.

Residual uncertainty, stated plainly. The residue rule is inferred from 13 points on one machine and one Chrome build; the cause (likely a libvpx tile/threading path) is unknown, and a different core count could shift it. The mitigation is that GenesisCA controls its own capture widths, and the fallback was measured fast at the worst residue. Anything unexpected degrades to 4:2:0 — never to a freeze.

6 · Out of scope

Tier 2 — stream to disk

Deferred by decision. File System Access / OPFS is not implemented. The investigation's measurements stand and its recommendation is marked DEFERRED BY DECISION so it is not re-litigated. Tier 1 already moved the ceiling from ~105 s to 4.4×–541× longer, and GOP 30 multiplies that again by ~3.5× on the dense content that bounds it.

Bitrate

Unchanged (max(4 Mbps, w·h·fps·6)). The investigation measured a 40 Mbps cap as a further 3.1× win, but at an unmeasured quality cost — a separate decision, not folded in silently. The Tauri binary-save gap is owned by a different session.
