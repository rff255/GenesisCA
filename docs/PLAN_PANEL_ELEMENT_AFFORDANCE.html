1 · Before — what the user is reporting

A model element row is a 2.5–3 % white wash with no border. It reads as a line of text, not as an object you can pick up — yet ten of these row kinds are draggable straight onto the graph canvas. Nothing on the row says so. Selecting a row also shifts the list by 2 px, because only the selected state declares a border.

4 · The token trap this had to route around

The row outline is --color-border, never --color-widget-border. The two themes need opposite edges: Nocturne is near-black, so definition comes from a lighter line; Blender's own idiom is a darker separator. --color-widget-border is the input/button outline, and its own token comment says it is “almost identical to panel bg — outlines virtually disappear” on Blender. Using it would fix the bug on Nocturne and leave Blender exactly as flat as today.
themepanel surface--color-widget-border--color-border
Nocturne#16181d#262a31 — lighter, reads#2a2d35 — lighter, reads
Blender#3d3d3d#3a3a3a — ≈ the surface, invisible#1d1d1d — darker, reads

Why the rail is a ::before, not a border or a box-shadow

techniqueverdict
box-shadow: inset.dropIndicatorBefore/After already own the row's box-shadow during a reorder drag; a second rule would replace theirs, so the drop indicator would vanish on exactly the rows that can be reordered.
border-left: 3pxReflows the row's content by 3 px.
::before, absolutely positionedZero layout, no collision, inset from the rounded corners.
