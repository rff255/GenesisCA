C3 — Fast-path diagnostics popover + generated capability docs

Illustrated plan for PLAN_CLARITY_C3.md. Proposal items P4 (rest) and P8. C1 = which engine · C2 = what it does each generation · C3 = what actually engaged, and why not.

Class F (fast-path eligibility) is the last of the four limitation classes still invisible. It is never an error: an ineligible model computes exactly the same thing, just slower. The popover therefore uses green / grey — never red.

Each entry is { generation, text }, appended at the fallback site, capped at 40 (oldest dropped). Sites that could fire every step reuse their existing warn-once latch, so a hash overflow logs once, not 10 000 times.

Additive: a new case in the message switch, no existing message shape touched (verify-agent-render.mjs stays green). Every field is read from state the worker already maintains — agentResidentEligible(), sieParamsPresent, the E1b counters, agentRenderActive / agentCompositeActive — plus the new event log. Zero simulation-behaviour change: only array pushes, counter bumps and a message case.

Runtime truth wins. C1's readout approximates the residency facts from node types (its own report flags this as C3's follow-up). The worker knows usesSpawn / usesStop / indicatorsBuf / maxBonds as allocated, so where the two disagree the popover shows the worker's answer.

Illustrative rows only — the real table is emitted from the sets above, so a node added to the catalogue and forgotten in a supported set shows up as ✗ on the next run instead of drifting silently.

Numbers stop being hand-typed

Help currently asserts "around 115 selectable node types (42 of them agent nodes)" while NODES_REFERENCE.md says 150 selectable, 53 agent — the two documents already disagree. Generated counts end that class of bug. The capacity constants (AGENT_NEARBY_SCRATCH_SLOTS, AGENT_WEBGPU_NEARBY_SLOTS, AGENT_GPU_ARRAY_CAP, the bond-request queue depth) are emitted with their values, which is exactly what Class C promises: a limit always stated with its number.

--check is a gate

Regenerates in memory and diffs against the committed module; non-zero exit when stale. Adding a node without updating the docs becomes a failing check rather than silent drift — the whole point of P8, since hand-maintained tables are how the present drift happened.

6. Out of scope this phase

  • Toasts for fallback events — C6 owns the UI half of loud fallbacks. C3 builds the log it consumes.
  • Any engine / resolver / emit change — compile-identity must stay byte-identical on all 29 models.
  • NODES_REFERENCE.md regeneration — its per-node target facts live in a prose Notes column; converting that is a separate migration. The generator is shaped so a later phase can emit it.
