Graph Layout + Rule Cadence

Illustrated plan. Design authority: IMPACT_MAP_GRAPH_LAYOUT_CADENCE.md · Execution: HANDOFF_GRAPH_LAYOUT_CADENCE.md

One reported symptom — the grown graph is an unreadable blob and runs slowly — with four measured causes. Everything here is measured, not reasoned.

1 · Why it collapses

Measured on the real growth process

The third row killed the obvious fix. interactionRange widens the search, not the force — which is zero past contact regardless, and past contact the sign flips to attraction. This is not a tuning problem.

2 · Cadence — in the rule graph, not the engine L2

There is no engine clock to decouple — the force pass already runs every generation. What is missing is the rule's ability to say when it rewrites. And today nothing can read the generation from a cell or agent graph (ovGetGeneration is Overseer-only; generation is not in the agent ABI).

phase matters as much as period: the reference alternates states-then-divisions, which is exactly period 2 at phases 0 and 1.

⚠ The delicate point — GPU residency

dispatchResidentBatch(rt, gens, …) const enc = device.createCommandEncoder() for (let g = 0; g < gens; g++) { // ALL generations… … hash · behaviour · force · posCommit … } device.queue.submit([enc.finish()]) // …ONE submit, no CPU touch per gen

A generation supplied through the Control uniform would be constant for the whole batch — silently wrong, on that path only, and invisible to any single-step test.

Fix: a GPU-side counter in a storage buffer, bumped by posCommit, which already runs once per generation. Cheap, keeps residency.
What does NOT belong in the graph: how many times the solver iterates per generation. That is numerical relaxation, not rule logic — an engine knob, like the existing positionalIterations. Putting it in the graph would be like exposing an ODE's step count as a node.

Risks, ranked

  • The hash bin edge. If the charge cutoff does not join the binEdge max, the force is silently truncated — plausible-looking and wrong. It gets its own exit-gate test.
  • The B1 mirror force variant. A second force pipeline exists; missing it diverges only for models that engage it.
  • GPU residency + generation (above) — wrong only there, only in a batch.
  • Mid-list ABI insertion. Append; a mid-list lane shifts every later baked offset (P5's finding).
  • 3D charge cost. The stencil is a volume — measure, don't assume the 2D default transfers.
