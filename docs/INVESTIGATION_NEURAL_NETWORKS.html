TL;DR A Neural CA is a GenesisCA model with learned constants. The constants already have a home.

Every piece of a Growing NCA except the dense layers is a shipped node; the weights fit the Lookup Table model attribute, which runs on JS, WASM and WebGPU, is live-updatable, and travels in the .gcaproj. Three primitives, a weight importer and a gradient-free training loop on the Overseer close the gap. Gradient training stays outside in v1 — the practitioners' own workflow.

have  Weight store, on every target

A Lookup Table is a flat float array with a live update seam on all three targets (updateLookupTable → the wasmMemory view + the WebGPU varAux/auxF32 upload), N-D axes up to 1 M entries, a seeded Randomize block, presets as checkpoints. Verified.

gap  No dense layer, no array ⇄ attributes bridge

There is no weighted sum over an array (Aggregate is sum/product/min/max/avg/median; Vector Op dot is 2–3 wide). A Growing NCA by hand is ~2 000 nodes. Verified against the catalogue.

gap  Training: the loop exists, the verbs do not

The Overseer already re-rolls tables from a seed, resets, runs fixed counts, reads indicators and keeps statistics. It lacks perturb, snapshot/restore and commit. Local (Hebbian) rules are expressible today.

honest  Gradient training belongs outside (v1)

Backprop through 64–96 unrolled generations needs a differentiable framework (ORT WASM ≈ 20 MB / 8 MB / 3 MB minimal) and a fourth compile target — or a hand-rolled BPTT for the NCA subgraph. Import the weights; keep the hand-rolled route on the table.

The organising observation. An NCA update is one neighbourhood gather, two dense layers, one random mask, one 3×3 max, one residual add. GenesisCA has the gather, the mask (Get Random), the max (Aggregate max with the centre cell included) and the residual add (Update Attribute increment). What is missing is the dense layer — and that is a primitive, not a rewrite.

Why a primitive and not "just wire it". 4 The design — three primitives, one weight store, no new runtime type

Weights are Lookup Tables, activations are Local Variable arrays, and the Growing NCA becomes a ten-node graph. Only Dense Layer needs real per-target emit.

Why weights are Lookup Tables and not a new "tensor" type

  • Live on every target [verified]: updateLookupTable copies into the existing view over wasmMemory (the WASM step reads it through its baked offset) and uploads to the WebGPU varAux; the agent targets carry tables in the agent memory region and the auxF32 buffer.
  • N-D axes, sized for this: MAX_LOOKUP_AXES = 6, intRange spans to 4 096, 1 048 576 entries per table. A weight matrix is a 2-axis intRange × intRange table; a bias a 1-axis one.
  • Persistence for free: tableData rides the .gcaproj; a preset snapshots every table — a checkpoint.
  • Already has a UI and an Overseer verb: the matrix widget, the seeded Randomize block (weight init), ovRandomizeTable.
  • Precision: f64 on the CPU targets, f32 on the GPU — the documented stance; NCAs train in f32 and the Distill demo ran at 8 bits.

Dense Layer — the contract

Dense Layer
  in:  x (array, float)          config: weights = <table id>    2-axis, out × in
  out: y (array, float)                  bias    = <table id | none> 1-axis, out
                                         activation = linear | relu | leaky_relu | tanh | sigmoid
                                         rowOffset (integer port, optional)   ← shape C: a weight BANK row

  y[o] = act( b[o] + Σ_i W[o][i] · x[i] ),  i ascending — the accumulation ORDER is the contract
  JS ≡ WASM bit-identical (the Math.hypot lesson); WGSL f32. tanh/exp are already host imports on WASM.
Cost model (estimates from operation counts — nothing here is measured). ~8.6 k MAC per cell per generation with fixed filters, ~15 k with a dense perception. 100×100 ≈ 90–150 M MAC: JS ~0.3–0.6 s, WASM ~0.1–0.3 s, WebGPU ~1–3 ms. 1000×1000: WASM tens of seconds, WebGPU ~0.1–0.3 s. An NCA at any interesting size is a WebGPU feature — and JS/WASM still run it, as the reference and the fallback. Cost a dense layer on its widest layer: the WebGPU per-thread array budget is real (AGENT_GPU_ARRAY_CAP = 2048).

6 Training — the honest map

Four routes, ranked by what they cost the app. The recommendation is the practitioners' own workflow for gradients, and the Overseer for everything gradient-free.

Shape C — neuroevolution

rowOffset = genomeId, a fitness attribute, Kill / Create Agent for selection (shipped), one mutate-row verb and a copy-row-on-division hook. Fixed topology, evolved weights — the NEAT-style regime. True NEAT is shape A's Form / Rewire Bond on neuron-agents: expressible, slow.

DiffLogic CA — import the circuit

The frozen artifact is a gate list; a generator turns it into Logical Expression nodes. No engine or compiler change, exact Boolean parity on all three targets — the one NN family where the f32/f64 stance does not even apply. Game of Life's 336 gates are the regression fixture.

Risks worth stating now

  • JS/WASM dot products are bit-identical by contract; WGSL's f32 will diverge visibly after a few hundred NCA steps — the documented stance, but the first thing a user notices. Say it in the sample.
  • The WebGPU per-thread array budget bounds the widest layer; the badge must state the number, not merely refuse.
  • Weight names arrive as dense_1/kernel:0 or layers.0.weight; remember the mapping per model.
  • The alive mask needs includeCentralCell on the Moore neighbourhood, or every cell's own alpha is silently ignored.
  • Where does "train" live in the UI? The Overseer panel is the honest home for ES; a dedicated Train panel is only justified by the hand-rolled BPTT route.
