Implementation handoff · v1.1 · twice-audited

Agent Capability Profiles

Two adversarial source audits (30 agents) stress-tested the architecture and the implementation plan. This v1.1 encodes the verdict, the corrections, the de-risked build order, and — new in v1.1 — the concrete drafted specs (types, presets, dependency graph, migration, field order, ABI audit, Spawn Event) an implementer works from directly. The full specs live in the .md §3; this page is the map.

✓ Go with fixes Pass 1 (feasibility): 14 audits + red-team → 2 overclaims, 4 blockers Pass 2 (plan hardening): 8 reviews + synthesis → footprint/terminology/sequencing fixes + 8 drafted specs

The architecture is sound and is the codebase's own trajectory (the type-removal, maxBonds=0, useBondingPhysics, hasLookupTables, agentAccess, gridCells gates are real precedents). But the design plan materially overclaimed two load-bearing things, and every capability audit independently confirmed the same core defect: the ~203-byte intrinsic core is not freely gate-able — position, velocity, force and radius are read unconditionally by the integrator, the render snapshot, serialization, and the compiled behaviour preamble. The fix: ship the editor-surface clarity win now (near-zero risk), redraw the honest core, build one shared ABI derivation first, then gate only the genuinely-appendable capabilities — Motion/Body SoA-gating is a separate XL milestone.

2The honest core vs. the gate-able set

3Shared infrastructure — build FIRST (STEP 0)

S1 · One deriveAgentAbi(profile, model) → OrderedDescriptor[]

The single ABI source of truth: { name, resolve:(store,model,ctx)=>value, gate?:(profile)=>bool, comment? }. Consumed by all four sites — buildAgentLoopParams (names) ↔ buildAgentLoopArgs (values) ↔ the parity harness buildArgs (re-derives, no 4th copy) — plus the division/init(/spawn) pairs. One gate-predicate evaluation per capability. Acceptance: Full profile reproduces today's params/args byte-for-byte; parity harness 0 mismatches.

S2 · One profile-driven computeAgentMemoryLayout

Gates both the CPU/WASM AGENT_F64_FIELDS baked offsets and the WebGPU AGENT_GPU_F32_FIELDS strided SoA from the same capability set, via append-at-a-stable-slot. Add a cross-target layout audit.

S3 · One AgentCapabilities profile, read everywhere

On model.centerBased, carried into the store, consulted by snapshotAgentsForRender, the Edit-panel row filter, getAgentState, and serialize/deserialize — so no consumer diverges.

S4 · Explicit dependency graph, auto-enforced  ·  S5 · Config-aware migration + versioned payload

Collision=Soft⇒Motion=Force · Growth⇒Body · Division⇒Body(+Bonds) · Bonds=Physics⇒Motion=Force. Migration: maxBonds:0⇒Particle, else Full. AgentStatePayload versioned (v1 legacy→Full, v2 profile-aware) — reject incompatible loads loudly.

5De-risked build order

STEP 0

Shared layout-agnostic ABI derivation (prerequisite) — lands no capability

Build S1 (a descriptor set + deriveAgentLayouts re-ordering per target — CPU and GPU differ in order); refactor the loop/division/init mirrors + harness to consume it.

GATE · the 4-site FIELD-ORDER audit (not arity — that misses order shifts) passes for Full, byte-identical to today; parity 0 mismatches
STEP 1

Editor-surface gating  ◆ SAFE · ship it

Schema + S4 dependency graph (moved forward) + presets + usage-aware migration + Properties panel (footprint bound to computeAgentMemoryLayout) + requirements tags + hiddenPorts + Edit-panel/inspector filter + linked-agent-mapping gate + macro-internals re-validation (informational). No SoA/engine change.

GATE · every preset shows only its nodes/ports/rows; Full deep-equals Morphogenesis; all .gcaproj byte-identical. The whole clarity win at near-zero risk.
STEP 2

Honest-core doc commit + badge-severity contract (no SoA code)

Commit §2; version the docs; informational→blocking badge contract. (S4 already shipped in STEP 1.)

STEP 3

First real SoA gate — Bonds + Field coupling (pipeline proof)

Gate the bond group (90% there via maxBonds=0); refactor runAgentStructuralPhase into capability-gated sub-steps (B2); _agentBondCount stays in the ABI (B1a); macro-internals badge becomes blocking.

GATE · parity + layout audit for Particle/Social-Graph/Vivarium + test-bonds-allocation + test-structural-guards + WebGPU L∞
STEP 4

Append-at-stable-slot gates — Sprite-block · Lifespan · Growth · Division

First: reorder AGENT_*_FIELDS to core-first append-at-stable-slot (the interleaved order blocks gating). Then gate each; Sprite-block converts the first unconditional ABI block; add Get Age; decouple Growth; Division fallback table (Bonds→tension vs spread axis).

GATE · reorder passes Full byte-identity first; then parity + layout audit after EACH, all presets
STEP 5

Net-new — split 5a Spawn · 5b FOV+Sensing · 5c Orientation

Independent fail-fast gates. 5a: Spawn Event root + deriveSpawnAbi + spawn* fields + free-list/overflow/leak-sweep (highest-risk). 5b: Get Agents In View / Sense Hemifield. 5c: split the sprite ABI so facing threads under hasSprites OR hasOrientation.

GATE (each) · parity + layout audit + WebGPU L∞ + browser end-to-end, 2D+3D
STEP 6

Deferred XL — Motion=Static + Body SoA-gate

Only after 0–5. Explicit Static integrator/force-pass branches on all 3 targets + snapshot/serialize guards. No .gcaproj breakage: a Motion=Static file saved in STEP 1–5 (toggle a no-op saved as intent) loads Static; the integrator branch replicates the always-on-but-unused velocity.

6Blocker & major-risk checklist

  • B1 · Field-order audit before any field gate — arity parity misses order shifts under matched arity.
  • B1a · _agentBondCount stays in all 3 CPU ABI mirrors even when Bonds=off (a core reduction; deleting it shifts every downstream param).
  • B2 · runAgentStructuralPhase refactored into capability-gated sub-steps — killRequest/divideRequest/bondFormReq reads go OOB the moment allocation is gated.
  • B3 · CPU and GPU layouts driven by the same predicates — separate ordered lists; audit checks field sets match.
  • B4 · Motion/Body stay always-allocated in v1 — no Static path exists.
  • B5 · Macro internals re-validated after expandMacros — a Divide/Form Bond in a macro bypasses palette gating (badge STEP 1, error STEP 3).
  • B6 · Linked agent output mappings on gated attributes gated — a mapping on radius/age dangles (_undef).
  • M1 · Versioned AgentStatePayload · M2 Retag+gate density · M3 Decouple Growth from bonding · M4 Gate the spatial hash · M5 One dependency graph at 3 gates · M6 Migration usage-widened (never narrowed) · M7 detectCapabilityRequirements covers macro/division/init/spawn nodes · M8 Footprint bound to computeAgentMemoryLayout.
STEP-1 caution (must be explicit): because STEP 1 changes no engine behaviour, hiddenPorts is purely cosmetic — the compiler still emits the myRadius preamble, so an existing wire into myRadius under Body=off keeps compiling. The amber badge is informational (non-blocking) in v1 and becomes blocking only from STEP 3. Do not remove any emit until Phase 2.
