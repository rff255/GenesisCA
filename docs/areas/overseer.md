## Overseer (Experiment Orchestration) — the THIRD graph (branch `sim_agent_fixes`)

The **Overseer** is an opt-in third rule graph that authors experiment protocols AROUND the simulation — replicate statistics (N seeded runs → mean ± std), parameter sweeps, run-until-stop protocols, capture — implementing docs/PLAN_OVERSEER.md (PR0–PR2 scope + the PR1 sample). **The Cells/Agents graphs are the physics; the Overseer is the scientist.** Everything is gated by **`model.overseerConfig?.enabled`** (Properties → Execution → "Use Overseer") — with it OFF there is ZERO trace of the feature anywhere (no graph pill, no palette nodes, no right-panel tab strip — the panel is just the Controls, as before; verified: loading a normal model over an overseer model removes every trace). All schema additive; legacy files load unchanged.

### The core posture — a DRIVER, not a compile target
The Overseer runs at EXPERIMENT tempo (a few node evaluations per run) as an **async JS program on the MAIN thread**, commanding the sim worker through the **existing message protocol** exactly like the transport bar does (post a step batch → await `stepped` → decide). The CA keeps running on whichever compile target the model selects — **the ALL-TARGET rule is satisfied by construction** (same stance as the agent colour pass). Verified end-to-end on ALL THREE targets through the real worker: the same seeded experiment is **bit-reproducible on JS and WASM (bit-IDENTICAL to each other)** and statistically reproducible on WebGPU (per-cell PCG — the documented stance).

### Schema ([types.ts](src/model/types.ts), all additive)
`CAModel.overseerGraphNodes?`/`overseerGraphEdges?` (serialized compact-inline like the agent graph) + **`overseerConfig?: OverseerConfig`** = `{ enabled, seedPolicy?: 'none'|'fixed'|'sequential', baseSeed?, maxSnapshotSlots? }`. `NodeRequirements.overseer?: boolean` gates the node family. ModelContext: `SET_OVERSEER_GRAPH` + `UPDATE_OVERSEER_CONFIG` (+ both useMemo dep arrays), LOAD_MODEL seed guards, and **`patchAllNodes` scans `overseerGraphNodes`** (its result now carries the graph and all 13 consumer sites SPREAD it — `{ ...model, ...patched }` — so adding a future graph can''t silently miss a cascade site).

### Editor (third pill + allowlist gating)
`ActiveGraphKind` = `'cells' | 'agents' | 'overseer'` ([graphState.ts](src/modeler/vpl/graphState.ts) + [modelerUiState.ts](src/modeler/modelerUiState.ts)). GraphEditor reuses the whole Agents-graph swap machinery: the amber **Overseer** pill (shown only when enabled; the strip now renders when `agentsTopo || overseerOn`), the graph-swap effect + scheduleSync/flushSync routing to `setOverseerGraph`, the graph-kind-tagged clipboard, the fall-back effect when the feature is disabled mid-session, and `experiment` in `SINGLETON_NODE_TYPES`. **Availability on the Overseer graph is an explicit ALLOWLIST** (`OVERSEER_UNIVERSAL_TYPES` in [nodeValidation.ts](src/modeler/vpl/nodes/nodeValidation.ts)): overseer nodes + the context-free universal subset (sequence/conditional/loop/forEachInArray/switch + getConstant/arithmetic/expression/Compare/logic/getRandom/valueSwitch/proportionMap/interpolation/arrayElement/arrayLength/getModelAttribute). EVERY per-cell/per-agent node is excluded (the allowlist IS the safety boundary); overseer nodes are invisible on the other graphs and when the feature is off; `isMacroAvailableOnGraph` gained the overseer arm.

### The node family (20, `requirements: { overseer: true }`, prefix `Ov*`)
**Root**: `experiment` (white, singleton — runs on the panel''s Run Experiment). **Run control** (indigo `#3949ab`): `ovResetBoard`, `ovRunGenerations` (Count inline — a **FIXED-count run**: a Stop Event does NOT halt it, so every replicate reaches the same iteration = the fixed developmental time point an ensemble average needs; Run Until Stop is the detector-gated node), `ovRunUntilStop` (Max Gens; value outs `atGeneration` + `stoppedBy` 0=cap/1=stopEvent/2=endCondition — action RESULTS, captured once as function-scope lets), `ovSetSeed`, `ovSetModelAttribute` (runtime-only slider semantics — never dirties the model), **`ovRandomizeTable`** (runtime-only re-roll of a Lookup Table's values from a Seed at a Density — the SAME deterministic `randomFillTableData` as the editor's Randomize block; the rule-space-search primitive, journals each {seed, density}; `O.randomizeTable` → `deps.randomizeTable` resolves axes + value policy in SimulatorView and posts `updateLookupTable`, multi-axis and legacy), `ovLoadPreset` (live-apply only; structural presets journal + skip). **Measurement** (teal `#00838f`): `ovReadIndicator` (config indicatorId + category for freq maps — bool/tag categories get a select, numeric buckets a text input; spatial indicators excluded like End Conditions), `ovGetGeneration`. **Data/stats** (purple `#6a1b9a`): `ovCollectSample` (series + run/experiment scope), `ovCollectSpatial` (capture a SPATIAL indicator''s whole per-position curve for one category as one replicate — see "Spatial aggregate" below), `ovClearSeries`, `ovSeriesStat` (mean/std/min/max/median/sum/count/ci95), `ovSweepValues` (list or linspace → array out; feed forEachInArray). **Capture** (blue-grey `#546e7a`): `ovLog` (`{value}`/`{gen}` placeholders), `ovScreenshot`, `ovStartRecording`/`ovStopRecording`. **Control**: `ovStopExperiment` (no NEXT). CaNode config blocks + `detectMissingConfig` cases for all reference-typed configs. Catalogue: **141 selectable** node types (144 − 3 hidden macro) / 45 agent / 20 overseer.

### Spatial aggregate — replicate-averaged chromatograms (mean ± σ)
`ovCollectSpatial` ([OvCollectSpatialNode.ts](src/modeler/vpl/nodes/OvCollectSpatialNode.ts)) captures a SPATIAL indicator''s (`xAxis` rows/columns/layers) current per-position-bin curve for ONE category as one run of a named **spatial series** (`O.sampleSpatial(series, indicatorId, category, chart)`). Its validation is the inverse of `ovReadIndicator` (requires a SPATIAL indicator + a category). The runtime ([overseerRuntime.ts](src/simulator/engine/overseerRuntime.ts) `spatialSeries` map + `spatialAggregate(name)`) stacks the per-run curves and computes a **per-bin mean + sample-σ (n−1)**; the panel ([ExperimentsPanel.tsx](src/simulator/ExperimentsPanel.tsx) `SpatialAggregateChart`) renders each **Chart group** (series sharing a `chart` name overlay on one canvas) as: faint individual replicate curves + a σ band + the bold mean per series, palette by insertion order. `SimulatorView.spatialMeta(indicatorId)` resolves the X-axis label (axisName + binSize) from the indicator def + live dims. CSV export is long-format (`series,run,bin,value`); JSON carries the aggregates. The **Chromatography** model ships the headline use: 12 seeded replicates × Reset → Run 300 → capture S1+S2 → Run to 600 → capture S1+S2, aggregated into two mean±σ chromatograms (verified in-browser: S1 [weak B-affinity] peak migrates bin 4→7 down the column while S2 [strong] lags at bin 1→2, a ~5-bin two-peak separation — the paper''s Fig. 3 as an ensemble average, S1 leads S2). **Gotcha**: `ovRunGenerations` being detector-gated would truncate the fixed-time snapshot and pollute the ensemble with the model''s spurious early-elution (a solute wrapping up the vertical torus) — hence Run Generations is a strict fixed-count run.

### The compiler ([compiler/overseer/compile.ts](src/modeler/vpl/compiler/overseer/compile.ts))
`compileOverseerGraph(nodes, edges, model)` → `{ driverCode, error }` where driverCode is the async function BODY for `new AsyncFunction('O', body)` (null when no `experiment` root — not an error). Front-end = the standard pipeline (`expandMacros → collapseReroutes → expandMultiAttrs`). **Value nodes reuse their per-node JS `compile()` verbatim** (lockstep semantics with the cell/agent compilers; the driver preamble provides `modelAttrs` + `_rs` for getModelAttribute/getRandom). **Values are RE-EVALUATED at every flow statement that consumes them** (each statement is wrapped in its own `{ … }` block, so `const _v<id>` redeclares per statement) — a Read Indicator consumed after a Run reads the POST-run value; the exceptions are ACTION RESULT ports (Run Until Stop) and For-Each element/index, which are captured once (`let _v<id>_<port>` hoisted / loop locals) and referenced afterwards. `if (O.aborted) return;` injected after every await + at loop back-edges. Flow walk mirrors the cell compiler''s semantics for conditional/loop/forEach/switch (both switch modes + firstMatchOnly) and walks `next` pass-throughs. Defence-in-depth: any reachable non-allowlisted node type → compile error. Verified by [scripts/test-overseer-compile.mjs](scripts/test-overseer-compile.mjs) — 18 assertions running the emitted driver against a mock O (statistics loop, sweep × until-stop with action results, conditional + stop, guards, RNG determinism).

### The runtime ([engine/overseerRuntime.ts](src/simulator/engine/overseerRuntime.ts)) + worker correlation
`OverseerRuntime` attaches its OWN worker listener (workers support multiple listeners — SimulatorView''s handler is untouched) and correlates its batches via **`reqId`**: `StepMsg`/`ResetMsg` gained `reqId?: number`, echoed on the resulting `stepped` (module `stepAckId` consumed by `sendColors` — set in the step/reset cases, carried across the async WebGPU/agent batch tails) and on the step case''s `stopEvent` posts. After each ack the runtime waits ONE macrotask so a trailing `stopEvent` (posted right after `sendColors`) is observed before deciding "no stop". Batches are bounded (`OV_BATCH` 500 gens) so Abort lands within one batch. **Seed policy**: `maybeAutoSeed` posts `setRngSeed` BEFORE each `reset` (fixed = base; sequential = base + reset-count) unless the graph ran Set Random Seed since the last reset. **Series** (run/experiment scope; run-scoped clear at each Reset) + **Journal** (capped 2000) + CSV (long format) / JSON export. `O.indicator` reads the runtime''s OWN last-stepped copy (no ordering dependence on SimulatorView''s handler); end conditions checked per batch via the passed `evalEndConditions`.

### SimulatorView wiring + the Experiments panel ([ExperimentsPanel.tsx](src/simulator/ExperimentsPanel.tsx))
The panel is titled **"Overseer Experiments"** and, when enabled, lives on its OWN tab of the shared right panel — SimulatorView's `rightPanelTab: 'controls' | 'experiments'` swaps the panel between the "Controls" view (brush + layers + indicators) and the "Overseer Experiments" view (mirroring the modeler's per-panel tabs). The tab strip (`.rightPanelTabs` / `.rightPanelTab` in SimulatorView.module.css) renders ONLY when `overseerEnabled`; with the feature off the panel is just the controls (as before, no tabs) and an effect resets `rightPanelTab` to `'controls'`. The ExperimentsPanel root carries the `rightSectionIndicators` grow class so it fills the panel (its body scrolls) as the sole tab content. Panel contents: Run/Abort, live status (runs · gen · elapsed), scrolling Journal, Series table (n/mean/std/min/max), an auto-rendered **`ScalarSeriesChart` per scalar series** (a HISTOGRAM of the value distribution across the runs with the mean marked — the classic replicate-distribution figure — toggleable per series to a per-run SEQUENCE view; state in the panel's `scalarModes`, default `'hist'`, series with ≥2 samples), the spatial aggregate charts, CSV/JSON export, and a hint when the graph has no Experiment root. So an experiment produces real FIGURES (histograms + spatial mean±σ curves), not just a text report. SimulatorView compiles the graph in a `useMemo([model, overseerEnabled])`, builds the runtime deps at Run time (worker access, `evalEndConditions`, `handleModelAttrChange`, the live-preset predicate mirroring `handleLoadPreset`''s structural check, screenshot/recording pass-throughs, `runtimeModelAttrsLatest` snapshot ref), and enforces **mutual exclusion**: `sendNextStep`/`handleStep`/`handleReset` early-return while an experiment runs; the `stopEvent` handler suppresses its notice (the runtime journals it); ANY model change / worker reinit / manual recompile / unmount **aborts the experiment** (`abortExperiment` at the model-effect top, `initWorkerWithDimensions`, `handleRecompile`, the unmount cleanup).

**Both Experiment charts are WIDTH-RESPONSIVE via the shared `useMeasuredWidth(wrapRef)` hook** (ExperimentsPanel.tsx) — the SAME discipline the indicator charts each inline: a **ResizeObserver on the always-mounted wrapper div** (so a right-panel splitter drag / window resize / panel collapse re-measures and redraws) + a **`useLayoutEffect` fallback with NO dep array** for the renders the observer hasn't delivered yet, the classic case being a FRESH MOUNT — the Experiments panel *unmounts on a tab switch*, so a resize performed while on the Controls tab must be picked up when Experiments mounts back. The measured width drives BOTH the canvas backing store (× dpr) and its CSS width, so the two can never disagree; the draw effects carry `width` in their deps. **They previously read `wrap.clientWidth` INSIDE the draw effect**, whose deps are only `values`/`mode`/`version`/`entries` — so a resize (which changes none of them, and which the splitter performs by mutating `panel.style.width` with no React state change at all) never re-ran it, while `canvas.style.width` stayed PINNED to the stale pixel width. The canvas then overflowed or under-filled its container until something unrelated forced a redraw (toggling Histogram/Runs, or a new `version` from a running experiment) — the reported "not dimensioning properly / not very responsive". **Adding a canvas here means using the hook, not re-reading `clientWidth` in a draw effect.**

### setRngSeed is now a SUPPORTED worker message (bug fixed)
Promoted from DEV-only. **The bug the E2E caught**: the WASM step/init read the RNG from the in-memory cell at `layout.rngStateOffset`, synced from `rngState[0]` only at `initGrid` — so seeding was a silent no-op on the WASM target (identical seed policies gave different WASM replicate statistics across two runs while JS reproduced bit-exactly). The handler now also writes the wasmMemory cell and re-derives the WebGPU per-cell PCG streams via `seedRngState`. Post-fix verification (real worker, 5-run experiment, sequential seeds): JS 453.4 ± 15.534 bit-reproducible; **WASM bit-IDENTICAL to JS** (453.4/15.534/440/479) and reproducible; WebGPU 460.8 ± 15.707 reproducible.

### Sample + harness + verification recipes
**`GoL Replicate Statistics`** ([scripts/gen-overseer-stats.mjs](scripts/gen-overseer-stats.mjs) → public/models/): Conway GoL 60×60 (p=0.35 random-soup Init Event, linked OM, linked freq indicator with trackedValues) + the Overseer protocol `Clear Series → Loop ×20 { Reset → Run 200 → Collect ← Read population[true] } → Log mean → Log std`, sequential seed base 4242. Verified in-browser on WASM: 20 replicates in 1.9 s, survivors 283.7 ± 58.6 (n=20, range 131–397), second run bit-identical. The dev harness `compileAll` gained an `overseer.driverCode` surface + the migrate guards. **Gotchas for future work**: (1) the runtime''s deps close over the model at Run time — fine because any model change aborts; (2) a no-Output-Mapping model''s reset/mutation refresh runs an extra STEP (pre-existing worker behaviour), so per-run generation counts read slightly above the requested N — consistent across runs, harmless for statistics; (3) Run Experiment while the tab is hidden keeps stepping (the auto-pause only gates the play loop) — deliberate; (4) snapshot slots (`ovSaveSnapshot`/`ovLoadSnapshot`), `ovWriteRegion`, `ovApplyImage`, overseer-scoped Local Variables, result CHARTS, the parallel worker pool (plan PR4) and the EA sample (plan PR5) are NOT yet implemented — see docs/PLAN_OVERSEER.md for their design.

## Overseer ⇄ LIVE mode — the mutual exclusion (Phase 4, 2026-09-07)

**An experiment and Live cannot share a session, and the reason is mechanical, not cosmetic.**
`SimulatorView`'s model effect opens with `if (prev && overseerRunningRef.current) abortExperiment('model
changed')` — and in **Live** the model changes as the user types. A sweep whose rule shifts mid-run
measures nothing, and the abort would read to the user as a crash.

Both directions, and they get **different dispositions** — the UI doctrine's hide-vs-grey test is
*can the user reach the working state from this panel?*

| Direction | Disposition | Why |
|---|---|---|
| **Overseer running → Live** | the **Live nav button is DISABLED IN PLACE**, with the reason in its `title` (`LIVE_OVERSEER_BUSY_REASON` in [src/live/liveState.ts](src/live/liveState.ts)) | **Grey.** The **Abort** button is visible in the Experiments panel, so the working state is one click away — the documented "one setting away" case, and the direct sibling of the doctrine's own *"the Overseer's Run button mid-experiment"* example |
| **In Live → Overseer** | the **Experiments tab strip is HIDDEN**, `rightPanelTab` is coerced to `'controls'`, and `handleRunExperiment` early-returns | **Hide.** From inside Live the working state is structurally unreachable without leaving Live, so a greyed tab would be clutter that only raises "why is this here?" |

- ⚠ **A hidden control needs its STATE handled, not just its markup.** A model whose right panel was left
  on `'experiments'` would otherwise strand the Live panel on a view that no longer renders — the same
  coercion the `overseerEnabled` fallback effect already performs. The Controls arm additionally renders on
  `live`, so the panel is never blank for the one frame before the coercion commits.
- ⚠ **MIRROR INVARIANT.** `App` lives in another React tree, so the predicate is published as a module
  global through `liveState.setOverseerRunning` — **assigned in the same statement block as the
  `setOverseerRunning` React state**, and cleared on `SimulatorView` unmount (a module global left `true`
  would grey the nav button for good).
- A model with `overseerConfig.enabled !== true` sees none of this: `overseerRunning` is never set.
- **Verified** on `GoL Replicate Statistics`: Run → the Live button disabled with the reason; Abort → it
  re-enables; entering Live → no tab strip, no Run Experiment button, the Controls panel showing the brush.
