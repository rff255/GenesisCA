## 3D Grid CA (milestone, in progress — branch `grid_3d`)

Makes the lattice a **`W×H×D` volume** end-to-end: schema, all three compile targets, 3D neighbourhood editing, authorable RGBA alpha, a WebGL2 voxel renderer, and the save/load + indicators + inspector consumer-scan. Runbook: [docs/HANDOFF_3D_GRID_CA.md](docs/HANDOFF_3D_GRID_CA.md). The engine 3-ification is incremental (`total = W*H*D`, a 3-tuple offset table, a `_layer` decode, **stride stays `coords.length`** so neighbour access is 3D-for-free); the renderer is wholesale new. **`gridDepth===1` / `dimension==='2d'` is the byte-identical 2D fast path on all three targets** (every existing model + legacy file compiles verbatim). Out of scope: bond-graph agents (UI checkbox hard-disabled), variegation-in-3D (2D-locked, V-tab elided in 3D). (The 3-axis `neighborIndex` codec — once out of scope — is now DONE: see PR10.)

### PR2+PR3 — JS 3D engine + compiler decode (done; ONE atomic PR per B1)
- **The `is3d` predicate is the single source of truth, shared by worker + compiler:** `is3dModel(model)` (exported from [compile.ts](src/modeler/vpl/compiler/compile.ts)) = `dimension==='3d' && (gridDepth ?? 1) > 1` (a 1-layer 3D model uses the 2D fast path). The worker derives `depth = dimension==='3d' ? max(1,gridDepth) : 1` and gates on `depth > 1` — the SAME predicate, so a hand-edited `dimension:'2d', gridDepth:8` file can't desync the baked/passed `total`.
- **Worker** ([sim.worker.ts](src/simulator/engine/sim.worker.ts)): `total = W*H*D`; `buildNeighborIndices` gains a `layer` loop + reads 3-tuples (`coords3d` when present, the STRIDE staying `coords.length` so every `nIdx[idx*nSz+k]` consumer is 3D-for-free); `cellIndexOf(layer,row,col)` + `inBounds3d` helpers; the `paint`/`paintManual`/`writeRegion`/`clearRegion` handlers carry an optional `layer` (absent → 0, so 2D is byte-identical). **`buildLoopArgs`/`buildCellArgs` push `depth, WH` ONLY when `depth > 1`** (2D arg list unchanged). `computeMemoryLayout` is called with the 3D `total`, so wasmMemory is correctly 3D-sized even on the JS target (the JS step's typed arrays are views over wasmMemory).
- **Compiler** ([compile.ts](src/modeler/vpl/compiler/compile.ts)): `decodeCoordLines(is3d, indent)` emits the per-cell preamble — 3D adds `_layer=(idx/WH)|0; _rem=idx-_layer*WH; _row=(_rem/W)|0; _col=_rem-_row*W;`, 2D stays the verbatim `_row=(idx/W)|0; _col=idx-_row*W;` (byte-identical). Applied at all 5 entry points (async step, sync step, InputColor, OutputMapping, InitEvent). `buildLoopParams`/`buildCellParams`/`omParamParts` add `D, WH` **only when `is3d`** (so 2D signatures are byte-identical — the param-list change does NOT happen in 2D). InitEvent emits `_v<id>_z = _layer; _v<id>_maxZ = D-1;` when 3D.
- **InitEvent z/maxZ ports** ([InitEventNode.ts](src/modeler/vpl/nodes/InitEventNode.ts)): added `z`/`maxZ` integer outputs, `hiddenPorts` hides them in 2D (the compiler emits no `_z`/`_maxZ` decode there). This required extending `NodeTypeDef.hiddenPorts` to `(config, model?) => string[]` — threaded the model at both call sites (CaNode + effectivePorts.getEffectivePorts gained an optional `model` param). `initEvent` is already in `MULTI_OUTPUT_TYPES`, so `varName()` resolves z/maxZ via the `_v<id>_<portId>` convention with no extra registration.
- **`withEffectiveNeighborhoods`** ([SimulatorView.tsx](src/simulator/SimulatorView.tsx)): when a 3D nbr has `includeCentralCell`, appends `[0,0,0]` to `coords3d` AND `[0,0]` to `coords` so the stride invariant holds.
- **`NodeRequirements.lattice2d`** (in [types.ts](src/modeler/vpl/types.ts)) added (PR4 uses it to gate the 2-axis `neighborIndex` family off in 3D; **PR10 un-gated the family** with a 3-axis codec, so no node sets this flag anymore — it remains as generic 2D-only infra).
- **Sample**: [scripts/gen-life3d.mjs](scripts/gen-life3d.mjs) → `public/models/Life3D.gcaproj` — 24³ torus, 26-cell Moore-3D, Bays 5766 (S5-7/B6) via getNeighborsAttribute→aggregate.sum→Compare(between/==)→Logic→setAttribute, InitEvent seeds a randomized central z-slab (uses the `z` port). `useWasm:false` until PR5 ports WASM 3D, then flips to true.
- **Verified**: compiler harness (3D stepCode has the `_layer` decode, `total===W*H*D`; a 2D model's signature has no `D,WH` + verbatim decode → byte-identical); direct compiled-JS-step 0 mismatches vs an independent Bays 5766; and the **real worker** (forced JS) advances generation and matches the independent rule with 0 mismatches over a random fill (validates buildNeighborIndices + the buildLoopArgs↔buildLoopParams ABI).

### 2D parametric neighbourhoods — the same generator, one dimension down (branch `updates`)
PR4's parametric block was 3D-only; a 2D model had the hand-drawing grid (Point/Circle/Ring/Line + symmetry) but no one-click named-shape generator. It now has one, rendered ABOVE the grid — the grid stays the hand-tuning path exactly as the 3D slice editor does. Editor-layer only: zero schema change (the existing `NeighborhoodShapeSpec` covers every 2D shape), zero compiler/worker impact (`shape` is editor metadata nothing else reads).
- **ONE generator, not two** ([neighborhood2d.ts](src/modeler/panels/neighborhood2d.ts)): a 2D shape is EXACTLY the `dl === 0` slice of the same 3D shape — every metric reduces to its 2D form at dl = 0 and the planar `ring`/`disk` kinds already live on the axis-'z' plane — so `generateCoords2d(spec)` = `generateCoords3d(spec).filter(dl===0).map(drop dl)`. One predicate set, one scan order (the 3D layer→row→col scan restricted to layer 0 IS a row→col scan), no drift. A `ring`/`disk` spec is normalized to axis 'z' first (in 2D the grid IS that plane; any other axis would slice the shape to a degenerate line).
- **Five kinds offered** (`SHAPE_KINDS_2D`): `moore` (box L∞) · `vonNeumann` (diamond L1) · `ball` labelled **Disk** (filled disc L2 — at dl = 0 it is identical to the 3D `disk` kind but carries no axis field) · `rangeN` (radius + a metric dropdown) · `ring` (radius + width, the 3D `ring` parameterisation). `shell` is omitted — its 2D slice is an annulus, which `ring` expresses more friendlily.
- **Same two lifecycle rules as 3D**: a regen CLEARS `tags` (keyed by coord INDEX, so every index moves) and leaves `includeCentralCell` alone (a separate flag the generator never touches). A hand edit CLEARS `shape` — but `applyCellsChanges` now does that **only when the coords actually changed** (`toAdd.length || removeKeys.size`), so toggling the CENTRE cell keeps the stored spec (it changes no coord). The panel remounts the form per selection (`key={selected.id}`, the 3D editor's rule) so a stale form can't overwrite neighbourhood B with A's spec.
- **The grid GROWS instead of clamping** (the 3D editor clamps radius to `margin`): `Generate` bumps `margin` to `maxAbsOffset2d(coords)` when the shape reaches past the current grid, so a shape is never generated invisibly; it never shrinks (the user's framing choice). Radius/width cap at 50 = the Margin field's max.
- **⚠ A RING WITH WIDTH ≥ 2 WAS SILENTLY TRUNCATED** (pre-existing, fixed here in the shared `generateCoords3d`): the planar branch scanned only the `±radius` box while the annulus predicate keeps cells out to `radius + width/2`, so e.g. r=3 w=2 dropped `(±4,0)`/`(0,±4)`. The scan bound is now `ceil(r + half)` for `ring`; a `disk` keeps `±r` because its own `dist <= r + 0.5` predicate can never admit a cell at `r + 1`. **Provably no shipped-model change** — the only stored `shape` in the whole library is Life3D's `{moore, r:1}`, and width-1 rings/disks/balls are byte-identical (verified cell-for-cell against unclipped independent references).
- **Verified through the real UI** (dev server, Game of Life + Life3D, 0 console errors on a clean-load full exercise): Moore r1 → the exact 8-cell set (and regenerating Game of Life's own Moore reproduces its shipped coords set, after which the model still compiles and **evolves** on its WebGPU grid target — alive 328@gen28 → 326@gen38); vonNeumann r1 → 4, r2 → 12; Disk r2 → 20 and Ball/Disk r1/2/3/5 all cell-identical to an independent `hypot ≤ r+0.5` reference; Ring r2w1 → 12 and r3w2 → 40, cell-identical to an unclipped independent annulus reference (6 width combinations); Range-N metric switching → 24 / 12 / 20 (cheb/man/euc at r=2) with the metric select hidden for the named kinds; radius 6 auto-grew the grid 5×5 → 13×13 with all 136 cells visible; a tag survived until the next Generate then cleared; a centre toggle KEPT `moore (r=1)` while a cell edit flipped the summary to `custom`; switching between two neighbourhoods reseeded the form to each one's stored spec. **3D untouched**: Life3D still shows the Parametric/Slice toggle, its own 7-shape list, `26 cells · moore (r=1)`, and regenerating still gives exactly 26 — the 2D block is absent there.
- **NB the euclidean convention**: `ball`/`disk` use the shipped 3D half-cell rounding `d <= r + 0.5` (so Disk r2 = 20 cells, a round blob), NOT a strict `d <= r` (which would give 13). Deliberate — changing it would alter 3D output. The 2D drawing TOOL's `annulusCells` uses exact distances; the two conventions coexist as they did before.

### PR6 — WebGPU 3D port (done; lockstep)
- **Layout** ([webgpu/layout.ts](src/modeler/vpl/compiler/webgpu/layout.ts)): `gridDepth` honoured only in a 3D model; `total = W*H*depth`; `WebGPULayout.gridDepth` field. `WebGPULayoutNbr.coords3d?` + the nbr region uses **stride 3** (dRow, dCol, dLayer) in 3D, 2 in 2D (`nbrStride`); `coords3d` falls back to a `dl=0` projection of `coords` for a 2D-only nbr in a 3D model.
- **Encoder** ([webgpu/encoder.ts](src/modeler/vpl/compiler/webgpu/encoder.ts)): `nbrCellIdx` gated on `gd>1` — 3D reads the 3rd offset (`u32(k)*3u + 2u`), decodes `layer=idx/WH; rem; row; col`, wraps/clamps the layer (torus / constant sentinel); 2D emits the verbatim 2-axis helper (byte-identical). (PR6: `nbrCellIdxFromNi` stayed verbatim 2D; **PR10 added its 3D form** — three 10-bit fields resolved via the layer, gated on `gd>1`.) `emitEntryPoint` bound `idx >= ${total}u` is 3D-correct (total = W*H*D).
- **Compiler** ([webgpu/compile.ts](src/modeler/vpl/compiler/webgpu/compile.ts)): only the **InitEvent** decode is 3D-relevant (the 3 row/col sites at 1196/1983/2077 are the variegated facing emitters — 2D-locked, never reached in 3D). - **Runtime** ([webgpuRuntime.ts](src/simulator/engine/webgpuRuntime.ts)): `uploadNeighborOffsets` packs **3 i32/neighbour** when `layout.gridDepth>1` (matches the encoder's `*3u`); 2D packs 2. Dispatch is `Math.ceil(total/64)` — already 3D-correct.

### PR7 — RGBA authorable alpha (done; setCellLooks.a + WebGPU alphaMode)

### PR8 — WebGL2 3D voxel renderer (done)
- **[src/simulator/render/gl3d.ts](src/simulator/render/gl3d.ts)** `Gl3DRenderer`: instanced 36-vertex unit cubes; per-instance `[cellIndex(u32), r, g, b, a(f32)]` (vertex shader decodes x/y/z from the flat index with INTEGER math via `uWu`/`uWHu` uint uniforms); `uploadColors` compacts ONLY alpha>0 cells (never instances the full volume); orbit camera (yaw/pitch/dist/pan → MVP); clip plane = fragment `discard` past a bounded axis cut (PRIMARY see-inside, NOT depth-sort); opt-in per-cell alpha = GL blend + back-to-front instance sort; colour-id `pick()` via a 2nd FBO pass ((idx+1)→full 32-bit RGBA, nearest via depth, 0 = background); `readPixels()` for screenshot/recording. `preserveDrawingBuffer:true`. Tiny self-contained mat4 (perspective/lookAt/mul).
- **≥2²⁴-cell grids: the voxel cell index MUST stay a 32-bit INTEGER end-to-end (fixed bug — "disconnected cells alternating along the column axis from a certain depth")**: the instance buffer's index lane used to be a Float32 (`d[o] = i` + `in float aCellIndex` + f32 shader decode + a 24-bit RGB pick encode). Float32 cannot represent odd integers ≥ 2²⁴ (16,777,216), so on grids past ~16.7M cells (300³ = 27M crosses it at layer ⌊2²⁴/(W·H)⌋ — 186 at 300×300) every odd-indexed voxel rounded onto its even col-neighbour: rendered gaps/doubles alternating along the col axis, and the pick/inspector returned `idx mod 2²⁴` (a wrong, usually-empty cell — the misleading "State: empty" popover). **The SIMULATION was always exact** (f64 JS / i32 WASM / u32 WGSL; verified at gen 230 on the 300³ Accretor: 1,050,289 non-empty cells, 0 without an occupied face-neighbour, 0 colour↔state mismatches) — render-layer only. Fix: `instDataU32` (a Uint32Array view over `instData.buffer`) writes/reads the index lane, `vertexAttribIPointer(2, 1, gl.UNSIGNED_INT, 20, 0)`, `in uint aCellIndex` + uint decode in VS/PICK_VS (uniforms `uWu`/`uWHu` via `uniform1ui` — float uniforms would themselves lose W·H past 2²⁴), PICK_FS encodes (idx+1) across ALL FOUR RGBA bytes (0 = miss), `pick()` decodes 32 bits, and `sortBackToFront` copies records through Uint32 views (bit-exact for the mixed int/float lanes). Verified per-cell-exact pick at idx 26,999,999 + the alpha-blend sort path. **Any new per-instance lane or shader that carries a flat CELL INDEX must use integer attributes/uniforms — never route a cell index through f32** (agent instance data is safe: positions are small floats, pick ids are instance counts).
- **SimulatorView seam**: a sibling `<canvas ref={glCanvasRef}>` (the 2D canvas is `display:none` when 3D). `draw()` (useCallback([]), ~20 call sites) branches FIRST on `is3dRef` and reads camera/clip/alpha/depth via refs (`cam3dRef`/`clip3dRef`/`alpha3dRef`/`gridDepth`). Init/dispose effect on `[is3D]`. Pointer effect on the GL canvas: LMB-drag orbit, wheel zoom, MMB/Shift pan; no-drag LMB = paint the picked voxel (radius-1, via `paint3dRef` → the existing paint flush, which now carries `layer`), Shift+click = inspect (`openInspect3dRef` → `commitInspectPopover`). `gridDepth.current` is set beside `gridWidth/Height.current`. Screenshot + recording read the GL display buffer (display resolution — documented semantics change; the 2D recording branch is now an `else if`, skipped in 3D). 3D controls overlay: Reset view, Clip plane (axis X/Y/Z + slider), Alpha blend. DEV hooks: `window.__sim3dCamera/__sim3dClip/__sim3dPick/__sim3dRenderer/__sim3dRedraw`.
- **WebGPU in 3D** (updated, feedback round 1): WebGPU is now a selectable compile target for 3D. The earlier "force WASM in 3D" was because WebGPU **direct-render** writes to an OffscreenCanvas and skips the CPU colors readback the WebGL renderer needs — so in 3D the canvas-attach was gated OFF (`pendingCanvasAttach` requires `!is3D`), which keeps WebGPU on the **readback** path (colors shipped via `stepped`). Net: WebGPU **compute** runs the simulation, the worker reads colours back each step, and the WebGL2 voxel renderer draws them. Verified: WebGPU-3D Life3D ships 4195 instances + matches Bays 5766 (0 mismatches). ### L1 — worker-side WGSL voxel render (3D grids on the WebGPU target; branch `optimize`)
The 3D grid's **render tax removed**: a 3D volume on the WebGPU target now renders **from the GPU inside the worker** — no per-frame colours readback, no colours `postMessage`, and no main-thread `uploadColors` rescan. Measured on the shipped **Accretor 300³ (27M cells)**, interleaved A/B on one machine at gens/frame = 1: **753 → 123 ms per worker frame (≈ 6.2×)**, with the fixed per-frame cost (`count: 0`) **860 → 8.7 ms**, *plus* the main thread's per-frame O(total) instance rescan (~55–220 ms at 300³) and 103 MB/frame of traffic gone entirely. Master runbook: [docs/HANDOFF_LATTICE_GPU.md](docs/HANDOFF_LATTICE_GPU.md); phase doc + Completion Report: [docs/HANDOFF_LATTICE_GPU_L1.md](docs/HANDOFF_LATTICE_GPU_L1.md). **This is the lattice twin of the agent Phase C** (the layering, the free/frame flip, the camera message and the shared camera/lighting helpers are the same seam) and it is **render-only: ZERO compiler changes** — `check-compile-identity` reports all 25 library models byte-identical on every surface.
- **The pass** ([webgpuRuntime.ts](src/simulator/engine/webgpuRuntime.ts) `setupVoxelRender` / `presentVoxels` / `destroyVoxelRender`, one encoder + one submit): a **compaction compute pass** over `total` cells (via `dispatchCells` — the 2-D tiling helper is REQUIRED; a flat 1-D dispatch silently no-ops past 4.19M cells, exactly the 3D regime) reads `colorsBuf`'s alpha, applies the **buried-cell cull** under gl3d's own eligibility rule, and `atomicAdd`s an instance counter that IS slot 1 of the **indirect draw args** — so the CPU never learns the count. Then an **indirect** instanced draw of 36-vertex unit cubes. The instance buffer is sized `total × 4` (the worst case) so no capacity readback is ever needed; it is size-checked against `maxStorageBufferBindingSize` and a failure falls back cleanly to today's path. The cube's 36 vertices are generated **procedurally** in the VS (no `const`/`var<private>` array — a per-invocation array would burn private memory per vertex thread, the `AGENT_GPU_ARRAY_CAP` lesson) with CCW-outward winding, so backface culling is valid; two draw pipelines differ only in `cullMode` and are picked per frame exactly like gl3d (cull unless a clip interval is open).
- **Parity with gl3d is by construction**: the same Z-up remap (col→+X, row→−Y, layer→−Z), the same `ambient + diffuse·n·L` + Blinn-Phong specular, the same clip interval, the same cube scale (cell gaps), the same alpha pass-through, and the **MVP + light direction are computed on the MAIN thread by the SHARED `sceneCameraMatrices` / `lightWorldDirFor`** helpers gl3d itself uses (exported by Phase C) — the two renderers cannot disagree on projection or lighting. The cell index is decoded with **integer math** end-to-end (u32 attribute + u32 uniforms; 27M > 2²⁴ — see the f32-index bug above).
- **Scene-anchored wireframes (bounds box / floor grid / origin axes) are drawn in the voxel renderer, depth-tested against the cubes — the free-mode occlusion fix** ([HANDOFF_VOXEL_OVERLAY_DEPTH.md](docs/HANDOFF_VOXEL_OVERLAY_DEPTH.md)). Free mode is a TWO-CANVAS split (voxel canvas z-index 1, gl3d's transparent `overlaysOnly` canvas z-index 2 ON TOP), so anything gl3d drew in the `overlaysOnly` branch composited ABOVE the voxels — the bounds/grid/axes could never be occluded by voxels between them and the camera (they always drew in front; frame mode was fine — one canvas, one depth buffer). Fix: `presentVoxels` runs a small WGSL **LINE pipeline** (`VOXEL_LINE_WGSL`, `pos+colour` vertex attrs, line-list, depth-test + depth-write ON, `depthCompare:'less'`) in the SAME render pass + `depth24plus` attachment as the cube draw, so voxels in front occlude the wireframe and it's visible where nothing intervenes. The line VS **reuses the `VoxelView` uniform's `mvp` (@0) — NO new uniform, NO VoxelView widening** (so `verify-render-uniform-layouts.mjs` stays green; a separate line uniform buffer was the fallback but proved unnecessary). Geometry comes from **`buildSceneWireframeVerts` in [sceneWireframe.ts](src/simulator/engine/sceneWireframe.ts)** — the SHARED builder (it started life here as `buildVoxelOverlayVerts` and moved out when the agent-sphere free mode gained its own line pass; **the voxel pass, the sphere pass and gl3d's `renderOverlays` all derive from that one function**, so no two of them can draw different lines). It mirrors `renderOverlays` byte-for-byte (same colours, same `>100-cell` grid step, same origin-corner axes with 2-pronged arrowheads); cached by a `${axes}${grid}${bounds}|W|H|D` signature and rebuilt only on change. **NB the voxel line VS needs NO clip-z remap** (its cubes use rasterizer depth too) — the agent sphere pass writes `frag_depth` and therefore does; see the Phase C section. The `Viz3D` axes/grid/bounds toggles are threaded via a new **`setGridViz`** worker message (mirroring `setGridCamera`; module var `gridViz3d`, re-applied on `attachVoxelCanvas` + `refreshGridDisplay`; `postGridViz` on the main thread posts on the `voxelRenderStatus` ack + whenever `viz3d` changes). **gl3d's `overlaysOnly` branch SKIPS this geometry** (the `sceneExternal` guard now covers `renderOverlays()` AND `renderBrushPlane()` — see "The brush plane is depth-tested on every path") so it isn't double-drawn; everything else gl3d draws in free mode stays ON TOP as always-visible CURSOR/UI (gizmo, brush footprint outline, hover cells, axis labels). **gl3d's FRAME-mode path is UNCHANGED** — it still draws bounds/grid/axes with correct depth (one canvas), so a 3D WASM model (Life3D, always gl3d frame-mode) and the free↔frame flip are visually identical. Render-only, ZERO compiler changes (`git diff --stat` = webgpuRuntime.ts + sim.worker.ts + SimulatorView.tsx + gl3d.ts). - **Post-ship regression fix #2 (2026-07-24) — free mode never displayed ANYTHING, and the ONE uniform-layout rule that follows.** Reported on the shipped Accretor 300³ (WebGPU, G/F 1): the voxel canvas rendered nothing, ever. **Root cause: the `VoxelView` WGSL struct and `uploadVoxelView` are two independent declarations of one byte layout, and they drifted.** `vec3<f32>` has align 16 but **SIZE 12**, and WGSL's rule is `offset(m) = roundUp(align(m), offset(prev) + size(prev))` — so the `ambient : f32` following `clipFwd : vec3<f32>` landed at byte **124**, inside clipFwd's trailing pad, while the writer wrote the scalar block from **128**. Every scalar shifted one float: **`cubeScale` read the SPECULAR slot (0 by default) ⇒ `local * cubeScale` collapsed all 36 vertices of every cube onto the cell centre ⇒ zero-area triangles ⇒ zero rasterised pixels** (and `clipEnabled` read garbage, which is why opening the clip interval didn't help). **Fix: `@align(16) ambient` pins the block back to 128, making the existing writer exactly correct** (one token; both sides now carry `// @byte` annotations). **Why every probe said it was healthy — the trap to remember:** `bg` is a `vec4`, whose 16-byte alignment RE-SYNCS the layout, so `gridW`/`gridWH`/`total`/`cullBuried` were read correctly — and those are the ONLY members the COMPACTION shader touches. Guarded permanently by the COMPUTED [scripts/verify-render-uniform-layouts.mjs](scripts/verify-render-uniform-layouts.mjs) — it implements the WGSL layout rules (incl. `@align`/`@size`), parses each registered struct + its writer's index assignments, and asserts **no write lands in padding** and **no member byte is left unwritten** (name-independent, so `half` ↔ `halfX/Y/Z` needs no mapping; registered: `VoxelView`, `RenderView3D`, `RenderView`; negative-controlled against all three mutation shapes). **Any new WGSL uniform struct filled by a hand-written TypedArray writer MUST be added to its REGISTRY.** `verify-agent-render.mjs` gained a **B10** block pinning the voxel attach wiring (presented canvas IS the DOM-attached element; the ack force-posts the camera past the dedup key; `presentVoxels` re-acquires the swap-chain texture each frame). A re-attach in FREE mode therefore stranded the mirror at ON while the worker sat at OFF, and the driver's `if (!gridUiSyncPostedRef.current)` guard then suppressed **every** later ON post; because the stuck value is ON, no OFF transition could resync it either, so the moment `want` turned true inside the ~300 ms window the desync became **permanent**. Pinned by the **B11** block in [scripts/verify-agent-render.mjs](scripts/verify-agent-render.mjs) (11 checks over both drivers; 10-mutation negative control, all caught). Full write-up: [HANDOFF_LATTICE_GPU_L1.md](docs/HANDOFF_LATTICE_GPU_L1.md) §11.

### 3D perf — occlusion round (backface cull + buried-cell cull, cells only)
Two render-layer occlusion cuts in [gl3d.ts](src/simulator/render/gl3d.ts), both **provably image-identical in the modes they run in** and auto-disabled (with an internal re-compaction) in the modes where interiors are legitimately visible. Zero compiler / worker / schema / 2D impact; agents (spheres/sprites/metaballs) are untouched.
- **Backface culling (voxel cube passes)**: each cube is a closed convex solid with consistent CCW-outward winding (verified per-face via cross products on `CUBE`), so its backfaces are never visible while it renders closed + opaque — `gl.CULL_FACE` halves rasterized cube fragments for free. Scoped strictly around the three cube instanced draws (display / pick / shadow-map) and disabled after each, so the sphere/sprite/line/metaball passes never see it. Gates: the pick + shadow passes cull iff **no clip** (a straddling cube's surviving fragment at a cut can be a backface); the DISPLAY pass culls when **`alphaBlend || !clip.enabled`** — under ALPHA BLEND culling is always ON and is a **CORRECTNESS requirement, not an optimization**: with `depthMask(false)` every triangle blends in BUFFER order, so an uncculled translucent cube composites its dark backfaces over/under its front faces in an order unrelated to depth — incoherent per-cube colour + doubled opacity (the reported "cubes look just weird" with alive alpha 100 on Life3D). Culled, a convex cube contributes only its front faces (which never overlap in screen space) and the per-cube back-to-front sort gives correct Option-A ordering — translucent volumes read as coherent glass voxels with depth-accumulating opacity. Kept ON under blend even when clipped (see-through anyway; the blend-order argument still applies).
- **Buried-cell culling (`uploadColors`)**: a cell with all **6 face-neighbours filled** is dropped from the instance buffer — a ray's first hit on a union of FLUSH opaque cubes always lands on a face whose adjacent cell is empty, so a fully-enclosed cell can never be the visible surface (a dense volume collapses to its shell; a solid 10³ block instances 488 not 1000). Eligibility (`buriedCullEligible`) = **cell gaps OFF** (`cubeScale ≥ 1` — with the 0.92 gapped look the crack planes between cubes expose interior side faces at grazing angles, so gaps-ON never culls) AND **no alpha blend** AND **no clip interval**. Boundary cells never reach cnt 6 (bounds guards), so the volume's outer faces always render; the render never wraps the lattice, so torus is irrelevant. The 6-neighbour scan is SHARED with occupancy AO (`needNbr = aoOn || cullBuried`); when neither runs, the upload path is byte-identical to the historical scan. **`instanceCount` is therefore ≤ the alive count when buried culling ran** (older "instanceCount = alive-cell count" notes assume gaps ON / ineligibility).
- **Eligibility flips re-compact INTERNALLY**: `uploadColors` stashes `lastColors`/`lastTotal` **by reference** (the worker hands a fresh buffer per step, never mutates in place — the same identity contract as SimulatorView's upload gate), and `setAlphaBlend`/`setClipPlane`/`setCellGaps` call `refreshVoxelsIfCullingChanged()` — a cheap bool compare per frame that re-runs `uploadColors` from the stash only when `buriedCullApplied !== buriedCullEligible()`. So toggling the clip open immediately restores the buried cells (the cut shows a full interior, not a hollow shell) with no SimulatorView round-trip. **`clearVoxels()`** (new) zeroes `instanceCount` AND drops the stash — SimulatorView's agents-only/no-colours branch calls it instead of writing `r.instanceCount = 0`, so a later eligibility flip can't resurrect a previous model's grid from stale colours; `refreshVoxelsIfCullingChanged` is additionally guarded on `instanceCount > 0` as defence-in-depth.

### 3D depth precision — bonds no longer draw in front of agents (branch `updates`)

User report: *"In 3D, bonds (edges), when zoomed out, end up being drawn in front of all agents … extremely hard to visualize when the model has many bonds."* Render-layer only — **`check-compile-identity`: 29 models byte-identical on every surface**; nothing in the worker, the engine or any compiler was touched (`git diff --stat` = [gl3d.ts](src/simulator/render/gl3d.ts) + the new harness).

**ROOT CAUSE — the near plane was a FIXED 0.05, so the depth buffer's world resolution collapsed as you zoomed out.** A bond is a LINE between two agent CENTRES; an agent is a sphere impostor whose FS writes its FRONT SURFACE depth. Bonds draw FIRST (`render()`), so the only margin a sphere has to cover a bond is its own `radius`. A perspective depth buffer's world-space quantum is `Δz ≈ z²/(near·2²⁴)`, so with a fixed `near` it grows with the SQUARE of the camera distance and overtakes the agent radius at

> `dist ≈ sqrt(radius · 2²⁴ · near) / maxGridDim`

— **≈5.8 for the shipped 200³ 3D Tissue, and ≈1.3 for a 600-unit Graph-Rewriting world with 0.7-unit nodes, i.e. TIGHTER THAN THE DEFAULT ZOOM.** Past it the sphere's front surface and the bond quantize into the SAME 24-bit bucket, GL_LESS rejects the sphere, and the bond mesh punches through every agent. **Measured through the real renderer on the shipped 3D Tissue** (1635 agents / 7659 bonds): agent ink lost to bonds **0.1% at dist 1 → 4.7% at dist 5 → 34.4% at dist 8**; on a GRA-shaped lattice (600³ world, 0.7 nodes, 1344 bonds) **60% at dist 1 → 90% at dist 1.9**. There is no error and no wrong-looking buffer — only pixels.

**THE FIX — three layers, in order of impact.**
1. **`sceneNearPlane(r, W, H, D, target, forward)`** (gl3d.ts, exported) makes the near plane ADAPTIVE — a quarter of the clearance between the eye and the nearest thing we draw, floored at the historical `MIN_NEAR_PLANE` (0.05) when the camera is inside the scene. It feeds the SHARED `sceneCameraMatrices`, so the WebGL renderer and BOTH worker WGSL free-mode paths move together and can never disagree. Quantum at dist 1.9 on the 3D Tissue: **0.172 → 1.7e-4 world units (~1000×)**.
   - **THE 0.25 FACTOR IS LOAD-BEARING, not a taste knob.** The WGSL passes feed this GL-convention matrix straight into WebGPU, whose clip volume keeps only `z_clip ∈ [0, w]` — it discards everything closer than the `z_ndc = 0` plane at `2fn/(f+n) ≈ 2·near`. A quarter of the clearance puts that plane at ~half the distance to the nearest geometry, a 2× margin. **Never raise it past 0.5 without also remapping z in every WGSL vertex shader.**
   - **`sceneReachTowardCamera` uses the box's exact SUPPORT along the view axis** (`Σ half_i·|forward_i|`), not the half-diagonal — a 600³ cube seen down an axis reaches 300, not 520, which is what keeps the adaptive plane engaged at close zoom. Padded by the overlays' `ext` (must match renderOverlays / renderAxisLabels / the worker's `buildVoxelOverlayVerts`) and by `|target|` for panning.
2. **The agent-surface passes compare LEQUAL** (`beginSurfaceDepth`/`endSurfaceDepth`, wrapping the sphere, metaball and sprite draws), so a residual quantized tie resolves toward the SURFACE. Sound because the window-depth mapping is strictly increasing in eye distance: a genuinely nearer point can never land in a larger bucket, so `bucket(sphereFront) ≤ bucket(bondPoint)` ALWAYS. **Scoped and restored** — left on globally, the BOND pass (which draws after the voxels) would win ties against the CA-grid cubes and bleed through the volume.
3. **Bonds now meet the agent SURFACE, not its centre** (`uploadAgents` trims each end by that agent's radius, clamped to 45% per side so an overlapping pair can't invert). GL rasterises a line at a MINIMUM of one pixel however far away it is while an agent's disc shrinks with distance, so a centre-to-centre bond covers its own endpoints outright once an agent is a pixel or two across — ink that is geometrically ON the agent, which no depth fix can reach. Also simply the correct ball-and-stick geometry.

**Measured after** (same models, true before/after with the old projection reconstructed in-page): 3D Tissue **34.4% → 0.5% at dist 8** (70×) and **4.7% → 0.5% at dist 5**, flat across the whole zoom range instead of exploding; GRA lattice **90.1% → 54.2% at dist 1.9**. The GRA residual is the honest floor — at that zoom each node is under a pixel while 1344 one-pixel bonds cross it, so there is genuinely more line ink than node ink (zoom in, or use the Show-bonds toggle).

#### Global lighting — cast shadows + occlusion AO (opt-in; branch `sim_agent_fixes`)
Two opt-in "global lighting" toggles so cells/agents shade EACH OTHER instead of each surface being lit only by its own normal (the reported "each cell/agent is independently lit" flatness). Both DEFAULT OFF → **byte-identical to the historical shade** (verified: off = exact baseline luminance; strength 0 == off). Render-layer only ([gl3d.ts](src/simulator/render/gl3d.ts) + the [SimulatorView.tsx](src/simulator/SimulatorView.tsx) Lighting panel) — zero compiler/worker/schema impact; 2D untouched. `Light3D` gained `{ shadows, shadowStrength, ao, aoStrength }` (defaults false/0.6/false/0.7; `sanitizeLight3d` clamps them; persisted in `genesisca_sim_settings.light3d`).
- **Cast shadows (shadow map)** — voxels + agents both CAST and RECEIVE. A depth-only pass renders the cubes + agent sphere impostors from the light's ORTHO POV into a `DEPTH_COMPONENT24` `sampler2DShadow` texture (`renderShadowMap`, first in `render()`, no-op when off); the voxel + sphere FS PCF-sample it (shared `SHADOW_GLSL` `shadowFactor(fragWorld, ndl)` — 3×3 taps over hardware-2×2 compare) to attenuate the diffuse+specular. **The light matrix** (`computeLightMVP`) fits the volume's bounding SPHERE (radius R from the origin-centred world), eye at `2R·L`, ortho `±R`, near/far `0.5R/3.5R` — stable at ANY light angle; up-vector degeneracy guarded (`|L.z|>0.99 → [0,1,0]`). **Two dedicated depth programs**: `CUBE_SHADOW_VS/FS` (decodes the cell centre EXACTLY like the main VS — col→+X/row→-Y/layer→-Z) and `SPHERE_SHADOW_VS/FS` (a LIGHT-facing billboard — axes ⟂ L via cross products — raycast to the light-facing sphere hemisphere + `gl_FragDepth`). Both clip-aware (a clipped-open view's interior is lit as if the removed shell weren't casting). **Scale-relative bias** `uShadowBias = 0.9/(3R)` (a ≈1-cell world bias mapped into the light's [0,1] depth range) + slope term — avoids acne on small grids AND peter-panning on huge ones. `SHADOW_SIZE=2048`, on `SHADOW_TEX_UNIT=1`; a 1×1 dummy depth-compare texture (`ensureDummyShadowTex`) is ALWAYS bound to unit 1 so the `sampler2DShadow` stays valid when shadows are off (the FS branches out on `uShadowEnabled=0`). Depth-only FBO completeness is checked → `shadowUnsupported` quietly disables shadows on a driver that can't do it. `sampler2DShadow` needs an explicit `precision highp sampler2DShadow;` in GLSL ES 3.00 (the compile error that first surfaced).
- **Ambient occlusion (voxel occupancy)** — each cell is darkened by how many of its 6 face-neighbours are filled (crevices/interiors → darker), computed in `uploadColors` INSIDE the existing per-step cell scan (an incremental `(col,row,layer)` walk + 6 bounded neighbour alpha reads, ONLY when AO is on — the off path stays as cheap as before). Stored in a PARALLEL `aoBuf` (attrib 4 on the cube VAO; the pick/shadow cube programs don't declare it → ignored) and applied to the AMBIENT term (`uAmbient*(1 - aoStrength*vAO)`), so shadows own the diffuse and AO owns the ambient. `sortBackToFront` reorders `aoData` in step with the alpha-blend instance reorder. `aoBuf` is kept finite across every off→on→off + capacity-grow path (grow allocates zeros; on = refresh; off+no-grow = skip, ×0 in the FS). Because AO is BAKED at upload, toggling it forces a re-upload (`prevAoRef` resets `lastUploadedColors3dRef` in the light3d effect — colours are unchanged so `draw()` would otherwise skip `uploadColors`). Agents get their "no longer independently lit" from the cast shadows, not occupancy AO (spheres already read as 3D; a screen-space / agent-cluster AO is a possible follow-up).
- **UI**: two rows (Shadows / Occlusion) in the 3D-View Lighting panel — a checkbox + a strength slider each (dimmed when off), below the View/World mode buttons. **The Occlusion row is gated on `gridCellsOn`** (hidden for an agents-only model, like Cell gaps): occupancy AO is computed from CELL face-neighbours in `uploadColors`, so it does nothing for agents — Shadows stays (agents cast + receive).
- **Verified on the GPU (readPixels luminance; screenshots time out on this heavy page)**: all shaders compile + the renderer inits; AO on darkens Life3D meanLum 97.82→85.57 (same pixel count) and off restores EXACTLY 97.82; shadows scale with strength (97.82 → 95.09 @0.6 → 93.32 @1.0) and off restores 97.82; a 200-agent dense cluster receives shadows (scales 0→1); zero console errors throughout. tsc + `npm run build` clean. (The planned adversarial-review workflow's agents hit the session limit — replaced by a manual adversarial self-review across the same dimensions; no defects.)

#### Agent Metaballs — implicit-surface agent rendering, 2D + 3D (opt-in; branch `sim_agent_fixes`)
Render the agent population as a **fused implicit surface** (Blender-metaball semantics) instead of discrete circles / sphere impostors — each agent contributes a Wyvill falloff `w = (1 − (d/R)²)³` over `R = influence · radius`, the fields SUM, and the surface is the isosurface at `threshold`, so overlapping agents bulge toward each other and MERGE (the natural look for tissues/morphogenesis). **Purely a RENDER mode** — picking/brushing/inspect (the sphere pick FBO), bonds, physics, engine, compilers, schema all untouched; sprite-agents are EXCLUDED from the field and keep drawing as billboards on top. Plan + deviations: [docs/PLAN_AGENT_METABALLS.md](docs/PLAN_AGENT_METABALLS.md) (+ `.html` mockup). DEFAULT OFF → byte-identical baseline (verified: off = exact sphere lit-pixel counts).
- **Config**: `Metaballs3D { enabled, influence 1–3, threshold 0.02–0.9, resolution 1|2|4 }` + `DEFAULT_METABALLS3D` + **`metaballAutoThreshold(influence) = (1 − 1/influence²)³`** — the threshold at which a LONE agent renders at EXACTLY its own sphere radius (verified pixel-exact: 585 = 585 px) — all exported from [gl3d.ts](src/simulator/render/gl3d.ts). ONE shared, persisted user setting (`genesisca_sim_settings.agentMetaballs`, state `agentMetaballs` + `sanitizeAgentMetaballs` in [SimulatorView.tsx](src/simulator/SimulatorView.tsx)) drives BOTH the 3D and 2D views. UI: a **Metaballs** block in the 3D View panel (checkbox + Influence/Threshold sliders + a ⟲ auto-threshold button + a 1×/2×/4× Detail control, agent models only) and a **Metaballs** block in the 2D agent common-controls ("Fuse agents into blobs" + the two sliders).
- **3D = bake a density field into a 3D texture, then raymarch it** ([gl3d.ts](src/simulator/render/gl3d.ts) `bakeMetaballField`/`renderMetaballs` + `META_VS`/`META_FS`): the CPU splat reads the **packed `agentInstData`** (already alive-compacted, colours 0..1, and sprite-agents flagged by a NEGATIVE radius — NB the SNAPSHOT's radius is always positive, so a snapshot-based bake would misclassify sprites) into an RGBA8 `TEXTURE_3D` over the agents' influence bbox (A = Σw/`META_F_MAX`(2.0), RGB = density-weighted colour → colours blend smoothly across fused tissue); the fullscreen-quad FS reconstructs the world ray from `inv(MVP)`, slab-tests the field box, marches (≤512 steps, half-voxel step) to the first threshold crossing, bisects ×5, shades with the SAME lighting model incl. `shadowFactor()` (the blob RECEIVES cast shadows; the sphere casters approximate the blob's own shadow), and writes `gl_FragDepth` with the SPHERE_FS formula so it depth-interleaves with voxels/bonds/sprites. Clip interval reads as density-0 → the blob is cut OPEN (matching the voxel cut). **The bake is LAZY on a `metaDirty` flag** (set by `setMetaballs` param changes / `uploadAgents` / `clearAgents`) — camera-only frames re-render without re-baking (measured 0.3 ms vs 9–37 ms bakes at 1500 agents); NO SimulatorView snapshot invalidation needed. **Field cap** ~2M voxels (`META_MAX_VOXELS`, ≈128³) with a CONTINUOUS per-axis effective resolution; **torus worlds bake the FULL world with modulo-wrapped splats** (verified: a seam-hugging agent's blob renders on both sides). **The mirroring gotcha**: `uFieldA`/`uFieldB` are the SIGNED world coords of the field's cell-min/cell-max corners — NOT a numeric min/max (the Z-up remap negates row/layer; per-axis `(p−A)/(B−A)` with a negative span is exactly what keeps the texture un-mirrored, and the slab test is order-robust). Texture unit **2** (0 = sprite atlas, 1 = shadow map), bound AFTER `setLightUniforms` (which resets the active unit to 0).
- **2D = an approximate "gooey" filter** ([SimulatorView.tsx](src/simulator/SimulatorView.tsx) `drawAgentsOverlay` + `ensureGooFilter`): non-sprite agent discs draw into an offscreen scratch (`gooScratchRef`, drawn-to only — never `getImageData`'d), then ONE blit through `ctx.filter = 'url(#genesisca-agent-goo)'` — an injected SVG filter of feGaussianBlur (σ = `(influence−1)·avgRadPx·0.85`) + a steep feColorMatrix alpha threshold. **The threshold is anchored to the blurred-disc PEAK alpha** (`1 − exp(−r²/2σ²)`) — without this, lone agents VANISH at high influence because blur flattens their peak below a fixed threshold (found in verification); with it, fusion is monotonic in influence (verified: 5 discs → 1 blob) and the full threshold range stays usable. Sprite-agents draw normally on top (a second `'sprites'` stamp pass); falls back to plain circles when `ctx.filter` is unsupported. `ensureGooFilter` ADOPTS an existing `#genesisca-agent-goo` element by id before creating one — a re-evaluated module (Vite HMR) must not append a duplicate id, since `url(#…)` resolves the FIRST match and the duplicate's params would never reach the canvas (a real debugging trap hit during verification).
- **Verification recipe** (screenshots time out on the 3D page — use `readPixels` via `window.__sim3dRenderer()` + direct `r.setMetaballs(...); r.render()` calls, and count connected components of the lit mask WITH OVERLAYS OFF — the bounds box/gizmo lines otherwise contaminate the component count): off = exact baseline; influence sweep monotonic; threshold monotonic; comps drop to 1 on fusion; pick id identical on/off.
