## Agent Capability Profiles (branch `absorb_old_automatosgt`)

Decompose the monolithic agent engine into **opt-in capability modules** so a model declares only the capabilities it needs and its EDITOR SURFACE (palette nodes, Behaviour-Step ports, agent Edit-panel rows, inspector fields) shows only its paradigm's machinery — a social-graph or particle author never sees morphogenesis nodes. Universality by **composition**, not by piling every feature onto one fixed agent. Spec/audit trail: [docs/HANDOFF_AGENT_CAPABILITY_PROFILES.md](docs/HANDOFF_AGENT_CAPABILITY_PROFILES.md) (authoritative) + [PLAN](docs/PLAN_AGENT_CAPABILITY_PROFILES.md) + [ANALYSIS](docs/ANALYSIS_AUTOMATOSGT_AGENTS.md). **STEP 0 + STEP 1 shipped (the entire clarity win, editor-surface); STEP 3 (Bonds SoA gate) + the physics-capability ENGINE wiring (Collision / Bonds=Physics / Growth now gate real engine behaviour — the honest-controls pass) shipped on top, all byte-identical for existing files; the remaining SoA memory-compute gating (STEP 4/6) + net-new STEP 5 nodes are the secondary win.**

### The honest core (always allocated) + the gate-able capabilities
- **Core (never SoA-gated before the deferred STEP 6):** the slot **id** (= the array index) + `alive` + `colors` + position (`x,y[,z]` + the `Next` double-buffer) + velocity (`vx,vy[,vz]`) + force (`forceX,forceY[,forceZ]`) + `radius` + the always-on i32 reductions `lineage`/`epoch`/`bondCount` + the user's agent attributes. **Motion & Body are always-allocated in v1** (there is no `Static` integrator path yet) — their toggle is a palette/port gate only; SoA-gating them is the deferred XL STEP 6.
- **Capabilities (gate-able on top of core):** Motion (static/velocity/force), Body, Collision (off/**soft**=springy repulsion force / **positional**=rigid no-overlap constraint — two GENUINELY different models), Bonds (off/data/physics), Auto-bond, Growth, Division, Lifespan, Population (birth/death), Sensing, Orientation, Field coupling, Appearance. **The PHYSICS capabilities (Collision / Bonds=Physics / Growth) now drive the ENGINE, not just the editor surface** — see "Physics-capability engine wiring" + "Positional (hard) collision" below.

### The profile is the single source of truth ([src/model/agentCapabilities.ts](src/model/agentCapabilities.ts))
- **Schema** ([types.ts](src/model/types.ts)): `AgentCapabilities` + `MotionMode`/`CollisionMode`/`BondsMode`; `CenterBasedConfig.agentCapabilities?` (additive — absent ⇒ inferred).
- **7 presets** (`AGENT_PRESETS`): Particle · Boids · Vivarium · Morphogenesis · Social Graph · CA-on-Agents. `Full ≡ Morphogenesis` (deep-equal — a STEP 1 gate). `matchAgentPreset` flips to `'custom'` on any edit that stops matching.
- **Mode-aware dependency closure** (`computeCapabilityClosure`): auto-enables hard deps (Collision=soft ⇒ Body + Motion=Force; Bonds=physics ⇒ Motion=Force; Growth/Division ⇒ Body; Auto-bond ⇒ Bonds=physics; Population.Birth ⇒ Motion). `applyCapabilityEdit` ALSO cascades REMOVALS (Body off ⇒ drop Growth/Division/Collision; Motion below Force ⇒ demote physics bonds / soft collision).
- **Node→capability requirement table** (`AGENT_NODE_REQUIREMENT`, `nodeSatisfiesCapabilities`): the ONE source consumed by BOTH the palette gate AND the migration widening. A node not listed is core/universal (Behaviour Step, Get Self Position, Get Agent Attribute-by-id, the array-tier plumbing) — always available when Agents is on. Only nodes that should VANISH when their capability is off are listed (Divide Agent→division, Apply Force→motion=force, Get Radius→body, Form Bond/For Each Bond→bonds, Secrete To Field→fieldCoupling, …).
- **Usage-widened migration** (`inferAgentProfile` / `migrateAgentCapabilities`, wired into LOAD_MODEL + `migrateForHarness`): **minimal base + engine-physics signal (`usesBondingPhysics` ⇒ collision/body/force, `autoBond` ⇒ physics bonds) + node-usage widen + Body-for-any-moving-model, then closure.** **DELIBERATE DEVIATION from the handoff's config-base-Full** — this is provably safe (the widen uses the SAME requirement table as the gate, so it can NEVER hide a node the graph uses) AND honest/tight (a maxBonds>0 model that never touches bonds no longer shows the whole morphogenesis palette). Verified: shipped Boids infers `motion/body/sensing` only; Tissue infers full physics+division. A fresh Agents-topology enable seeds the friendly `defaultAgentCapabilities()` = Boids.
- **Footprint estimate** (`estimateAgentFootprint`): the per-agent byte readout enumerating the SAME field groups STEP 3's profile-driven `computeAgentMemoryLayout` will gate (v1 is a display-only what-if — the engine still allocates the full struct).

### The three enforcement gates (all read the resolved profile)
1. **Palette** ([nodeValidation.ts](src/modeler/vpl/nodes/nodeValidation.ts) `isNodeAvailable`): hides a capability-off node from palette / quick-add / connection-drop (within the existing `bondGraph`+Agents-graph branch).
2. **Badge** (`detectCapabilityRequirements` → CaNode amber `!`): INFORMATIONAL in v1 (the compiler still emits unconditionally, so a placed violator keeps working; the badge guides the user). Covers macro internals via `countMacroSubgraphIssues`. Becomes BLOCKING from STEP 3.
3. **Ports/rows**: `BehaviourStepNode` `hiddenPorts` hides Radius/Area (Body) · Bond Degree (Bonds) · Age (Lifespan); the Properties [AgentCapabilitiesSection.tsx](src/modeler/panels/AgentCapabilitiesSection.tsx) preset picker + toggles + live footprint; SimulatorView's `agentEditPanelAttrs` + the inspector popover filter geometry rows to enabled capabilities.

### STEP 0 — shared layout-agnostic ABI descriptor ([src/modeler/vpl/compiler/agentAbi.ts](src/modeler/vpl/compiler/agentAbi.ts))
The three CPU-side agent-ABI mirrors (compile.ts `buildAgentLoopParams`/`buildDivisionParams`/`buildAgentInitParams` NAME strings, the worker's `buildAgentLoopArgs`/`buildDivisionArgs`/`buildAgentInitArgs` VALUE arrays, the parity harness `buildArgs`) now ALL derive from ONE source — `deriveAgentAbi(kind, shape[, profile])`. Each field bundles its param NAME + a `get(store, rt)` value resolver, so name and value are defined together and the four sites **cannot desync in order** (the "3D dimsModel/total" desync class). The descriptor takes a lightweight `AgentAbiShape` (primitives — `is3d`/`agentAttrs`/`fieldAttrs`/`hasLookupTables`) so the worker (which keeps no model) derives it from its own state (`agentAbiShapeOfStore` + `agentAbiBaseRt`). `buildAgentAbiParams` (names) + `buildAgentAbiArgs` (values, used by BOTH worker + harness). An optional per-field `gate(profile)` is wired but a **no-op in STEP 0** — the descriptor is currently profile-unaware, so the output is byte-identical to the pre-refactor mirrors (this is the prerequisite that makes STEP 3+ field gating a one-place change). `is3dModelLike` (niCodec) — NOT `is3dModel` (compile.ts) — avoids a circular import.

### STEP 3 — first real SoA gate: Bonds (SHIPPED)
The Bonds capability is AUTHORITATIVE for the ragged bond store. `resolveMaxBonds` ([centerBased.ts](src/model/centerBased.ts)) is profile-aware — `bonds === 'off'` ⇒ **0** regardless of the config's `maxBonds` ceiling, riding the already-tested maxBonds=0 code path (pure-force models). So a Boids/Chemotaxis/Ant model that never forms bonds no longer pays `28·maxBonds·maxAgents` for a store it never touches (~112 KB at 2000 agents), while a bonded tissue keeps its store. **Byte-identical output** for any bond-free model (the compiled per-agent code loops `b < bondCount[idx]` = 0 and never indexes the 0-length store). The GPU layout's maxBonds now also goes through `resolveMaxBonds` (was a direct read — the desync fix); the auto-bond scan is gated on `s.maxBonds > 0`; the load-state stride check (M1) rejects a mismatch only when the saved state HAS bonds. `scripts/test-bonds-allocation.mjs` asserts it. Verified: parity 0 mismatches; Boids on WebGPU (resolvedTarget=webgpu, effMaxBonds=0) flocks 0.999. Field coupling needs no SoA change (agentAccess already prunes the `_field_` signature). **The badge stays INFORMATIONAL** (a placed capability-off node still compiles as a no-op — making it blocking would error a leftover node that would work if the capability were re-enabled).

### STEP 5 — Get Age + Get Agents In View + Sense Hemifield (SHIPPED); Spawn / Orientation remaining
**Get Age** ([GetAgeNode.ts](src/modeler/vpl/nodes/GetAgeNode.ts)) is the Lifespan capability's palette node — reads `_agentAge[idx]` (a byte-clone of Get Radius; JS + WASM + WebGPU emitters, `NEVER_INVARIANT` + `NEVER_PURE`).

**Get Agents In View** (STEP 5b — [GetAgentsInViewNode.ts](src/modeler/vpl/nodes/GetAgentsInViewNode.ts)) is the directional-FOV node — the array of nearby agents inside a heading-relative **vision cone** (the Sensing capability's second node; it un-hid the Sensing FOV description). **Zero new SoA/ABI:** the cone test rides the SAME 3×3(×3) spatial-hash gather as Get Nearby Agents (`emitNearbyFill` on WASM + WebGPU was PARAMETERIZED with an optional cone, NOT cloned — getNearbyAgents keeps `cone=null` ⇒ byte-identical). Membership = `dot(heading, offset) ≥ cosHalf·|heading|·|offset|` (the division-free rearrangement of `cosA ≥ cosHalf`); `cosHalf = cos(halfAngle·π/180)` is a **compile-time literal** (`viewCosHalf`, no runtime `cos` ⇒ JS↔WASM bit-parity, no host-cos import); `|heading|²==0` (a still agent under the velocity source) ⇒ **omnidirectional** (the ÷0 guard); `halfAngle ≥ 180°` ⇒ an omni compile-time fast-path. Config: `halfAngle` (deg) + `headingSource` (**velocity** default / **wired** X/Y/Z — a `facing` source lands with Orientation, deferred to avoid an unbacked option). 2D + 3D (`hiddenPorts` hides the Z heading in 2D). **The 5 registration sites the parity harness caught** (the "half-wired feature" lesson): AGENT_WASM/WEBGPU_SUPPORTED_TYPES, AGENT_ARRAY_PRODUCERS (×both), the array-dispatch case, **AGENT_VALUE_NO_HOIST** (else the pre-emit tried to hoist it as a value → "unsupported value node"), and the **nearby scratch-slot budget** (else `slot·maxAgents·4` = `undefined·… = NaN` → `i32Const(NaN)` "leb128s: non-finite NaN"). Verified: JS 0-mismatch vs an independent cone calc (66% cull); JS↔WASM bit-parity ([scripts/parity-agent-wasm.mjs](scripts/parity-agent-wasm.mjs) `buildFOVModel` synthetic, 30 steps); WebGPU real-GPU shader compile (0 errors) + end-to-end (0 mismatch, 65% cull); Boids (getNearbyAgents on WebGPU) unregressed (polarization 0.998).

**Sense Hemifield** (STEP 5b — [SenseHemifieldNode.ts](src/modeler/vpl/nodes/SenseHemifieldNode.ts)) is the Braitenberg **LEFT / RIGHT** sensor — a MULTI-OUTPUT value node (`Left Count` + `Right Count`) that runs the SAME FOV-cone gather as Get Agents In View but, instead of an id array, SPLITS each in-view neighbour by the sign of the heading-relative **cross product** (steer by `Left − Right`). It carries `getAgentOffset`'s registration footprint (MULTI_OUTPUT_TYPES + NEVER_INVARIANT + the accessorCSE never-pure list + the asyncWriteHazard reader-seed/read-keys + AGENT_WASM/WEBGPU_SUPPORTED_TYPES + a value-emitter case on each compiler) **PLUS two id-ARRAY outputs, `Left Agents` / `Right Agents` — see the next bullet.** Reuses `viewCosHalf`/`viewHeadingExprs` from Get Agents In View so the cone math is IDENTICAL, and the WASM/WebGPU emitters reuse the SHARED `emitHashStencil`/`emitAllPairs` (no gather drift). The split: **2D** `cross = hx·dy − hy·dx`; **3D** `cross = det[heading, offset, up]` = `select(hx·dy − hy·dx, hz·dx − hx·dz, upY)` with `up = +Z` normally, swapped to `+Y` when the heading is near-vertical (`upY = hz² > 0.81·hm2`, computed once per agent — det[h,o,+Z] reduces to the 2D form). `cross ≥ 0` ⇒ LEFT (a deterministic tie toward Left); a zero heading ⇒ omnidirectional cone ⇒ all Left. Config `halfAngle` (default **90°** = a 180° front hemisphere) + `headingSource` (velocity/wired). Verified: **tsc**; **JS logic** ([scripts/test-hemifield-logic.mjs](scripts/test-hemifield-logic.mjs)) — 5 hand-verified + independent-re-implementation cases (2D omni / 2D cone-60 / heading-rotation / 3D up-swap / 3D no-swap), all L/R exact; **JS↔WASM bit-parity** ([scripts/parity-agent-wasm.mjs](scripts/parity-agent-wasm.mjs) `buildHemifieldModel` synthetic storing BOTH outputs so a L/R swap is caught, + all 8 samples unregressed); **WebGPU real-GPU** — 2D (no `select`) + 3D (`select` with the verified operand order) shaders compile with 0 device errors.

  - **The two id ARRAYS make it a CONDITIONAL array producer** (so a rule can ACT on a side, not merely measure it: `Left Agents` / `Right Agents` feed For Each In Array / Get Agents Attribute / Filter Agents / Aggregate). **THE COST RULE: only a CONSUMED array port costs anything** — an unconsumed side emits no declaration, no scratch, no push and (on WebGPU) no `var<function>` slot, so a counts-only graph compiles to EXACTLY the pre-arrays code on all three agent targets (`check-compile-identity`: 29 models byte-identical, incl. the shipped `Boids — Hemifield Vision`).
    - **ONE predicate decides it everywhere.** `hemifieldArraysUsed(nodeId, edges)` / `hemifieldArraySlotCount` (exported from [SenseHemifieldNode.ts](src/modeler/vpl/nodes/SenseHemifieldNode.ts)) derive consumption from the FLAT EDGE LIST — the one input every front-end AND every gate has — so the JS emit's injected `_leftAgentsUsed`/`_rightAgentsUsed` config flags (the `_indexesConnected` precedent, injected by `compileRoot`), the WASM/WebGPU emitters, the WebGPU array-producer BUDGET and the WebGPU slot ASSIGNMENT all get the same answer by construction. Both compilers stash the flat edges on their ctx (`ctx.flatEdges`) purely so the emitters can ask that same question from that same input.
    - **THE COUNT *IS* THE ARRAY INDEX AND THE LENGTH**: the push rides the SAME branch as the count bump and uses the count as its write index, so `leftAgents.length === leftCount` holds by construction and the arrays partition EXACTLY the set the counts count (asserted in both harnesses). On WebGPU the push is capped at `AGENT_GPU_ARRAY_CAP` like every other GPU array producer, so past the cap the ARRAY truncates (`len = min(count, cap)`) while the COUNT stays exact — the documented GPU capacity bound.
    - **SCRATCH BUDGET, per target.** **WASM**: the arrays ride the general per-agent BUMP-POINTER slab (`allocScratch`, capacity `highWater`) — the same region getBondedAgents / filterAgents / getAgentsAttribute use — so they do **NOT** consume one of the `AGENT_NEARBY_SCRATCH_SLOTS` (4) baked-offset buffers and the WASM capacity gate is unchanged. **WebGPU**: one `var<function>` slot per CONSUMED port (0/1/2, keyed `${nodeId}:${portId}`), counted into the `AGENT_WEBGPU_NEARBY_SLOTS` (6) budget by the SAME `hemifieldArraySlotCount` the slot assignment uses.
    - **Registration deltas beyond the ports**: `senseHemifield` joins `AGENT_ARRAY_PRODUCERS` on BOTH agent targets, but ONLY for its array ports — a new **`isAgentArrayPort(nodeType, portId)`** guard keeps its scalar `leftCount`/`rightCount` off the array path (without it, a count wired into an `isArray` input would silently resolve to the whole id array). It is added to the array DISPATCH (`compileArrayNode`) on both targets, to the WebGPU array-source EDGE gate, and — **per NODE, not per type** — to both `isHoistable` predicates: a hemifield with a WIRED array port is an array producer and must emit at its use site, while a counts-only one keeps hoisting exactly as before (which is what preserves byte-identity).
    - **Verified**: `test-hemifield-logic.mjs` (11 checks) asserts array MEMBERSHIP by a `Σ 2^id` bitmask against an independent re-implementation (2D omni / 2D cone-60 / heading rotation / 3D up-swap) plus `length === count`, disjointness, and that a counts-only node emits NO array machinery; the `[synthetic] Hemifield (L/R counts + both id ARRAYS)` parity entry sums each side's ids through a For Each + Local Variable and carries a VALUE invariant recomputing all six outputs independently (**negative-controlled**: an identical off-by-one on BOTH targets passes parity and is caught by the invariant). **Real worker, all three agent targets** (JS / WASM / WebGPU, 40 agents): counts, sums AND lengths match an independent recompute from the read-back positions with **0 of 40 agents disagreeing** and identical L/R totals (351/276) on all three; the WGSL compiles + dispatches on a real device with 0 errors and `agentEngineActive: 'webgpu'`, 0 fallback events.
    - **A pre-existing bug fixed in passing**: `test-hemifield-logic.mjs` was STALE and failed 5/5 on HEAD — its ABI shape omitted C9's `gates` (and the bond-attr / generation blocks), so its arg list declared 9 more fields than the compiler's param list and every later arg shifted (the documented `AgentAbiShape` mirror rule). It now builds the store WITH `resolveAgentFieldGates(model)` and passes the matching shape.

Catalogue → **118 selectable / 45 agent**.

### STEP 4 + STEP 6 — SHIPPED (C9, branch `GRA`): profile-gated SoA fields + the Static integrator

Both former "Deferred XL" items landed as Clarity phase **C9** ([HANDOFF_CLARITY_SIMPLIFICATION.md](docs/HANDOFF_CLARITY_SIMPLIFICATION.md) §C9, plan + impact map [docs/PLAN_CLARITY_C9.md](docs/PLAN_CLARITY_C9.md)). **[src/model/agentFieldGating.ts](src/model/agentFieldGating.ts) is the ONE source of truth** for both — `resolveAgentFieldGates(model)` (which optional fields exist) and `agentMotionMode` / `motionIntegrates` / `motionAppliesForces` / `motionModeCode` (whether the engine moves anything).

- **STEP 4 — the four optional field groups are gated by CAPABILITY *OR USAGE*.** `sprites` (`spriteIds`/`Frames`/`Speeds`/`Rotations`/`Scales`, **36 B/agent**; at C9 the only group with no baked byte on any target — it has since gained a WASM region so Set Agent Sprite can emit there, appended after every other region, so the gating argument is unchanged), `age` (8 B), `targetRadius` (8 B), `density` (8 B). **Measured on the shipped library: 24 B/agent of f64 reclaimed on 6 models, 16 B on 5, 8 B on 3** — plus the 5 dropped sprite ABI params on ALL 14 (no shipped agent model has sprites).
  - **THE SAFETY CATCH — ONE uniform representation: a dropped field is a ZERO-LENGTH typed array, never `undefined`.** On a zero-length `TypedArray` **`a[i] = v` is a silent no-op**, so every engine WRITE (`initAgentSlot`, `divideAgent`'s daughter seeding, `paintAgents`, and the serialize `copyInto`, which already clamps to `min(dst, src)`) needs **no guard at all**; only READS do. The three agent compilers therefore emit the typed default: JS via `ctx.agentGates` in the node emitters + the `behaviourStep.myAge` preamble; WASM via `ctx.layout.f64[f] === undefined` (`gatedF64Read`, with the write emits skipped); WebGPU via `hasF32` / `gatedF32` over `layout.f32Base`. Engine-side, `getAgentState` reports `?? 0`.
  - **THE GATE IS USAGE-WIDENED, never capability-only** — `hiddenPorts` + the palette gate are cosmetic (the badge is informational), so a placed `Get Age` keeps compiling with Lifespan off. `age` = `lifespan || getAge || a WIRED behaviourStep.myAge`; `targetRadius` = `growth || usesEngineGrowth(cfg) || setTargetRadius || setAgentRadius`; `density` = **deliberately the NEIGHBOUR-SCAN predicate** (`agentGraphReadsEngineDensity(model) || usesSoftCollision || usesBondingPhysics || usesCharge`, where the first term is `divideAgent` OR a `neighbourDensity` whose Radius is INACTIVE — an active Radius lowers the node away, so nothing reads the reduction), because that scan is the field's only writer, so density-off implies the scan never runs and nothing writes it on any target; `sprites` = `model.sprites.length > 0 || setAgentSprite`.
  - **THE LOCKSTEP — the gates decide BYTE OFFSETS, and the resolved record is SHIPPED, never recomputed.** `resolveAgentFieldGates(model)` rides the init/recompile message as `agentFieldGates` (the `agentBondReqSlots` precedent) into `createAgentStore({ fieldGates })` and onto `store.fieldGates`; `computeAgentMemoryLayout` reads it off `AgentLayoutExtras.fieldGates` (which `buildAgentLayoutExtras` fills from the same resolver). It is ALSO in `needsFullInit` — a gate change re-lays-out the SoA, so a soft recompile would leave the store one shape while the freshly compiled module bakes another.
  - **THE `AgentAbiShape` MIRROR RULE (a real desync this phase hit and fixed).** The gates ride `AgentAbiShape.gates`, so **EVERY shape builder must carry them** — `agentAbiShapeOf` (compile.ts), `agentAbiShapeOfStore` (the worker, which reads `s.fieldGates`), and the parity harness's `shape`. Missing it at ONE site makes the param list and the arg list describe different field sets and every later arg shifts: the worker's builder was missing `gates`, and Ant Necrophoresis' Agent Init Event died with *"Cannot read properties of undefined (reading '0')"* — `_rngState` had shifted off the end of the arg list. **`audit-agent-layout` CANNOT catch this** (it compares compile's params to the descriptor using the SAME shape), so tier D of [scripts/test-c9-gates.mjs](scripts/test-c9-gates.mjs) pins it as a source invariant over all three sites.
  - **The WebGPU agent SoA layout is deliberately NOT gated** (only its emitters carry the safety catch). Its runs are a transient per-generation mirror re-uploaded from the CPU store, not where agents live; gating them would additionally touch the windowed upload/readback plan (`buildF32ReadPlan`, whose `compactBase` THROWS on an unplanned base) for no memory win. Flipping it on later is a layout-only change — the emitters are already ready.
- **STEP 6 — `Motion: Static | Velocity | Force` now drives the ENGINE, not just the palette.** `force` (the default and every legacy file) is the historical integrator byte-for-byte. `velocity` integrates `x += v` with the velocity the graph SET and seeds NO engine force (so `Set Velocity` genuinely coasts — under force mode a momentum-0 model wipes it the same step). `static` moves nothing: the force accumulation, the integrate block **and the position commit** are all skipped.
  - **THE HAZARD (and the reason the two are skipped TOGETHER):** `Ant Necrophoresis` SHIPS `motion: 'static'` and moves its ants with `Set Agent Position`. Skipping the force pass while KEEPING `swapPositions` would copy the stale `xNext` over `x` and revert every graph write — the Ant section above warned that the inert pass "MUST run" for exactly this reason. So: JS skips `swapPositions`; the per-gen WebGPU path refreshes `s.xNext` from the live `s.x` before the upload (making the readback commit an identity); and the resident `posCommit` is compiled for the mode — under Static it writes `xNext = x` instead of `x = xNext`.
  - **Per target**: JS gates both the 2D and 3D integrate arms plus the commit; **WASM emits one of three COMPILE-TIME variants** (`emitForcePass(..., motionMode)`) rather than taking a runtime param — the motion mode is a MODEL property that cannot change without a recompile, which is exactly the reasoning behind `forcePassParamsFor(chargeOn)`, and it adds no ABI slot; **WebGPU** gates at RUNTIME on a new `ForceControl.motionMode` field (appended last, `FORCE_CONTROL_BYTES` unchanged at 128 — the `doCharge` convention, since the shader text is not identity-checked).
