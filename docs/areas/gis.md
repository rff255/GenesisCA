## Esri ASCII grid (`.asc`) — the GIS raster seam + `ModelProperties.georef` (branch `tasks_batch_2026_08`)

**Tier 1 (+ the Tier-3 georef record it needs) of [docs/INVESTIGATION_GEOSPATIAL_IO.md](docs/INVESTIGATION_GEOSPATIAL_IO.md); its UI rides the "Geographic tools (GIS)" gate below.** Makes GenesisCA directly consumable from every GIS on earth by the SAME contract FARSITE / Cell2Fire / NetLogo use, with **no new dependency and no projection machinery** (alignment happens upstream — every surveyed tool refuses or ignores misaligned data). It is an EXTENSION of the CSV import/export, not a parallel feature: one dialog, one pure module, the existing `importGridValues` worker seam.

**ZERO compiler impact, structurally**: `git status` touches no file under `src/modeler/vpl/compiler/` and no worker/engine file. Proven, not asserted — `check-compile-identity` reports **29 models, all surfaces unchanged** against a stashed HEAD.

### The pure core ([csvImport.ts](src/simulator/csvImport.ts) — same DOM-free module, same discipline)
- **`parseAscGrid(text)`** → `{ ncols, nrows, xllcorner, yllcorner, cellSize, nodataValue, centerOrigin, tokenCount, table }` or **null** (not an `.asc`). `isAscGridText` is the cheap router (first non-empty line's first token is `ncols`).
- **Header**: up to 6 `KEY value` lines, **case-insensitive**, whitespace/tab tolerant, in any order, each optional but `ncols`/`nrows`. `xllcenter`/`yllcenter` convert to the corner form (`corner = centre − cellSize/2`) and set `centerOrigin`; absent origin ⇒ 0, absent `cellsize` ⇒ 1, absent `NODATA_value` ⇒ **null** (no cell is "no data" — distinct from 0).
- **⚠ THE BODY IS A FLAT ROW-MAJOR VALUE STREAM, NOT ONE LINE PER ROW.** That is what the spec says; the tokens are chunked `ncols` wide. Every real writer emits one line per row, so the two readings coincide — the flat read additionally survives a WRAPPED body, which a line-based read would silently reshape. A SHORT stream leaves trailing cells missing (padded + counted); a LONG one keeps the declared `nrows`. `tokenCount` vs `ncols*nrows` is surfaced in the dialog summary rather than guessed at.
- **Whitespace-tokenised (`/\s+/`), NOT the RFC-4180 machinery** — `.asc` bodies are commonly space-ALIGNED, and the CSV parser would read runs of spaces as empty fields. (Same reasoning as the `none`-delimiter path having its own reader.)
- **`buildGridValues(table, attr, charMap?, nodataValue?)`** — the 4th arg is additive: a raw field matching `nodataValue` **NUMERICALLY** (so `-9999`, `-9999.0` and `-9.999e3` all match) takes the attribute default and is counted in the new **`nodataCells`**, NOT in `badValues` — "outside the study area" is a legitimate statement, not a parse failure. Absent/null ⇒ the historical path byte-for-byte (`nodataCells` stays `undefined` on the CSV path).
- **`buildAscGrid(values, w, h, georef?, opts?)`** — the six header lines from the georef (absent ⇒ the neutral `0 / 0 / 1`) + `NODATA_value` (`ASC_NODATA_DEFAULT` = −9999) + whitespace-separated rows.
  - **VALUES ARE PLAIN NUMBERS — never `formatCsvValue`.** `.asc` is a numeric raster, and "integer codes + a separate code→class table" is exactly how the field encodes categorical layers (Cell2Fire fuel models, NLCD classes). So a **tag exports its INDEX** and a **bool `0`/`1`** — both of which `decodeCsvValue` reads straight back, which is what makes the round trip exact. Writing the tag NAME would produce a file no GIS can read AND break the round trip.
  - A **non-finite** value is written as the NODATA sentinel (which re-imports as the attribute default) — the honest "no value here".
  - `maxRows` truncates the BODY only; the header still declares the full height (the dialog preview relies on this).

### `ModelProperties.georef?: GeoReference` ([types.ts](src/model/types.ts))
`{ xllcorner, yllcorner, cellSize, crs? }` — the Esri LOWER-LEFT-CORNER convention. **Additive + optional, NO migration.** **PRESENTATION + I/O ONLY** — nothing in any compiler, the worker or the engine reads it (the C8 presentational-geometry doctrine); written by the `.asc` import via `updateProperties`, read back by the `.asc` export. `crs` stays absent for `.asc` (the format carries none); a future GeoTIFF import fills it. It rides the `.gcaproj` for free — `stringifyCompact` is a whole-object walker with no field picking (verified: it serialises and `parseModelJSON` returns it unchanged).

### The dialogs — extended, never forked
**[CsvImportDialog.tsx](src/simulator/CsvImportDialog.tsx)**: when the loaded text parses as `.asc`, the file decides the dialog's whole shape (an "an enabled control must do something" application) — the **Target switch is HIDDEN and Grid is FORCED** (a raster is a board, not a list of agents), the **Delimiter + Header rows are HIDDEN** (the format defines both; `isCharMode` is additionally forced false so a stale `none` selection can't apply), the preview line shows `ncols / nrows / cellsize / NODATA` instead, and the title reads *Import Esri ASCII grid*.
- **Multi-layer**: a `Layers` block with **+ Add layer…** (its OWN `multiple` `<input accept=".asc,.txt">`), one target-attribute select per extra file. The primary file is layer 0 and reuses the shared *Cell attribute* select, so a single-file import reads exactly like a CSV. **ALL layers must agree on `ncols`/`nrows`** — the FARSITE co-registration contract — checked loudly (red row + a named message) and **blocking Apply**. The stack resets on a new `text` (the dialog is re-rendered, not remounted).
- **A third fit, `resample`** (`.asc` ONLY — a georeferenced raster has a cell SIZE, so resampling it onto the model's grid is meaningful and georef-correct; a plain CSV board has no such scale and keeps resize / keep). It runs the SAME kernels the GeoTIFF importer does, via **`buildAscLayer`**:
  - **NEAREST resamples the parsed TABLE** (`resampleCsvTable` — cell TEXT and all), so every existing `buildGridValues` behaviour survives: a tag matched by NAME, the per-cell issue reporting, ragged-row padding. Turning the board into numbers first would silently drop tag-by-name support.
  - **AVERAGE has to go through numbers** (a mean over text is undefined), so `csvTableToNumbers` reads the body raw (unparseable → NaN, which the decode still reports as a miss) and hands it to the SAME `buildBandValues` — one box filter, one NODATA rule, for both formats. It is refused there for a categorical target regardless.
  - ONE **Method** select for the session, shown only when at least one layer targets a numeric attribute; a multi-layer stack resamples every layer identically. The georef takes `scaleGeorefForResample` (corner put, cell size scaled). **No crop box** — an `.asc` is text, and in practice already the extent you cut.
- `CsvImportResult`'s grid variant now carries **`layers: Array<{attrId, values}>`** (a CSV/char board is the one-entry case) + an optional `georef`. `pendingGridValuesImport` holds the same list, and both consumption points post one `importGridValues` per layer.

**[CsvExportDialog.tsx](src/simulator/CsvExportDialog.tsx)**: the grid flavour gains a **Format** select (`CSV table` / `Esri ASCII grid (.asc)`); `.asc` hides the Delimiter row, swaps the title, extends `totalLines` by the 6 header lines, states the georef in the summary (and says so when there is none), and saves with the `.asc` extension through `saveTextFile` (`text/plain`) — never a bare `<a download>`. The **agents flavour is untouched**.

## Backdrop map + georef editing + the world-coordinate readout (Tier 3, branch `tasks_batch_2026_08`)

The visible half of [docs/INVESTIGATION_GEOSPATIAL_IO.md](docs/INVESTIGATION_GEOSPATIAL_IO.md) **Tier 3** (every surface below is behind the "Geographic tools (GIS)" gate — see that section): the georef record the `.asc` import writes becomes EDITABLE and READABLE, and a model can carry a static map image drawn under the cells (SLEUTH's hillshade layer / QGIS's basemap). **PRESENTATION ONLY — ZERO compiler / worker impact**: `git diff --stat` is `types.ts` + the new `backdrop.ts` + `InfoPanelContent` + `PropertiesPanelContent` + `SimulatorView` + `HelpView`; nothing under `compiler/` and no `sim.worker.ts`.

### Schema — the IMAGE is model data, the VIEW settings are not
- **`ModelProperties.backdrop?: MapBackdrop`** = `{ dataUrl }` — a STILL image travelling inside the `.gcaproj` exactly like the thumbnail (verified: `stringifyCompact`'s whole-object walk serialises the nested object with no per-key handling). Rules in [backdrop.ts](src/model/backdrop.ts): `BACKDROP_ACCEPT` (png/jpeg/gif/webp — **deliberately NARROWER than the thumbnail's: NO video**, since the draw path blits it every frame and a `<video>` frame source would need its own play/seek lifecycle for no gain) + `BACKDROP_MAX_BYTES` = **4 MB** (a legible map export is photographic, unlike a 200 px card preview — but it still rides in the `.gcaproj`, so it stays bounded).
- **`showBackdrop` / `backdropOpacity` are per-USER VIEW settings** in `genesisca_sim_settings`, never in the model — *which* map is a property of the model, *how strongly to show it* is a preference. Declared with the other persisted view options **ABOVE** the settings-persist effect (the documented declaration-order trap).

### Draw order, and the ONE interplay that needed care
Inserted in `draw()`'s 2D branch immediately BEFORE the grid blit, so the map is the bottom-most content layer, drawn through the SAME integer-snapped tiling the grid uses (a new local `forEachWorldTile`, which the later `bg2d` fill now shares — so the map lines up with the cells to the pixel, seams included, and tiles in infinity mode).
- **`bg2d` had to move UNDER it.** The void colour normally fills the world rect LATER in `draw()` (it applies only when the grid layer is hidden), which would have completely hidden the map it is meant to back. So with a backdrop the fill is emitted in the backdrop block and the later block is skipped via **`bg2dDrawnEarly`**. The same pairing exists in `renderSimulationFrame`.
- **Smoothing is ON for this blit only** (`ctx.save`/`restore` — `imageSmoothingEnabled` is part of the saved drawing state): a photographic map upscale should interpolate, unlike the crisp cell grid.
- **AN OPAQUE CELL HIDES THE MAP, and that is the contract** — stated in the Info-panel hint, the simulator tooltip and Help. `putImageData` REPLACES pixels in `srcCanvas` (alpha included) and the display `drawImage` composites source-over, so a cell whose Output-Mapping colour carries alpha < 255 blends over the backdrop. **Measured, not assumed**: with the linked palette's dead colour at `#00000080` over a 4-quadrant test map, the display reads exactly `(127,0,127)` / `(0,127,127)` / `(127,127,0)` / `(127,64,0)` — the 50 % composite — while alive cells stay pure `(255,255,255,255)`.
- **THE GPU DISPLAY PATHS NEED NOTHING THREADED INTO THE WORKER, and that is a property of their CLEAR, not luck.** This is a main-thread presentation layer; every path ends in ONE `ctx.drawImage(<worker canvas>)` over the backdrop, so source-over decides everything. **2D WebGPU direct render**: the blit source is a grid-resolution OffscreenCanvas the worker paints — opaque cells hide the map, translucent ones blend over it, exactly as on the CPU path. **A1 agent direct render**: `computeAgentRenderView` clears the agent canvas **transparent unless the grid layer is HIDDEN *and* `bg2d` is set** (`bgA = 0` otherwise) — so on an agents-only model with no `bg2d` the map shows through under the discs, and with `bg2d` on the void colour is the worker's clear (which is exactly why the backdrop block SKIPS its own early `bg2d` fill in that case). **E2 grid+agents composite**: `showGrid2d` is true there, so the canvas is cleared TRANSPARENT and `GRID_PRESENT_WGSL`'s FS returns **premultiplied `vec4(r·a, g·a, b·a, a)`** — a cell with alpha < 255 leaves the composite partially transparent and the backdrop shows through it too. No worker-protocol widening is needed on any of them.
- **Capture**: the view scope reads the display, so it carries the backdrop for free; `renderSimulationFrame` draws it after the `CAPTURE_BACKDROP` fill and before the grid, gated on `showBackdrop`. **3D draws no backdrop at all** (the voxel scene has `bg3d`), and every backdrop control is HIDDEN in 3D — the standing structurally-impossible rule.

### Georeference editing + the world readout
- **Properties → Structure → Georeference** — three `NumberField`s (X origin / Y origin / Cell size, Esri corner convention in the tooltips) + a CRS text input + a **Clear** button shown only when a georef exists. Every edit spreads over a module-level **`defaultGeoref`** (`0 / 0 / 1`, the same fallback `buildAscGrid` writes) so typing ONE number into an absent georef yields a COMPLETE record — `GeoReference`'s three numbers are all required.
- **The hover chip gains a second line** when a georef is present: `⌖ <wx>, <wy>` — the hovered cell's CENTRE. `worldLabelOfCell(georef, col, row, nrows)` is the one formula and it carries **THE ROW FLIP**: `wx = xll + (col+0.5)·cs`, **`wy = yll + (nrows−1−row+0.5)·cs`** — the Esri origin is the lower-left corner with Y growing UPWARD, while grid row 0 is the TOP row. Precision follows the cell size (`< 1` ⇒ 6 decimals for degrees, else 2).
- **It publishes FORMATTED STRINGS**, so the hover store's cheap dedup compare covers them and `HoverCoordsChip` stays a pure render; the georef itself rides a `georefRef` assigned during render (the chip is on the pointer hot path and must not close over a stale model).

### Verified in the real UI (Game of Life + Life3D, dev server, **0 console errors**)
Backdrop confined to the world rect **exactly** (746 496 lit = 864², the 100 224-px letterbox untouched) with the four quadrants at their injected colours; the alpha-128 composite above; **opacity strictly monotone** (total luminance 2.31M → 73.5M → 120.7M → 154.3M → 179.4M at 0 / .25 / .5 / .75 / 1, and restoring 1 returns to the same number); **Show** off ≡ opacity 0 and greys the slider; **infinity mode tiles it** (every pixel lit, the left letterbox showing the neighbouring tile's correct quadrant); **hover world coords exact on three cells** — (150,150) → `504515.00, 4604485.00`, (0,0) → `500015.00, 4608985.00` (X min, Y **max** = north-west) and (299,299) → `508985.00, 4600015.00` (X max, Y **min**), i.e. the row flip proven at both ends; **both capture scopes carry it** (a real 📷 with area *Simulation* = 720×720 grid-aspect, with *View* = 980×864 display-res, both showing the same composited quadrants); **`.gcaproj` round trip** — the saved JSON carries `backdrop.dataUrl` + `georef`, and after a full page reload a stock Game of Life shows NO Backdrop section while dropping the saved file back restores the identical rendered image; the **`.asc` import** writes its header into the new Properties fields (`1000 / 2000 / 10`, CRS empty — the format carries none) and raises the Clear button; **3D (Life3D)** *with a backdrop attached* renders none and shows no backdrop control anywhere.
- **⚠ Verification hazards hit here, worth reusing.** The Browser pane can report `innerWidth 0` — call `resize_window` first or every canvas measures 0×0 and `draw()` bails. `draw()` then has to be provoked: `window.dispatchEvent(new Event('resize'))` is a real listener and paints synchronously. The hover pipeline is **rAF-coalesced** and rAF is suspended in a hidden pane, so it needs an rAF shim — but **restoring rAF while a callback is still queued leaks `hoverWorkRaf.current`, and the chip then never updates again** (a probe artifact, not a product bug: real rAF always fires). Accumulated monkey-patching likewise made model LOADS stop taking effect; a page reload restores normal behaviour, so do the round-trip test on a fresh page.

## GeoTIFF import (Tier 2 — the ONE runtime dependency, branch `tasks_batch_2026_08`)

**Tier 2 of [docs/INVESTIGATION_GEOSPATIAL_IO.md](docs/INVESTIGATION_GEOSPATIAL_IO.md); its menu item rides the "Geographic tools (GIS)" gate (a DROPPED `.tif` always opens the dialog).** The sources users actually download — LANDFIRE, WorldPop, NLCD, Copernicus — ship GeoTIFF, and asking them to convert every band to `.asc` in QGIS first is pure friction. Pick a `.tif` → map each band to a cell attribute (with a categorical code table for tag/bool targets) → resize the grid to the raster or resample onto it → apply through the **EXISTING `importGridValues` seam**.

**ZERO compiler / worker impact, structurally**: `git status` touches no file under `src/modeler/vpl/compiler/`, no `sim.worker.ts` and no `engine/` file — the dialog produces the SAME `layers[]` payload the `.asc` path does.

### THE DEPENDENCY, AND THE VIEWER BOUNDARY (the load-bearing decision)
`geotiff` (3.0.5 — pure JS, browser-first, no WASM; pulls pako / lerc / zstddec / float16 / xml-utils). **It is reached through exactly ONE module, [geotiffLoader.ts](src/simulator/geotiffLoader.ts)**, which does the lazy `import('geotiff')` and exports `GEOTIFF_SUPPORTED`.
- **In the MAIN app** it lands in its OWN lazy chunks, fetched the first time a user opens a GeoTIFF. Measured: `geotiff 315.7 kB` + `lerc 97.4` + `zstd 81.1` + `pako 21.8` + `jpeg 11.2` + four tiny decoders — **none of it in the entry chunk**.
- **IN THE VIEWER IT MUST NOT EXIST**, and a lazy import is NOT enough: `vite-plugin-singlefile` sets **`inlineDynamicImports: true`**, so in the presentation build a dynamic import is folded into the ONE HTML file. So `mode === 'viewer'` **aliases `./geotiffLoader` → [geotiffLoader.viewer.ts](src/simulator/geotiffLoader.viewer.ts)** (the `createSimWorker.inline.ts` precedent, both regex ends anchored), whose `GEOTIFF_SUPPORTED = false` hides the menu item + the file input — no control the build cannot honour. **Measured, not assumed: `viewer-template.html` is 2 376 771 B with the alias and 2 908 411 B without it — the alias keeps 519 KB out of EVERY exported presentation** (and pako/lerc/zstd markers are provably absent from the shipped template). The dialog component itself (~17 KB) stays in the viewer bundle; only the library is dropped.
- The `.tif` file input + dialog are gated on `GEOTIFF_SUPPORTED` for the same reason.

### The pure core ([geotiffImport.ts](src/simulator/geotiffImport.ts) — everything but `openGeoTiff` is DOM- AND dependency-free)
- **The resampling kernels live in [rasterResample.ts](src/simulator/rasterResample.ts)** — a dependency-free LEAF module, because BOTH `geotiffImport` and `csvImport`'s `.asc` path resample onto the grid and must do it IDENTICALLY (a `.asc` and a GeoTIFF over the same ground have to pick the same cells); `geotiffImport` already imports TYPES from `csvImport`, so putting them in either would make the pair circular. `geotiffImport` re-exports them, so every existing import site is unchanged.
  - **`resampleNearest`** — the DEFAULT and the ONLY method for a CATEGORICAL target: averaging class codes invents classes that do not exist (`gdalwarp -r near`, for the same reason). Centre sampling `floor((d+0.5)·src/dst)`, clamped, with an **EXACT identity fast path**. ⚠ Deliberately NOT geotiff.js's own `resampleMethod: 'nearest'`, which is TOP-LEFT anchored (`round(rel·x)`) — centre sampling matches the cell-centre convention every other GenesisCA importer uses (the GeoJSON rasteriser samples centres too).
  - **`resampleAverage`** — a NODATA-aware BOX FILTER, for CONTINUOUS bands (elevation, population), i.e. `gdalwarp -r average`. Destination cell `d` covers `[d·src/dst, (d+1)·src/dst)`, widened to at least one sample so an UPSAMPLE degrades to nearest instead of producing NaN. Sentinel-matching samples are EXCLUDED from the mean (folding `-9999` in would smear the study-area boundary across every edge cell); a box holding NOTHING but NODATA outputs the sentinel again, so the caller's existing NODATA handling still sees it.
  - **`supportsAverageResample(attr)`** is the gate — integer / float / neighborIndex only. The UI HIDES the control for a categorical target (the enabled-control rule) **and `buildBandValues` refuses it structurally**, so a caller that ignores the gate still cannot average a class code. A value MAP (a code table) forces nearest for the same reason.
- **`decodeNumericValue(attr, v)`** — the NUMERIC twin of `decodeCsvValue` (a raster is already numbers; stringifying a float to re-parse it would be lossy theatre). integer/neighborIndex ROUND · float as-is · **bool: NONZERO is true** (the universal raster-mask convention) · tag: the option INDEX, out of range ⇒ default+counted · non-finite ⇒ default+counted.
- **`buildBandValues(band, srcW, srcH, dstW, dstH, attr, { noData, valueMap, resample })`** — **RESAMPLE THEN DECODE, and the order matters**: nearest picks a whole source sample, so NODATA and class codes survive the resize in their ORIGINAL numeric form and are compared / looked up there. Decoding first would resample already-defaulted values. NODATA is compared NUMERICALLY before the decode and counted in `nodataCells` (the `.asc` convention); an unmapped code is reported ONCE **per VALUE**, never per cell.
- **`distinctValues` / `autoSeedValueMap`** — the categorical table (the Cell2Fire code→fuel table, as UI), keyed by `String(rawValue)` with values in the canonical `Attribute.defaultValue` encoding, i.e. the SAME shape `CsvCharMap` uses. Auto-seed is IDENTITY where already meaningful (an in-range tag index, 0/nonzero for bool) and nothing where not. Enumeration stops at `GEOTIFF_MAX_DISTINCT` (64) and reports `truncated` — a continuous band has ~one distinct value per cell, and a million-row mapping UI is not a UI.
- **`georefFromGeoTiff` — THE FLIP IS THE WHOLE POINT.** GeoTIFF states the **TOP-LEFT** corner; `GeoReference` (and `.asc`) state the **LOWER-LEFT**, so `yllcorner = topY − height·|yres|`. A file whose `yres` is POSITIVE already has its origin at the bottom, so no subtraction applies. `|xres| ≠ |yres|` warns and uses X (`GeoReference` carries ONE square cell size). `crsFromGeoKeys` maps `ProjectedCSTypeGeoKey` (else `GeographicTypeGeoKey`) to `EPSG:xxxx`, skipping the 32767 user-defined sentinel.
- **`scaleGeorefForResample`** — a resample covers the SAME ground with fewer/more cells, so the lower-left corner is unchanged and only `cellSize' = cellSize·srcW/dstW` scales. X drives it; a changed ASPECT warns.
- **`shiftGeorefForWindow(georef, win, srcH)` — THE CROP'S OWN GEOREFERENCE, and the ROW FLIP is the trap** (the same one `georefFromGeoTiff` handles): the georef states the raster's LOWER-LEFT corner while the window is TOP-LEFT pixel coordinates, so `xll' = xll + x·cs` and **`yll' = yll + (srcH − y − height)·cs`**. The cell size is UNCHANGED — a crop selects fewer cells of the SAME resolution. **Compose CROP THEN RESAMPLE**, in that order. Sanity: `y = 0` (the TOP rows) gives the largest `yll`; `y = srcH − height` gives exactly the original.
- **The crop window**: `GeoTiffWindow {x,y,width,height}` (source pixels, top-left origin, half-open) + `clampWindow` (into the raster, ≥ 1 px, rounds a fractional drag) + **`defaultWindow`** (the WHOLE image when it fits, else the largest cap-shaped box CENTRED on it — never a rejection; the per-axis clamp is axis-INDEPENDENT so it cannot preserve the aspect, while the pixel-cap shrink is uniform and does) + `windowCapError`.
- **THE CAPS APPLY TO THE WINDOW, NOT TO THE SOURCE — that inversion is the whole feature.** `GEOTIFF_MAX_DIM` 8192 and `GEOTIFF_MAX_PIXELS` 16 777 216 (a 4096² tile) now bound the CROP; `GEOTIFF_MAX_SOURCE_DIM` (200 000) is a corrupt-header guard only. **Verified against geotiff@3.0.5's `_readRaster`, not assumed**: `minXTile..maxXTile` come from the window AND `numPixels = windowW·windowH`, so both the decode and the allocation scale with the piece you ask for. A 9000-wide source that used to be an outright rejection now opens.
- **`openGeoTiff` reads METADATA ONLY.** `readBand(index, win?)` reads one band over a window (cap-checked; cache keyed by band+window and bounded at `BAND_CACHE_MAX` 6, so dragging the box cannot retain a Float64Array per window traversed), normalising to Float64 once. **`readPreview(index, maxEdge)`** returns a whole-image thumbnail or **null**.
- **⚠ `width`/`height` DECIMATION DOES NOT REDUCE DECODE WORK** — geotiff.js resamples AFTER decoding the window (its `_readRaster` lines 539-551; measured: a full-image read decimated to 256² took *longer* than the plain full read). So the preview cannot simply ask for a small `width`/`height` of a huge image. **`pickPreviewImage`** instead chooses an IFD under the decode budget: a reduced-resolution **OVERVIEW** (a COG's pyramid) identified by the standard heuristic — smaller, same aspect within 5 %, with an explicit skip of transparency masks (`NewSubfileType & 4`, the one extra-IFD kind that would otherwise pass) — else the main image if it fits, else null. Every probe is wrapped: a malformed sub-image costs the preview, never the import.

## GeoJSON vector import (Tier 4 — the NetLogo/GAMA parity piece, branch `tasks_batch_2026_08`)

**Tier 4 of [docs/INVESTIGATION_GEOSPATIAL_IO.md](docs/INVESTIGATION_GEOSPATIAL_IO.md); its menu item rides the "Geographic tools (GIS)" gate (a DROPPED `.geojson` always opens the dialog, and applying one turns the gate on).** Rasters cover the ground; VECTORS are the things on it — lakes / exclusion zones / districts (polygons), rivers / roads (lines), towns / nests / sensors (points). Two consumers, exactly as the investigation frames them: **rasterise onto a cell attribute**, or **points → agents**. **NO NEW DEPENDENCY** (GeoJSON is JSON and every geometry primitive is arithmetic) and therefore **no viewer alias** — the dialog ships in the viewer like the CSV / `.asc` ones.

**ZERO compiler impact, structurally**: `git status` touches no file under `src/modeler/vpl/compiler/` and no `engine/` file. The ONE worker edit is an additive optional flag on an existing message (below).

### The pure core ([geojsonImport.ts](src/simulator/geojsonImport.ts) — DOM- AND dependency-free)
- **`parseGeoJson(text)`** → `{ items, counts, bbox, propertyKeys, skipped, crs }` or **null** (not JSON / not GeoJSON — never throws; the dialog reports). Accepts a FeatureCollection / a bare Feature / a bare geometry; **flattens every Multi\*** (the parts SHARE the feature's properties AND its 1-based index, so a multipart district behaves as one district) and **descends GeometryCollection** under a depth guard. A malformed geometry (null, a non-numeric coordinate, a 1-point LineString, a 2-point ring) is COUNTED in `skipped`, never fatal. **The 3rd coordinate (altitude) is deliberately IGNORED** — it is a height in world units, not a grid layer.
- **THE TRANSFORM IS THE FOUNDATION, and it is the exact inverse of the simulator's hover readout.** `toCellSpace(t, wx, wy)` maps world → CONTINUOUS cell space (cell `(col,row)` = the unit square `[col,col+1)×[row,row+1)`): `cx = (wx − xll)/cs`, **`cy = height − (wy − yll)/cs`** — the Esri row flip (origin lower-left, Y up; grid row 0 is the TOP). `worldLabelOfCell` reports a cell's centre as `wx = xll+(col+.5)cs`, `wy = yll+(nrows−1−row+.5)cs`; feed that back and you get `(col+.5, row+.5)`. **Cell space IS the agent frame** (the agent world is the grid frame 1:1 — the field bridge indexes `floor(y)*W+floor(x)`), so `worldToAgent` is the same function unrounded and `worldToCell` is its floor. `makeCellTransform(georef, height, mode)`: **`'cells'`** (or no usable georef) is the IDENTITY — x → column, y → row, **NO flip** — so a hand-written file needs no georeference.
- **`polygonCells`** — EVEN-ODD scanline over CELL CENTRES. Every ring's edges go into ONE crossing list, so **holes subtract with no special case** and the winding direction is irrelevant. Centre sampling matches the GeoTIFF resampler, so a polygon and a raster over the same ground pick the same cells. **Spans are HALF-OPEN in x and y**: two polygons sharing a border never both claim the boundary cell, and a shared vertex counts once. Cost is O(rows-in-bbox × edges), never O(grid). An unclosed ring closes implicitly; a polygon containing no cell centre covers NOTHING (and the caller reports it) rather than silently rounding up.
- **`segmentCells`** (supercover, Amanatides–Woo) + **`lineCells`**: **width 1 IS "every cell the segment passes through"** — deliberately NOT centre-within-0.5, which a diagonal would miss. A wider line adds every centre within `(width−1)/2`, i.e. a **capsule with ROUND caps** (the 2D brush Line tool's shape), so it reaches half the width past each endpoint. Off-grid cells are skipped while the walk CONTINUES, so a segment entering from outside still draws its in-grid part; a Manhattan step bound makes a degenerate slope unspinnable.
- **`rasterizeFeatures`** → `{ groupOf: Int32Array, groupValues, cellCount, featuresUsed/Filtered/Outside, badValues, featuresMissingValue, issues }`. **The per-cell store is a 4-byte GROUP INDEX, not a value** — a burn over a large grid costs the GRID, not the feature list — and **the LAST feature wins** on overlap while the cell is counted once. `collectRasterGroups` splits it into one **Int32Array of cell INDICES per distinct value**, so the caller materialises `{row,col}` objects only one batch at a time.
- **`GeoJsonValueSource`**: `fixed` (one value) or **`property`** — the NetLogo `gis:apply-coverage` shape, each feature painting its OWN value, so a landcover file lands its classes in one pass. `decodeGeoJsonProperty` COMPOSES the two decoders that already exist rather than inventing a third: a **number** → `decodeNumericValue` (tag = INDEX, bool = NONZERO — so a raster code and a vector code behave identically), a **boolean/string** → `decodeCsvValue` (so a tag matches by NAME, case-insensitively).
- **`hasProperty` — ABSENT ≠ BAD.** A GeoJSON property set is genuinely SPARSE (features in one collection routinely carry different keys), so an absent key is NO DATA: it takes the attribute default **silently** (counted only in `featuresMissingValue`), while a key that IS there but is null / unparseable is BAD DATA (default + counted + listed). Counting absence floods the report on any real file — measured 12 bogus "misses" on a 4-feature fixture before the rule.
- **Points → agents** reuses the CSV importer's column logic verbatim: `autoMapGeoJsonProperties` = `autoMapAgentColumns` over the property keys, and `geoJsonAgentTargetOptions` = `agentTargetOptions` **minus `x`/`y`** — position comes from the point GEOMETRY and is never overridable from a property (a property literally named `x` auto-maps to ignore). `buildGeoJsonAgents` mirrors `buildAgentSpecs`' reporting (skipped / bad / out-of-bounds, the worker owning the actual wrap/clamp).

### AUTO-ENABLE — the discovery path (why the gate can be off by default without hiding the feature)
A GEOGRAPHIC import that APPLIES turns the gate on, so a fresh model that swallows a `.tif` gains the Georeference + Backdrop blocks and the GIS menu items from then on:
- **`applyGridImport(r, busyLabel, gis)`** writes **ONE** patch — `georef` when the file carried one, `gisTools: true` when `gis || r.georef` and it is not already on. One dispatch, and a repeat import of an already-geographic model re-dirties nothing.
- **`.asc`** always carries a georef (`CsvImportDialog` builds one from `primaryAsc`, defaulting to 0/0/1), so it enables through the `r.georef` arm. **GeoTIFF passes `gis: true` explicitly** — a `.tif` is geographic by definition even when it has no geokeys and `georefFromGeoTiff` returned nothing.
- **GeoJSON enables in BOTH coordinate modes** (`enableGisTools()` at the top of `applyGeoJsonImport`). A judgment call: a grid-cells burn is still a vector import, and enabling only in World mode would make the menu item vanish again right after a perfectly good import.

### MIGRATION — inference, once, only when the field is absent
`LOAD_MODEL` ([ModelContext.tsx](src/model/ModelContext.tsx), beside the other additive guards): a file with **no `gisTools` field** but **with `properties.georef` or `properties.backdrop`** infers `true`, so a GIS-touched file saved before the gate keeps its UI. An explicit `false` is the user's own choice and stands; everything else stays off. Idempotent.

Generators: [scripts/gen-wildfire-sierra.mjs](scripts/gen-wildfire-sierra.mjs) + [scripts/gen-urban-recife.mjs](scripts/gen-urban-recife.mjs) over the shared [scripts/geodataLib.mjs](scripts/geodataLib.mjs).

### The rules, and the two things that are load-bearing about them
- **WIND is eight compile-time constants, not eight runtime branches.** Fire arriving from a neighbour at `(dr, dc)` travels in the compass direction `(−dc east, +dr north)`, so its weight is `1 + windE·(−dc/dist) + windN·(dr/dist)`. Those coefficients are baked into **two Expression nodes** (four cardinals; four diagonals, whose `1/√2` distance factor and projected wind components are the SAME constant), which is what keeps the whole mechanism to 6 inputs per expression. The eight per-direction reads come from ONE Moore neighbourhood with compass **tags** (`getNeighborAttributeByTag`), not eight one-cell neighbourhoods.
- **SLOPE rides each direction's own term** (`max(0, 1 + slopeBoost · clamp((myElev − nbrElev)/15 m, −1, 1))`), so it is per-neighbour rather than a single averaged number — which is why `slopeBoost` 0 vs 1.6 swings the burn's mean elevation by ~85 m (measured).
- **URBAN counts Urban and Road neighbours SEPARATELY, and that separation is the feature.** Counting them together made every road-adjacent cell eligible whatever `Road attraction` said — **measured: turning the slider to 0 left the near-road growth rate at 1.07× the far-from-road rate before the split and 2.06× after**, i.e. the slider had been nearly inert. Counting them apart lets ONE slider own the whole road mechanism (`edge = (nUrban + rw·0.25·nRoad)/8`, plus the distance pull), so at 0 the network genuinely leaves the rule.

### ⚠ THE RESET TRAP — SOLVED by `resetRestoresBoard`
The layers live in the model's embedded `simulationState`, so the model opens with the landscape and needs **no network at load time**. But **a plain Reset re-seeds the grid from the model's Init Events, and imported data is not an Init Event** — so Reset used to CLEAR the landscape (measured: fuel `{0:4997, 1:242, 2:5128, 3:483, 4:29083, 5:68}` → `{0:40001}`). Both models now set **`properties.resetRestoresBoard: true`**, so Reset reseeds and then applies the embedded board on top; the ■ button's own menu still offers a from-rules reset. Two things go with it, both required:
1. `properties.instructions` says so in its opening sentence (the Simulator's ⓘ pill), including how to reach the from-rules reset;
2. verified end to end — plain Reset leaves the fuel histogram IDENTICAL, the menu's *Reseed from rules* reproduces the wipe, and *Restore saved board* brings it back exactly.
**Any future data-backed model just sets the flag** (a fresh GIS import sets it for you — see the flag's own section). A Grid Init Event cannot substitute: there is nothing to procedurally regenerate — the data came from a satellite. *(This REPLACED a shipped "Restore landscape" preset the user had to know to load; dropping it also halved both files, 1.53 → 0.91 MB and 2.00 → 1.17 MB, since the board no longer ships twice.)*

### The generator conventions (follow these for a third one)
- **`scripts/geodataLib.mjs`** owns everything shared: the **cache**, windowed COG reads, Overpass, the georef, Horn slope + hillshade, the BFS distance field, a dependency-free **PNG encoder** (`node:zlib` + chunk framing — no new npm dependency), and `gridStateBlock()` (the embedded-board shape, mirroring `serializeSimState`).
- **FETCH ONCE.** Every network read is cached under **`scripts/geodata-cache/`** (gitignored) keyed by the exact window, so a re-run is offline-stable and **byte-identical** (verified). Delete the directory to re-fetch.
- **WINDOWS, NOT TILES**: `geotiff`'s `fromUrl` range-reads only the tiles covering the window — a few hundred KB out of a 38 MB / 114 MB file. **Snap the pixel window with an EPSILON** (`floor(x + 1e-6)` / `ceil(x − 1e-6)`): a window whose edges land exactly on the source graticule otherwise gains a spurious row/column from float drift, and resampling a 201-wide block onto 200 cells misregisters the whole layer by half a cell.
- **Resample CONTINUOUS data with `resampleAverage` and CATEGORICAL data with `resampleNearest`** (both imported straight from the shipped [rasterResample.ts](src/simulator/rasterResample.ts) — Node 22 strips types, so a dependency-free `.ts` module imports directly; `geojsonImport.ts` needs the esbuild helper because of its extension-less imports). Averaging class codes invents classes.
- **Only the DATA layers go in the board.** The worker's `loadState` SKIPS an attribute the payload does not carry, so `state` / `burnTimer` are omitted and keep their defaults — which IS the starting configuration, at no file size.
- **`colors` is shipped for real** (computed from the default viewer's palette): `applySimulationState` gates `hasGrid` on `state.colors != null`, and shipping the buffer the app itself would write makes the first frame right on every compile target before any colour pass runs.
- The **backdrop** is rendered at the land cover's native 10 m resolution (3× the grid) with the hillshade bilinearly upsampled, and the **shade is quantised to 48 levels** — invisible on screen, and it cut the PNGs from 251/308 KB to **120/143 KB**.
- Both models set `gisTools: true`, a real `georef`, and a default viewer whose palette is **alpha 0 for the untouched classes** so the backdrop reads through (measured: 50.6 % of the Recife board is fully transparent).

### Two silent-failure traps these models hit (worth knowing before authoring a graph in a script)
- **The Color→Attribute event root's node type is `inputColor`, NOT `inputMapping`.** An unknown `nodeType` is silently DROPPED from the flow walk — no compile error, no root found, and the brush simply does nothing. `compileAll` reported zero errors; only running the real `paint` message in the app caught it.
- **`_port_<id>` only works on a port that declares an `inlineWidget`.** Group Counting's `Compare To` has none, so `_port_compare: '2'` was ignored and the count silently fell back to `> 0`. Wire a `getConstant` instead. (`statement.y`, `arithmeticOperator.y`, `setAttribute.value` and `getRandom.min/max` DO have widgets and are fine.)
