## N-Dimensional Lookup Tables + Seeded Randomization (Accretor) — branch `sim_agent_fixes`

Generalizes the 2-axis `lookupTable` attribute to **N axes** (1..6) + a seeded random table fill, so rule-table CA families are authorable — flagship: the **Accretor** CA (Driessens & Verstappen), a 3D accretion automaton whose rule is `Rule[state, faceCount, edgeCount, cornerCount] → newState` (a 4-axis table). Impact map + plan: [docs/IMPACT_MAP_ND_LOOKUP_TABLES.md](docs/IMPACT_MAP_ND_LOOKUP_TABLES.md) / [PLAN_ND_LOOKUP_TABLES.md](docs/PLAN_ND_LOOKUP_TABLES.md) (+ `.html` mockup). **All additive** — the legacy 2-axis path is byte-identical (proven by [scripts/check-compile-identity.mjs](scripts/check-compile-identity.mjs): 23 library models, every compile surface unchanged), no `.gcaproj` migration.

### The design — lower to a flat dense read, one emit story on all six surfaces
A 2-axis table already compiles to a flat array read `row*colCount+col` everywhere; N-D is the same flat read with `Σ idxₖ·strideₖ` — **zero new runtime machinery** (the table regions in WASM memory / varAux / auxF32 are already flat + size-agnostic). Emit branches on mode inside each emitter, so a legacy table emits its exact pre-N-D code (byte-identical) and only axes-mode gets the new path.
- **Schema** ([types.ts](src/model/types.ts), all optional): `LookupKeySource += { kind:'intRange', min, max }` (integer-range axis — labels `String(min)..String(max)`, the natural kind for neighbour-count axes); `LookupAxis = { name?, source }`; on a lookupTable `Attribute`: `axes?: LookupAxis[]` (present ⇒ axes mode, supersedes rowKeySource/colKeySource), `tableData?: number[]` (dense row-major over `axes`, length = Π dims), `tableRoll?: { seed, density, max? }` (informational — seeds the editor Randomize fields; `max` = the 1..max integer value range, stored only for integer-valued tables and also consumed by the Overseer `randomizeTable` dep so a runtime re-roll of an integer table reproduces the editor's value policy). Preset capture: `SimulationState.lookupTableData?: Record<attrId, number[]>` (the axes-mode sibling of `interactionTables`).
- **`resolveAxes(attr, model)`** ([variegation.ts](src/modeler/vpl/compiler/variegation.ts)) is the new single source of truth for axis geometry (`{ axes:{name,labels,dim}[], dims, strides, mins, total }`); a legacy table resolves as N=2 with identical numbers, so all the old `resolveKeyLabels` call sites migrate to ONE helper and can't drift. Also new there: `normalizeLookupTablePayload` (dims-aware sibling of `normalizeLookupTable`), `buildLookupTablePayload` (the ONE worker-payload builder — legacy ships labels+values, axes-mode ships `dims`/`mins`/`data`), `randomFillTableData` (THE shared seeded xorshift32 fill — editor + Overseer), `remapTableDataAxis` / `remapTableDataForAxesChange` (the structural cascades). Caps: `MAX_LOOKUP_AXES=6`, `MAX_INT_RANGE_SPAN=4096`, `MAX_LOOKUP_TABLE_ENTRIES=1048576`.
- **Table Lookup ports** ([LookupInteractionNode.ts](src/modeler/vpl/nodes/LookupInteractionNode.ts)): static max-6 `axis_0..axis_5` integer inputs, sliced/relabeled per the referenced table by the **shared shaper `applyLookupAxisPorts`** (consumed by BOTH CaNode + effectivePorts — the buildExtraSlotPorts dual-consumption pattern; the expression-node static-port-slice discipline). Legacy tables keep `labelA`/`labelB` (existing wires never move); axes-mode hides those + shows the axis names. `compile.ts` pre-resolve bakes `_dims`/`_mins` (comma-joined strings — NodeConfig is scalars-only) parsed by `lookupNodeDims`/`lookupNodeMins`.
- **Emit** (JS / WASM / WebGPU lattice + agent WASM/WebGPU): axes-mode = per-axis **saturating clamp** `clamp((axisₖ|0) − minₖ, 0, dimₖ−1)` + the row-major multiply-add. Legacy = raw (no clamp), byte-identical. Layout regions (`wasm/layout.ts interactionTableOffsets`, `webgpu/layout.ts` varAux, `agentEngine.ts` lookupTableOffset, `agentWebgpu/layout.ts` auxF32) all carry `dims`/`mins` and size Π dims via `resolveAxes` (the layout-lockstep single-resolution rule). `interactionTableMap` (Table Map) supports **N=2 axes only** (its shape is two parallel index arrays; N>2 → validation badge + empty output). **Fixed a pre-existing agent-WebGPU bug** in the same emitter: it read ports `'row'`/`'col'` instead of the def's `labelA`/`labelB`, so it always read the clamped [0,0] cell.
- **Worker** ([sim.worker.ts](src/simulator/engine/sim.worker.ts)): `InteractionTablePayload`/`UpdateLookupTableMsg` gain `dims`/`data`/`mins`; init + `updateLookupTable` normalize via `normalizeLookupTablePayload` (view sized Π dims). **THE load-bearing worker fix**: the worker's `computeMemoryLayout` lookupTables input MUST size a multi-axis region by `dims` (a multi-axis payload's rowLabels/colLabels are EMPTY → the old `t.rowLabels.length||1` path reserved **1 cell**, truncating the whole table to `tableData[0]` AND desyncing every offset baked into the WASM module — the model compiled + round-tripped its table but ran inert, growing 0 cells). Legacy tables take the unchanged rowLabels/colLabels path.
- **Editor**: [AttributesPanelContent.tsx](src/modeler/panels/AttributesPanelContent.tsx) — an **Axes-mode select** (Rows×columns ↔ Multi-axis) with explicit one-shot conversions (legacy→multi flattens tableValues→tableData; multi→legacy for N=2 rebuilds the sparse map), `LookupAxesEditor` (name + source per axis, **append / remove-LAST only** — never reorder, the multi-attr-slots discipline: storage + node ports are positional), `KeySourceField` gains **Integer range** (min/max). [LookupTableEditor.tsx](src/modeler/panels/LookupTableEditor.tsx) — a multi-axis **slice view** (the LAST two axes span the grid — deterministic vs. row-major storage; outer axes get prev/next+select steppers) reusing the per-valueType cell widgets, + the **Randomize block** (Seed + 🎲 reroll, Density, integer Max) shared by both modes via `randomFillTableData` (legacy fills the sparse map, axes-mode fills tableData; `tableRoll` metadata records the roll). Live during a sim run (the simulator right-panel editor carries tableData/tableRoll through `handleInteractionTableEdit`).
- **Cascades** ([ModelContext.tsx](src/model/ModelContext.tsx)): axes-mode structural `tableData` remaps — tag rename/reorder on a referenced tag axis, own-axes edits (intRange grow/shrink/shift + custom renames, via label-name matching), removed tag attr collapses its axis to `single` — all via the shared `remapTableData*` helpers.
- **Randomize is design-time** (writes `tableData` into the model, saved in `.gcaproj`, reproducible; same seed+density+shape ⇒ identical table on any machine). The Overseer **`ovRandomizeTable`** node (plan PR4) is the runtime-only sibling for automated rule-space search — re-rolls the WORKER's table without dirtying the model (like a slider), journaling each {seed, density}; see the Overseer node-family section.

### The Accretor sample ([scripts/gen-accretor.mjs](scripts/gen-accretor.mjs) → `public/models/Accretor.gcaproj`)
**300³** constant-boundary 3D grid (27M cells — practical because the model ships with **Skip Isolated Empty Cells** ON: empty attr `state`, empty value 0, range = radius-1 chebyshev, which provably covers the rule since growth requires faceCount ≥ 1; verified byte-identical to the full loop at a fixed RNG seed, inits ~1.9 s, ~10 gens/s), tag `state` (empty/A/B), **three neighbourhoods** (faces 6 / edges 12 / corners 8 as explicit `coords3d` + same-length 2D projections). The rule is a 4-axis Lookup Table (State intRange 0..2 × Faces 0..6 × Edges 0..12 × Corners 0..8 = 2457 entries, `valueType:'tag'` → `valueTagAttributeId:'state'`), pre-rolled by the script's inline copy of `randomFillTableData` (seed **318**, density **0.13** — chosen by a seed search for a rule where BOTH the random-asymmetric AND the mirror-symmetric seed grow a substantial structure to the edge ~50 gens; `tableRoll` lets the user re-roll in the editor). Step graph: `state==0` gate → 3× `getNeighborsAttribute → groupCounting(greater, compare defaults 0 = count occupied)` → `faces≥1` gate → `lookupInteraction(state,f,e,c)` → `setAttribute(state)`; a sibling edge-stop branch reads the `border` cell attribute → `AND(occupied)` → `stopEvent` (pauses when the structure reaches a border). Standalone Output Mapping: empty → alpha 0 (voxel-culled), A green / B magenta via `categoricalColor` + alpha `(state!=0)*255`. Linked frequency indicator (trackedValues A,B).
- **GRID-VOLUME-INDEPENDENT seeding via TWO init roots** (both compute from the LIVE grid dims, so a simulator Resize re-centres/re-detects everything — NO baked centre/bounds): (1) a **per-cell Init Event** flags the `border` cell attr (a new bool the step reads) via the folded coord `dblₖ = |2·coord − maxₖ|` (arithmeticOperator `*2` → `− max` → `abs`; INTEGER — no `floor` node, arith has none — `= maxₖ` only at coord 0 or maxₖ, so `dblₖ >= maxₖ` on any axis ⇒ an outer face); the Stop Event fires when a `border` cell becomes occupied. (2) a **[Grid Init Event](src/modeler/vpl/nodes/GridInitEventNode.ts)** (`gridInit`, runs ONCE) scatters the seed: `Loop(SEED_N=60) { getRandom offset ∈ [−3,3]³ + value ∈ {A,B}; Set Cell (at Position) at centre+offset }` — the centre = `width/2` etc. from the gridInit `width`/`height`/`depth` outs.
- **Symmetric vs asymmetric seed** via the **`symmetricSeed` bool MODEL attribute** (a live toggle — flip it + Reset). ASYMMETRIC writes only the primary point. SYMMETRIC additionally writes the point's **7 other octahedral mirror cells** (a `conditional(symmetricSeed)` gating 7 more `Set Cell` nodes) with the **SAME** value — the mirror coord is `(dim-1) − primary` (reflect across the TRUE grid centre `(W-1)/2`; mirroring across `W/2` is off by ½ and only ~37% symmetric). Because the value is drawn ONCE per loop iteration and reused across all 8 writes, the seed is BOTH **random** (`getRandom` re-rolls every Reset — the RNG stream advances across Resets) AND **mirror-symmetric** → the structure grows symmetric. This is the whole point of moving the seed to the Grid Init Event: **a once-run event can draw one random value and mirror it — a per-cell event fundamentally cannot** (mirrored cells run at different points in the per-cell RNG stream, so they'd never match; the old per-cell shell `(dblX+dblY+dblZ) mod 3` was symmetric but NOT random). Verified in the real worker (JS + WASM): asymmetric grows to the edge (re-rolls each Reset); symmetric grows to the edge with **100% mirror-X/Y/Z + 100% point symmetry** AND re-rolls each Reset (two Resets → different seeds, both 100% symmetric); 24³ (resized) → seed re-centres. `getRandom` integer supports negative `min` (`floor(rand·(max−min+1))+min`), and RNG nodes are loop-pinned (drawn fresh each iteration).
- **Ships an Overseer Rule Explorer** (`overseerConfig.enabled`, seedPolicy `'fixed'` so the centre seed is constant across the sweep and the series isolates the RULE): `Clear Series → forEachInArray(ovSweepValues [8 known-good seeds]) { ovRandomizeTable(rule, seed=element, density 0.13) → ovResetBoard → ovRunUntilStop(600) → ovCollectSample(accreted ← Read A + Read B) → ovLog }` — the automated "re-roll until something interesting grows" workflow; each seed is journaled (reproducible in the editor). Verified: 8 seeds → a rule→size histogram.
- **Verified end-to-end in the real worker** — JS: asym grows to the edge + re-rolls each Reset, sym 100%-octahedral + re-rolls; WASM (default): sym 100%-mirror + edge-stop; the multi-axis rule compiles on JS/WASM/WebGPU. Legacy Chromatography (2-axis) unregressed.

## Particle Life (samples + matrix-play UX — branch `Improvements`)

The classic Particle Life sandbox ([sandbox-science.com/particle-life](https://sandbox-science.com/particle-life); source verified against their `SandboxScience-master` repo) as TWO shipped library samples (**Particle Life** 2D + **Particle Life 3D**, [scripts/gen-particle-life.mjs](scripts/gen-particle-life.mjs) — ONE parameterized builder emits both), plus the enabling features that make "playing with the interaction matrices" first-class. Plan + mockup: [docs/PLAN_PARTICLE_LIFE.md](docs/PLAN_PARTICLE_LIFE.md)/`.html`.

### The model (faithful to their force law)
- Agents-only (`gridCells:false`), torus; `species` = an agent TAG attribute (K=6) keying **THREE asymmetric species×species float lookup tables**: `rules` (∈[−1,1] — the matrix), `attractMin` (per-pair repulsion-core radius, rolled 3..6), `attractMax` (per-pair range, rolled 8..16). **rmin/rmax are PER-PAIR TABLES in Particle Life, not scalars.**
- Force per neighbour at distance d (their `particleComputeForces.wgsl` exactly): `d < minR → repel·(d/minR − 1)` (always repulsive, rule-independent); `d < maxR → tent` peaking `rule` at `(minR+maxR)/2`, zero at both ends; accumulated along the torus-shortest offset. Graph: Get Nearby Agents(queryRadius ← model attr) → For Each → Get Agent Offset → 3× Table Lookup → 2× Compare + 2× valueSwitch + Expressions → Apply Force.
- Integration: **graph-side friction** (Get Velocity → `v·f` → Set Velocity, `f` = a bounded model attr ⇒ a live slider) + engine `momentum: 1.0` ⇒ `v = f·v + (Δt/η)·ΣF` — their `v += F·k; v *= friction` family. Engine physics OFF (Particle profile, collision off, `maxBonds:0`, `useBondingPhysics:false`, `repulsionStiffness:0` + `bondStiffness:0` so `clampAgentDt` keeps `dt = timeStep = 1`). Spawn: Agent Init → Loop (**Count wired** from model attr `N`) → Create Agent(rand·worldW, rand·worldH[, rand·worldD]) → random species → Add To World; `N` applies on Reset.
- Sliders: `N` / `forceFactor` / `repel` / `friction` / `queryRadius`. Tuned defaults (browser-measured): forceFactor 0.05, friction 0.8, repel 1.5 → vmax ≈ 2 units/step → species-sorted clusters (density 1.6× uniform; same-species neighbour fraction 0.40 vs 0.17 null). **`queryRadius` must stay ≤ `neighbourQueryRadius` (24, the hash ceiling) and ≥ the attractMax roll range** — a wired query radius above the config ceiling silently misses far pairs (documented in the model description; no validation yet). 4 presets = named matrices (`interactionTables` on `rules` only) ported from their `rulesGenerator.ts`.
- Verified: all six agent compile surfaces; JS↔WASM bit-parity (parity harness globs both samples → permanent coverage); WASM gate+instantiate; WebGPU behaviour+force shaders device-compile 0 errors (2D+3D); browser ~110 steps/s at 1800 agents (real worker), 3D spans the full volume, 0 NaN. NB the gen script mints fresh node ids per run, so re-running it churns compile-identity hashes for these two models only (expected, like every gen script).

### Three latent compiler parity bugs it surfaced (all fixed)
1. **`compileAgentGraph` never ran the lookup-table geometry pre-resolve** — Table Lookup / Table Map on the AGENT graph baked `_colCount` = 1, so the JS agent emit indexed `row·1+col` and read the WRONG cells of any multi-column table (WASM/WebGPU resolve dims from the layout and were right — JS was the broken target). Fix: `preResolveLookupTableNode` extracted to module scope in [compile.ts](src/modeler/vpl/compiler/compile.ts), called by BOTH the cell pre-resolve and `compileAgentGraph` (cell side proven byte-identical). No shipped sample had used Table Lookup on the agent graph.
2. **`getAgentOffset.distance` emitted `Math.hypot` on JS** vs the WASM emitter's `f64.sqrt`-of-squared-sum — hypot is correctly-rounded, so Distance consumers diverged by ULPs (bit-parity broken). JS now emits `Math.sqrt(dx*dx+dy*dy[+dz*dz])` in the WASM op order. Boids' emitted text changed as a dead const only (it never wires Distance). **Rule: agent JS emits must never use `Math.hypot` — match the WASM associativity.**
3. **`getCurvature`** had the same hypot pattern (fixed via the spawned follow-up task + a permanent bonded-population parity synthetic).

### Matrix-play UX (the enabling features)
- **Signed/ranged Randomize** (`tableRoll.rangeMin`/`rangeMax` + `TableFillPolicy.rangeMin/rangeMax`): float tables roll uniform in [Min, Max) — signed ranges (−1..1) are the Particle Life rules matrix. Absent range ⇒ **bit-identical** to the historical (0,1) draw (proven in [scripts/test-ndtable.mjs](scripts/test-ndtable.mjs)); the Overseer `ovRandomizeTable` runtime re-roll reads the stored range (mirrors the integer `max` policy).
- **Lookup-table axes + value-tag sources bind AGENT tag attributes**: `resolveKeyLabels` / `resolveValueTagOptions` ([variegation.ts](src/modeler/vpl/compiler/variegation.ts) `findTagAttrById`) search `model.attributes` THEN `agentAttributes` (cell/model wins on collision) — all six compile surfaces + the worker payload inherit from the one resolver. `KeySourceField` + the value-tag dropdown offer agent tag attrs when the Agents topology is on. The UPDATE/REMOVE_ATTRIBUTE lookup-table cascades were extracted into shared helpers (`remapLookupTableForTagChange` / `detachLookupTableFromRemovedTag` in [ModelContext.tsx](src/model/ModelContext.tsx)) now ALSO invoked by UPDATE/REMOVE_AGENT_ATTRIBUTE — species renames/reorders/removals remap all three tables.
- **Matrix-play view** ([LookupTableEditor.tsx](src/modeler/panels/LookupTableEditor.tsx), both call sites — Attributes panel + the simulator **LEFT**-panel Model Attributes section): float tables default to a diverging-color grid (red = repel / cyan = attract over dark neutral, |value|/scale = saturation; scale = the declared roll range else the live data extent), **horizontal drag-on-cell** adjust (range/150 per px, clamped), click select + Ctrl multi-select, a shared slider editing the selection or ALL cells (their "All Types"), hover value tooltips, `# Values` toggles back to the NumberField grid. Square 2-axis tables add **Fill pattern** ([src/model/matrixGenerators.ts](src/model/matrixGenerators.ts) — seeded xorshift32 ports of their generator catalogue: uniform/symmetric random, snake, rock-paper-scissors, chains, bipartite, hub-and-spokes, shells, anti-symmetric swirl, dimers, triad flocks) + Zero/Symmetrize/Transpose/Negate/Mutate. Editor-only (compilers untouched, byte-identity green); edits stream live via the existing `updateLookupTable` path. Symmetric tables show + edit the mirrored cells in matrix view (writes go through the same mirror rule).

## Ant Necrophoresis — the discrete, mass-conserving rebuild (branch `improvements`, 2026-07-28)

The shipped sample was **rebuilt from scratch** ([scripts/gen-ant-necrophoresis.mjs](scripts/gen-ant-necrophoresis.mjs)). The original was reported as nonsensical and it was: `corpse` was a FLOAT field, pick-up/drop were `affectCellsUnder` **add/subtract 1 over an r = 0.8 disk under a FRACTIONALLY-positioned agent** (so a pick could take 1 from each of several cells and a drop add 1 to a different number of cells), and pick-up was gated only on the neighbourhood MEAN — never on the cell actually holding a corpse. So it subtracted from empty cells (negative densities), created mass on every mismatched pick/drop pair, and rendered as a smeared decimal cloud that grew past what was seeded. There was no discrete item, no conservation, and no cell-level pick/place.

### The rebuilt design — conservation is STRUCTURAL, not tuned
**The invariant: `corpses on the grid + corpses being carried = constant`.** Four load-bearing choices:
- **`corpse` is an INTEGER cell attribute holding 0 or 1** — a discrete item, never a density. The linked Output Mapping spans 0..1.
- **Ants live on EXACT INTEGER cell positions.** They are spawned at integer cells by the Agent Init Event (`floor(u·W)`, `floor(u·H)` via Get Grid Dimensions, so it is grid-size independent) and moved one cell per step by **Set Agent Position** with a hand-written torus wrap (`(x+dx) − floor((x+dx)/W)·W`). The engine integrator is inert (`customForcesOnly`, `momentum 0`, no forces/growth/bonds, `agentCapabilities.motion:'static'`), so its unconditional `xNext = wrap(x + v)` pass just re-writes the same integer — **but it MUST run**, because `swapPositions` commits `xNext` over `x` every step, so a Set-Position write would otherwise be reverted. **Because the position is exactly integral, an `r = 0.5` disk covers EXACTLY ONE cell** (own cell at distance 0; the 4-neighbours at 1 > 0.5) — that is what makes Read/Affect Cells Under a single-cell read/write instead of a blob. (Contrast the old **deposit-radius gotcha**: at a FRACTIONAL position radius 0 writes NOTHING and ~0.71 writes 1–4 cells depending on the fraction.)
- **Both writes are `set`, gated on the opposite cell state**: pick-up requires `cell == 1` and writes `set 0`; drop requires `cell == 0` and writes `set 1`. `set` (not add/subtract) means the field is structurally confined to {0, 1}; the gates mean every write is a genuine transfer. Each ant carries ≤ 1 corpse (`carrying` bool agent attr).
- **The agent target is WASM (and the grid WASM too) — a deliberate exception to the library compile-target policy.** The one-corpse-per-transfer guarantee relies on the **SEQUENTIAL** agent loop (JS/WASM): a second ant on the same cell reads the field AFTER the first ant's deposit. A parallel WebGPU dispatch reads a snapshot, so two ants could both claim one corpse (~1 same-cell pair per step at 120 ants on 6400 cells) and slowly manufacture mass. The grid stays WASM because the cell rule is EMPTY (corpses don't move on their own) — a WebGPU grid would add a per-gen field-bridge round-trip for nothing.

Rule (Deneubourg et al. 1991 / Bonabeau et al.), with `f` = the occupied FRACTION over the sensing disk (`readCellsUnder` mean of a 0/1 field): empty-handed on a corpse → `P(pick) = (k1/(k1+f))²` (falls with density); carrying on an empty cell → `P(drop) = (f/(k2+f))²` (rises with density). Autocatalytic → cemeteries. Live model attributes: Ants / Seed Density (both apply on Reset) / Sense Radius / k1 / k2. A linked TOTAL indicator "Corpses on ground" makes the conserved pool visible (it can only ever dip by at most the ant count).

### TWO cross-target compiler defects this model surfaced (BOTH NOW FIXED IN THE COMPILER)
The model was first reshaped to avoid them; the compiler was fixed afterwards — see **"Agent-compiler branch-scope + RNG-order fixes"** for the root causes, the fixes and the permanent regression synthetics. The shapes were:
1. **RNG DRAW ORDER diverged between the JS and WASM agent compilers** — JS sink-analysis hoisted a draw whose uses sat at agent-loop top into the pre-flow value block (topo order) while WASM emitted at the flow use site, so a graph with a draw inside a branch plus a draw after it advanced the shared `_rs` stream in a different order per target and every downstream decision diverged. (Local Variables did NOT help: `setVariable` pins the assignment, not where JS emits the `getRandom`.)
2. **A value used BOTH inside a branch AND after it was emitted INSIDE the branch by the JS agent compiler** → `ReferenceError: _v… is not defined`. Two shapes: a `valueSwitch` feeding a `setAttribute` inside the `then` AND the post-conditional colour; and a `getVariable` read consumed in BOTH branches force-emitting its shared pure input (`readCellsUnder`) into the FIRST branch.

**The model keeps its defect-free shape on purpose** (it is also the better model): ONE random draw per agent per step, split into a direction index `k = floor(u·9)` and the leftover fraction `roll = u·9 − k`; and a colour index computed purely as `c + act·(1−2c)` rather than reusing the branch's value or re-reading the attribute after the write. Re-reading an attribute after a write in the same step is still not advisable — it depends on hazard pinning agreeing across targets.

The decision is therefore **BRANCH-FREE**: one roll, one probability (`valueSwitch` on carrying), one cell test, one `AND`, one conditional whose body does the transfer — instead of two mirrored branches.

### Verified
`scripts/parity-agent-wasm.mjs` **JS↔WASM bit-parity ✓ on all samples**; `scripts/check-agent-wasm-gate.mjs` GATE✓ COMPILE✓ INST✓. **Real worker, WASM grid + WASM agents, in-browser**: seeded 778 corpses + 120 ants; at **generation 42 002** the field held 767–768 corpses with 10–11 carried — **TOTAL exactly 778, unchanged**, `nonBinary` cells **0**, `fractionalPos` **0** (ants still exactly on integer cells after 42k moves), 120 alive, 0 worker errors. Clustering deepened over the same run: mean occupied-Moore-neighbours per occupied cell **0.96 (random baseline) → 2.72 @ gen 2k → 4.64 @ gen 42k**, densest 5×5 patch **24 of 25 cells** — real cemeteries. (Composited pixels were not eyeballed — the Browser pane was occluded; the "Corpses on ground" indicator read 768, matching the measured field.)
