## Indicators (Implemented)

### Architecture:
- Three kinds: **Standalone** (typed scalar, graph-writable), **Linked** (auto-computed from cell attributes) and **Graph** (GRA P6 — a graph-global measurement of the bond-graph AGENT population; see "Graph Indicators" below)
- Standalone indicators support all types: bool, integer, float, tag — stored as JS numbers in `_indicators` object
- Linked indicators aggregate cell attribute arrays: Frequency (count per value) or Total (sum)
- Both kinds have Accumulation Mode: per-generation (reset each step) or accumulated (running total, reset on simulator reset)
- **X-axis** (linked only): `generation` (default — classic time-history) or `rows`/`columns` (a live **spatial histogram** = chromatogram; see Spatial Indicators below). Standalone indicators are Generation-only (a graph-written scalar has no spatial extent).

### Indicator Nodes:
- `GetIndicatorNode` (value, `'data'`): reads `_indicators[<slot>]` — **any indicator whose value is a SINGLE NUMBER**, not just standalone (see "Reading a computed indicator from a rule" below)
- `SetIndicatorNode` (flow, `'output'`): writes `_indicators[indicatorId] = value` — **standalone only** (a linked/graph value is COMPUTED from the model; writing it would be overwritten next generation)
- `UpdateIndicatorNode` (flow, `'output'`): modifies based on type — Bool: toggle/or/and; Int/Float: increment/decrement/max/min; Tag: next/previous. **Standalone only**, same reason.
- All three have teal color `#00695c`

### Reading a COMPUTED indicator from a rule (Get Indicator; user-reported gap, 2026-07-31)
**`Get Indicator` reads standalone, linked-`total` AND scalar graph metrics** (`nodeCount` / `edgeCount` / `meanDegree` / `maxDegree` / `componentCount`) — so a rule can feed a measurement back into itself ("stop dividing past N nodes", "modulate by mean degree"). It previously listed **`kind === 'standalone'` only**; every shipped agent/GRA model has ONLY graph + linked indicators, so on those models the picker was empty but for "Select…", the node could never be configured, and it compiled to `_indicators[-1]` — reported as *"get indicator is not working on agents rule graph canvas"*. The COMPILE path was never broken (verified working on all three agent targets); the node simply could not be pointed at anything the model had.
- **[indicatorValue.ts](src/model/indicatorValue.ts) is the ONE shape rule** — `indicatorScalarBlocker(ind)` returns null (readable) or the reason it is not. **Frequency maps, degree histograms and spatial curves are NOT readable** (no single value), and they render as **DISABLED dropdown entries carrying that reason** rather than being omitted — silent omission is exactly what hid this gap. Shared by the picker (CaNode), the badge (`detectMissingConfig`) and IndicatorDisplay's scalar/frequency chart branch, so "what the UI offers" and "what the engine can deliver" cannot drift.
- **ZERO compiler change ⇒ all six surfaces by construction.** The emit is `_indicators[<slot>]` where `<slot>` is the indicator's INDEX IN `model.indicators` regardless of kind, and `cachedIndicators` is one f64 slot per indicator. The worker's **`syncComputedIndicatorScalars()`** mirrors every computed result that is a `number` into its slot — the RESULT's runtime shape is the classifier, which is exactly what the predicate encodes. Standalone slots are never touched (the graph owns those). Both WebGPU indicator uploads were widened from `standaloneIds` to the full `indicatorSlotById` map so the GPU sees the same values (a frequency indicator's slot stays 0, as before).
- **FRESHNESS — one generation stale, exactly like `density`.** The value a rule reads is the metric as of the END of the previous generation. **`refreshRuleReadableIndicators()`** runs at the tail of EVERY generation (after the structural phase = the settled graph) in both `runAgentStep` and `runAgentStepWebGPU`, gated on **`rulesReadComputedIndicator`** — a macro-aware scan of BOTH rule graphs (`Get Indicator` is universal) threaded through init/recompile, mirroring `agentUsesDensity`. **Without the gate the refresh would be once per BATCH, so at 20 gens/frame a rule gating on `nodes (N)` would read a number up to 20 generations old — a silent coupling between a DISPLAY throughput setting and rule semantics.** `graphResultsFreshForSend` stops `sendColors` recomputing the metrics a second time in the same generation, so the gated path costs ONE compute per generation, not two. A model that only CHARTS its graph metrics keeps P6's once-per-batch schedule and pays nothing new.
- **Verified in the real worker on ALL THREE agent targets**: a rule copying `edges (E)` into an agent attribute reads the value an independent recount from the bond store produces — **6/6 single-generation steps exact**, and **4/4 ten-generation batches exact** (measure E after generation 9, step the 10th, read: the rule saw E-after-gen-9 exactly, including a batch where E grew 163 → 354, which a per-batch refresh would have read as 163). Real UI on the user's own `Cubic GRA`: the Agents-canvas picker lists nodes (N) / edges (E) / max degree as selectable and the degree histogram disabled with its reason; selecting one clears the amber badge. Guarded by [scripts/test-get-indicator.mjs](scripts/test-get-indicator.mjs) (36 checks: the shape rule, the badge, slot-is-the-index on JS/WASM/WGSL, and that the GRA models had ZERO standalone indicators under the old rule). 29 models byte-identical.
- **Open follow-up**: reading ONE CATEGORY of a frequency map (what the Overseer's `ovReadIndicator` does via a `category` config) — five shipped models (Chromatography, Golly-style, GoL Replicate Statistics, Kelp War, snake) have only frequency/spatial indicators and so still expose nothing a rule can read.

### Compiler Integration:
- `_indicators` parameter added after `activeViewer`, before optional `order` in `buildLoopParams`, `buildCellParams`, and output mapping params
- Step function loop-wrapped: `_indicators` is a shared object across all cell iterations within a single step — enables accumulation patterns

### Worker Integration:
- `cachedIndicators: Record<string, number>` — mutable during step function execution
- `standalonePerGenIds` — per-generation indicators reset to defaults before each step
- `computeLinkedIndicators()` — iterates typed arrays after each step (frequency, total, with float binning)
- `computeSpatialIndicators()` — the spatial (rows/columns) sibling: bins each cell by position and aggregates per bin using the SAME per-type branches; writes `Record<seriesKey, number[]>` into `linkedResults` (see Spatial Indicators)
- `linkedAccumulators` — running state for accumulated linked indicators
- Indicator values included in `stepped` message as `indicators: Record<string, number | Record<string, number> | Record<string, number[]>>` (the `number[]` arm carries spatial series)
- `initIndicators()` called on init, `resetIndicators()` on reset
- `updateIndicators` message rebuilds indicator state when definitions change

It's a controlled child: `mode`/`selectedId`/`onSelect` from the Indicators panel's bare-id selection slot.
- Standalone: type selector, default value (type-specific), tag options editor
- Linked: attribute dropdown (cell attrs only), aggregation (type-dependent), **Value Bins** (float + frequency only — renamed from "Bin Count" to disambiguate from spatial bins), **Track Categories** (bool/tag frequency only — a checkbox checklist to chart a SUBSET of category values), **X Axis** (Generation/Rows/Columns), and when spatial: **Bin Mode** (Slices/Absolute) + Number of Slices / rows-per-bin
- Both: accumulation mode radio, watched toggle, delete button
- **Track Categories / `Indicator.trackedValues?: string[]`** (bool/tag frequency only; absent/empty = all): filter the per-category frequency map to a chosen subset so a dominant category doesn't flatten the rest on the shared chart Y-axis. Applied at ONE point — `sendColors` in [sim.worker.ts](src/simulator/engine/sim.worker.ts) (message assembly, post-aggregation) — so it uniformly covers JS-embedded / WASM-worker / WebGPU-reduced results AND generation + spatial axes; integer/float frequency (dynamic/range keys) and `total` (scalar) are untouched. UI = `TrackCategoriesEditor` in `IndicatorsPanelSection`; full/empty selection stores `undefined` (track all). SimulatorView threads `trackedValues` through BOTH the `init` and `updateIndicators` worker payloads (the worker `IndicatorDef` + internal `linkedDefs` both carry it).

### Simulator UI:
- `IndicatorDisplay` component in right panel below brush controls
- Scalar values (standalone, linked total): single numeric display + sparkline chart (always-mount-wrapper pattern — see Key Patterns)
- Frequency maps (linked frequency): three viz modes cycled via a header button — **Bars** (`IndicatorDisplay` inline bar chart, current gen only), **Lines** (`IndicatorMultiLineChart`, one coloured line per category over time), **Stack** (`IndicatorStackedAreaChart`, cumulative-sum bands). Preference persists per indicator via `indicatorVizModes: Record<id, 'bars'|'multiline'|'stacked'>` inside `genesisca_sim_settings` localStorage.
- **Legend click-to-hide (Lines/Stack/Spatial)**: clicking a legend entry dims/hides that series (line-through + opacity 0.4); click again to restore. Runtime, display-only state `indicatorHiddenCategories: Record<indicatorId, Set<category>>` owned in `SimulatorView`, persisted in `genesisca_sim_settings` as `Record<id, string[]>`, threaded via `IndicatorDisplay` to all three multi-series chart components (`IndicatorMultiLineChart` / `IndicatorStackedAreaChart` / `IndicatorSpatialChart`) via `hidden` + `onToggleCategory` props. The charts skip hidden series in the scaling + draw loops (Stack recomputes its cumulative bands + yMax from visible series only; Lines + Spatial rescale Y over visible). `colorFor()` keys the palette by the design-time series position (see "Stable series palette indexing" below), so hiding one series never recolors the others. **Distinct from `trackedValues`** (Track Categories): `trackedValues` is a design-time, model-level filter applied in the worker (changes which data reaches the chart); legend-hide is a per-session UI toggle (NOT saved into `.gcaproj`).
- **Chart settings (gear popover) / `Indicator.chartSettings?: IndicatorChartSettings`** — per-indicator chart display config: `yMin`/`yMax` (fixed axis bounds; absent = dynamic, each bound independent), `yTicks` (2–11 tick labels incl. min+max), `seriesColors` (per-category hex overrides; scalar charts use the single key `'value'`). TWO layers, field-level merge (override wins, colors merge per key): model-level DEFAULTS on the Indicator (edited via `ChartDefaultsEditor` in `IndicatorsPanelSection`, design-time-enumerable categories only — scalar `'value'`, bool `false/true`, tag options; numeric freq buckets are runtime-only) and simulator-side OVERRIDES (`indicatorChartOverrides: Record<id, IndicatorChartSettings>` in SimulatorView, edited via the ⚙ `ChartSettingsPopover` in `IndicatorDisplay` with runtime series keys, persisted in `genesisca_sim_settings` AND serialized into `SimulationState.indicatorChartOverrides` under "Simulator controls"; `applySimulationState` restores wholesale). Shared helpers in [indicatorChartSettings.ts](src/simulator/indicatorChartSettings.ts): `mergeChartSettings`, `applyAxisOverrides` (applied AFTER the 6% dynamic pad), `tickCount`, `drawIntermediateYTicks`, `hasFixedAxis` (charts clip data drawing to the plot rect when an axis bound is fixed — samples may fall outside the user's window), `chartSettingsKey` (redraw-effect dep). All four chart components take a `settings?: IndicatorChartSettings` prop (the EFFECTIVE merge); their `colorFor(idx, cat)` consults `seriesColors[cat]` before the index-keyed palette, so an override never recolors other series.
- **Stable series palette indexing (Track Categories fix)**: `designTimeSeriesKeys(ind, model)` (moved to [indicatorChartSettings.ts](src/simulator/indicatorChartSettings.ts), shared by the modeler's `ChartDefaultsEditor` AND the simulator charts) is the canonical design-time series order — scalar `'value'`, bool `false/true`, tag options (sorted, matching the charts' key sort); numeric freq buckets are runtime-only → `[]`. SimulatorView memoises `indicatorCategoryOrders: Record<id, string[]>` from it and threads it into `IndicatorDisplay` → the three multi-series charts + the gear-popover swatches as `categoryOrder`. Each chart's `colorFor(idx, cat)` now prefers `categoryOrder.indexOf(cat)` over the runtime `idx`, falling back to `idx` only for runtime-only keys. So **unticking a Track Categories value no longer shifts the surviving series onto different palette slots** (the bug was: filtering changed the runtime index, recoloring everything). Legend-hide (above) was already safe because it skip-draws rather than reindexes.
- History shape in `SimulatorView.indicatorHistoryRef` is polymorphic: `number[]` for scalars, `Record<category, number[]>` for frequency maps. Capped at 500 samples per series.
- `chartExpandedRef` is populated by `IndicatorDisplay`'s render-phase ref-compare notification. Do NOT reset it in `initWorker`'s useEffect — that runs AFTER the child's render and wipes the populated set, so the first stepped messages collect no history (symptom: scalar sparklines stay blank until manual collapse/expand).
- Eye icon per indicator toggles `watched` state
- Spatial indicators (`xAxis` rows/columns/layers) render `IndicatorSpatialChart` (per-series over position bins) — bypasses the scalar/freq branches. They have their OWN 2-state **Lines ⇄ Bars** style toggle (curves vs a per-bin histogram; multi-series bars overlay semi-transparent), stored in the SAME persisted `indicatorVizModes` slot (`'bars'` = bars, anything else = lines; `onSetVizMode` sets it directly — the 3-mode freq cycle doesn't fit a 2-state flip). Their ⌫ clear renders DISABLED with an explanatory tooltip (a spatial chart redraws from the current generation — no history to clear). **Header-control visibility is DEFINITION-based** (`isFreqDef`/`isScalarDef` from `kind`/`linkedAggregation`/`xAxis`), NOT value-shape-based — the viz-mode/clear buttons show from load instead of only after the first step delivers a value (the val-shape `isFreq`/`isScalar` still drive the chart rendering itself). `IndicatorDisplay` takes `gridWidth`/`gridHeight` props (live dims) to label the X-axis with real row/column positions.

### Spatial Indicators (chromatogram X-axis — purely a measurement/visualization layer):
- A spatial indicator plots value **per position bin** along the grid's `rows` or `columns` axis instead of over `generation` — reproducing the chromatogram plots in the Kier chromatography/enantiomer papers (population vs column position, one curve per species). **No graph nodes, no compiler changes, no per-cell position read** — it's one extra CPU pass in the worker, opt-in per linked indicator.
- **Why linked-only:** spatial binning = "scan all cells, bin each by position" = a cell-aggregation, which is exactly what linked indicators already do. Standalone indicators (a single graph-written scalar) have no spatial extent and stay Generation-only.
- **Data shape:** the per-step value is `Record<seriesKey, number[]>` — each array indexed by **position bin** (length = bin count). Each value-bucket the linked path already produces becomes a **series** (a curve): bool → `true`/`false`; tag → one per option (the chromatogram's per-species curves); integer freq → one per distinct value; integer/float **total** → single `total` (per-bin sum); float freq → one per **value-bin** (2-D value×position histogram). color/neighborIndex unchanged.
- **Two distinct bin counts — don't conflate:** `binCount` = **value** bins (float frequency only); `spatialBinCount` (slices mode) / `spatialBinSize` (absolute mode) = **position** bins. Only float+frequency uses both (value-bins → series, position-bins → array index).
- **Schema** (`Indicator`, all optional, additive — no migration): `xAxis?: 'generation'|'rows'|'columns'`, `spatialBinMode?: 'slices'|'absolute'` (default slices), `spatialBinCount?` (slices; default 50, clamped [2, axisLen]), `spatialBinSize?` (absolute; rows/cols per bin, default 1 → B = ceil(axisLen/size)).
- **Worker** (`computeSpatialIndicators` in [sim.worker.ts](src/simulator/engine/sim.worker.ts)): mirrors `computeLinkedIndicatorsFromBuffer` (same per-type branches + sub-attr parent-match guard) but bins by `row = ⌊i/width⌋` / `col = i % width`. `linkedDefs` carry the xAxis + bin config; `hasSpatialIndicators` gates the per-step call. Writes `linkedResults[id]` as `Record<key, number[]>`.
- **Buffer/timing (the critical gotcha):** called **post-step, after the buffer swap/copy**, so `readAttrs` holds the just-computed generation on JS (ref-swap) AND WASM (w→r copy) — the same buffer a later `getState` reads, which is what makes the parity check exact. On WebGPU it runs inside `finalizeStepWebGPU` after the attrs readback; spatial source attrs (and their parents, for sub-attrs) are force-added to `watchedAttrIds` so the selective readback always pulls them even when a sibling generation-axis indicator on the same attr is GPU-reduced.
- **Never accumulated:** spatial is always a live per-step snapshot (the accumulation loop + history collection both skip it; SimulatorView detects array-valued entries structurally). End conditions exclude spatial indicators (a spatial value isn't a scalar/category count); the end-condition target dropdown filters them out.
- **WebGPU:** spatial indicators are CPU-only — `buildReductionPlan` ([webgpuReduce.ts](src/simulator/engine/webgpuReduce.ts)) skips any `xAxis` rows/columns def.
- **Verified** (tsc + cross-target parity): per-bin series match an independent `getState` re-bin with 0 mismatches and sum-of-bins == per-value total, on JS (columns) / WASM (rows) / WebGPU (rows), both slices and absolute modes.

### Graph Indicators (GRA P6 — the agent tier's measurement layer)
The third `Indicator.kind`, `'graph'`: a **graph-global** quantity over the bond-graph agent population. GRA research is "roll a rule, measure what it did, keep the seed" — GenesisCA already had the SEARCH half (seeded table Randomize + the Overseer's sweep / replicate statistics / journal / CSV export); this is the MEASUREMENT half. **It has ZERO compiler presence** — nothing in a rule graph writes it, so `check-compile-identity` is untouched (26 models byte-identical) and there is no per-target emit.
- **Schema** (additive, no migration): `IndicatorKind += 'graph'` + `Indicator.graphMetric?: string` (absent ⇒ `nodeCount`; typed as a string in [types.ts](src/model/types.ts) so it stays engine-import-free — the canonical union is `GraphMetric`).
- **[src/simulator/engine/graphMetrics.ts](src/simulator/engine/graphMetrics.ts)** is the SINGLE implementation, shared by the worker (fed a live `AgentStore`) and [scripts/verify-graph-rewrite.mjs](scripts/verify-graph-rewrite.mjs) (fed a `getState` payload, then recounted INDEPENDENTLY — the exactness oracle). It takes the same NORMALISED view the harness's `decodeAgentGraph` produces, so a live store and a `getState` payload are interchangeable.
- **Metrics**: `nodeCount` (O(1) — `liveCount`), `edgeCount` (**IS invariant I1** — `Σ bondCount / 2`, the handshake lemma the harness already checks, so the metric and the invariant validate each other), `meanDegree`, `maxDegree`, `degreeHistogram` (a **frequency map** — keys are the FIXED window `0..maxBonds`, so it renders through the existing bars / lines / stacked charts with **no new chart code**, `designTimeSeriesKeys` can enumerate it, and palette slots stay pinned), `componentCount` (union-find, path halving + union by size; isolated agents count one each). **Measured cost: 2.07 ms at 20 000 agents / 46 247 edges** (the degree pass is 0.87 ms).
- **Work sharing + opt-in cost**: `computeGraphMetrics(view, metrics, passes?)` runs ONE O(N) degree pass covering edge/mean/max/histogram and the union-find ONLY when `componentCount` is asked for. The worker's `computeGraphIndicators()` returns on `graphDefs.length === 0` **before touching the store**, so a model with no graph indicator pays nothing — proven, not asserted, by the DEV `__graphIndicatorStats` probe (Boids: 200 generations / 40 batches ⇒ `calls 0, degreePasses 0, componentPasses 0`).
- **Where it computes**: in `sendColors` (the ONE message-assembly point) — after the batch's structural phase, so the reported graph is the SETTLED one, and mutation tails (reset / paint / seed / load state) refresh it too. Results ride the SAME id-keyed `indicators` payload, so every existing consumer works unchanged: chart history (value-shape driven), end conditions, and the Overseer's `O.indicator` (hence **`ovReadIndicator` needed no Overseer change** — a frequency-shaped metric takes a category exactly like linked-frequency).
- **Freshness on the WebGPU agent target (verified, not assumed)**: every field read (`alive`/`liveCount`/`bondCount`/`bondPartner`) is CPU-AUTHORITATIVE on all three targets — the behaviour shader writes `agentAlive` only under `usesSpawn` (reconciled by `readbackAgentStep` every generation on the per-gen path) and, since P3, writes only bondStore ATTRIBUTE lanes (`bondAttrWord = 2 + i`, never word 0 = partner). The ONE path that can leave the CPU mirror stale — the resident batch — requires `maxBonds === 0 && !usesSpawn` (`agentResidentEligible`), so nothing the metrics read can have changed during it.
- **UI**: a "+ Graph" button in the Indicators panel list, gated on `topologyMode.agents` (an EXISTING graph indicator still edits if agents are later turned off); a Graph Metric dropdown + per-metric hint in the detail panel; **Accumulation is HIDDEN** for the kind (a graph metric is an instantaneous measurement, not a per-step quantity to sum — hidden rather than shown-and-inert); a `G` badge in the simulator, `GRAPH` in the list.
- **`Indicator.kind` proved extensible** (P6 §5 assumption 1): every value-shape-driven path (history collection, chart rendering, `O.indicator`, end-condition evaluation) works unchanged; the `kind`-switch sites that would have defaulted to the LINKED branch were cosmetic/affordance only and are all fixed — the list badge, the simulator `S`/`L` badge, `designTimeSeriesKeys` (a graph SCALAR used to fall through and return `[]`), `isScalarDef`/`isFreqDef`, the `ovReadIndicator` category widget + validation, and the end-condition category widget. **When adding a fourth kind, those are the sites to sweep.**
- **Sample**: `Graph Metrics - Growth Sweep` ([scripts/gen-graph-metrics-sweep.mjs](scripts/gen-graph-metrics-sweep.mjs)) — see the GRA section's sample list.

### Manual Brush (runtime-only Input Mapping):
- Special "Manual" tab that always appears as the rightmost entry in the right-panel brush mapping strip, alongside the model's color-input mappings. Renders even when the model has zero color-input mappings (also auto-selected on load in that case). Does NOT appear in the Modeler's Mappings tab — it's purely a simulator UX layer with no model-schema counterpart.
- Selecting Manual swaps the color picker for a `<ManualBrushPanel>` (one row per cell attribute: `[Set checkbox] [name + sub-attr hint] [type-appropriate widget]`). Widgets reuse `InlineNumberInput` / `InlineBoolSelect` / `InlineTagSelect`; **neighborIndex** attributes use the `NeighborIndexValuePicker` grid widget (the same cell-matrix picker the Model Attributes panel uses — hint neighborhood resolved via `neighborhoodHintId`, dr/dc fallback inputs when no hint) instead of a raw packed-i32 number field, so picking a neighbour is a click on the offset grid. `ManualBrushPanel` takes `neighborhoods` for this. Unchecked rows are dimmed (`.manualBrushWidget.dim` — `opacity: 0.4; pointer-events: none`) and their attribute is skipped at paint time.
- **THE ROW GEOMETRY FOLLOWS THE `.paramRow` DISCIPLINE, and it is shared by THREE consumers** — the cell Manual brush, the agent **Add** seed config and the agent **Edit** config — so a change here lands on all three. The rule used to be `grid-template-columns: auto 1fr minmax(70px, 90px)`, which handed the LABEL every spare pixel and pinned the WIDGET at 90px: **measured at a 470px panel, a name as short as "Radius" took 339px of a 450px row while its field got 90**, a float rendered truncated (`0.40000000596`) and a vector's X / Y fields were **34px each**, with a dead gap between. Now: the **label is a FIXED 120px column** (`flex: 0 0 120px`, ellipsised, with the full name + description on its `title`) — elastic labels would each settle at their own text width and leave the widgets' left edges RAGGED down the panel — and the **widget is the only elastic cell** (`flex: 1 1 140px`), so its width is a function of the PANEL width alone, never of the value. Below ~340px the widget's basis no longer fits the line and the row **WRAPS** it under the label at full width instead of crushing either; a vector row wraps its components the same way (`flex: 1 1 56px`). **Measured after: widget 90 → 179 / 309 / 459px at panel 340 / 470 / 620, vector components 34 → 78 / 143 / 219, and a 170-sample sweep (5 panel widths × 8 values × 5 checkbox toggles) shows 0px of row-geometry drift and 0 horizontal overflow.** The `dense` variant (the image-mapping dialog) is untouched — its overrides reset both flex values, so it still packs a content-sized label + an 88px widget hard left.
- Worker protocol: `paintManual` message — `{type: 'paintManual', cells: [{row, col}], sets: [{attrId, value}], activeViewer}`. UI pre-encodes string values into typed-array numerics via `encodeAttrValue()` in `src/model/attrValueEncoding.ts` (shared with worker's `defaultValue()`/`boundaryCellValue()`). Bypasses any compiled `InputColor` function. Worker handler mutates `readAttrs[attrId][idx]` directly (plus `writeAttrs[...][idx]` in sync mode for next-step consistency), works on JS, WASM, and WebGPU targets without per-target code paths — WebGPU branch readbacks attrs first when `gpuOwnsAttrs && needs parent-match read`, then patches per-cell via `patchWebGPUCells(idxs, writtenAttrIds)` — the WRITTEN-attribute subset, so the touched cells' other attributes keep their live GPU values instead of reverting from the stale CPU mirror (see the stale-mirror-revert bullet in the GeoJSON section).
- Sub-attribute semantics: **per-cell skip**. For each sub-attr being Set, the worker computes the cell's *effective* parent value — the brush's parent value if the parent is itself in `sets` (`brushParentOverride` Map), else `readAttrs[parentId][idx]` — and suppresses the write when that value isn't in `parentValues`. Mirrors the schema's iteration semantics. `parentValueToInt` is now exported from `subAttribute.ts` for the worker to share.
- State: `manualBrush: Record<attrId, {enabled, value}>` in SimulatorView, persisted per-model in localStorage under `genesisca_manual_brush_v1:<model.properties.name>` (separate from the global `genesisca_sim_settings`; NOT saved into `.gcaproj` / `.gcastate` — Manual Brush is per-user UX). Signature-keyed merge effect (`cellAttrSig = "id1:type1|id2:type2|..."`) re-derives state when the attribute SET changes; live name/description edits don't reset values. New attrs seed `{enabled: true, value: defaultValue}`; deleted attrs vanish; type-changed attrs reset.
- Flush plumbing: `flushPaintBatch` ([SimulatorView.tsx](src/simulator/SimulatorView.tsx)) branches on the `MANUAL_BRUSH_MAPPING_ID` sentinel, snapshots `manualBrushRef.current` AT FLUSH TIME (so widget edits during a drag take effect mid-stroke), encodes values via `encodeAttrValue()`, posts `paintManual`. The existing mid-drag mapping-change flush path piggybacks on the sentinel — swapping in/out of Manual flushes correctly.
- Suppressed in Manual mode: Shift+RMB color popover (no color to set), Open Image button (image import requires a color mapping — disabled with explanatory tooltip), and the "Shift+RMB color" hint string. Ctrl+wheel cycle includes Manual as the rightmost entry.

### End Conditions & Stop Events:
- `ModelProperties.endConditions?: { enabled, maxGenerations?, indicatorConditions? }` — optional auto-pause rules evaluated on the main thread in `SimulatorView.evalEndConditions` after each `stepped` message; pauses play and shows a blue info notice.
- `IndicatorEndCondition.category?: string` — for linked-frequency indicators the comparison is `frequencyMap[category] <op> constant`. UI branches per linked attribute type: bool/tag → dropdown, integer → number input, float-binned → disabled with warning (bin keys aren't knowable at design time).
- Stop Event node compiles to a write into a shared `_stopFlag` Uint32Array (+ `layout.stopFlagOffset` for WASM). Worker reads the flag after every `runStep`, clears it at the top of each step, surfaces the message via a `stopEvent` message. Main thread pauses + shows the same blue notice. `stopMessages: string[]` passed via init/recompile; Stop Event config.`_stopIdx` is 1-based so 0 means "no stop requested".
- Saved state (.gcastate / embedded in .gcaproj) restores the grid configuration only. `generation` resets to 0 and indicators re-init on load — saved files represent starting configurations, not run snapshots. `serializeSimState` skips generation/indicators/linkedAccumulators on write; loader ignores them on read (back-compat with older files).
