### Agent brush KINDS — Editor vs Spawner (branch `polishing`)

*"The Input Mapping brush can only be used to edit existing agents?"* An AGENT Colour→Attribute
mapping now declares **`brushKind: 'editor' | 'spawner'`** (`Mapping.brushKind`, **ABSENT ⇒
`'editor'` ⇒ the historical behaviour, so there is NO migration** and `check-compile-identity` is
29 models unchanged — nothing shipped uses agent input mappings).

- **THE TWO SHAPES.** **Editor** runs the graph ONCE PER AGENT the footprint covers, with that
  agent as `self`. **Spawner** runs it ONCE PER BRUSH APPLICATION with **no self**: its root
  additionally exposes **`Brush X` / `Brush Y` / `Brush Radius`** (+ `Brush Z` in 3D) and the graph
  CREATES the agents itself (Create Agent → set-by-handle → Add Agent To World), distributing them
  however it likes. That is the shape an editor structurally cannot express: with nothing under the
  cursor an editor runs ZERO times, so "click empty space to add agents *this particular way*" has
  nowhere to hook.
- **`inputBrushKindOf` ([inputMappingParams.ts](src/model/inputMappingParams.ts)) is the ONE
  reader of `brushKind`** — the `inputParamsOf` / `resolveMaxBonds` discipline. A value outside the
  union resolves to `'editor'` (the SAFE arm — the kind that has a self), and a CELL `inputColor`
  root is ALWAYS editor (a lattice brush is per-cell; there is no spawner counterpart), enforced in
  `inputBrushKindForNode` rather than left to callers.
- **ONE root node, reshaped by the mapping** — deliberately NOT a second root type, so every
  existing wire, badge, drag payload and picker keeps working. `buildInputParamPorts` PREPENDS the
  brush ports for a spawner, and BOTH consumers (`CaNode` + `effectivePorts`) get them from that one
  builder (the dual-consumption rule).
- **ABI: a FIFTH kind, `spawner` = `init` + the brush block + `_killRequest`.** Mirroring `init`
  (not `input`) is what gives it the grow-only spawn closures and no `idx`/`_alive`/`highWater`;
  **`_brushZ` rides the TRAILING 3D block**, not with its x/y, so *2D stays a strict PREFIX of 3D* —
  the invariant `audit-agent-layout` asserts. `buildAgentSpawnerParams` ↔ `buildAgentSpawnerArgs` is
  the FIFTH ABI mirror; the worker's DEV arity assert branches on the SHIPPED `spawner` flag and
  sizes each kind from ITS OWN arg builder (an editor-sized spawner is exactly the desync that pair
  exists to catch).
- **The EDITOR kind gained the lifecycle verbs too** — the `input` ABI now carries
  `_agentCreate` / `_agentAddToWorld` / `_agentMaxAgents` + `_killRequest`, so an editor brush can
  spawn agents AROUND the one it painted and remove agents. Both kinds' spawn closures are
  **grow-only** (`makeBrushSpawnClosures`, the behaviour-graph precedent): a Create appends at
  `highWater` and never reuses a free-list hole, so a slot freed by a Kill EARLIER IN THE SAME
  APPLICATION can never be handed straight back out. A Created-but-never-Added handle is swept.
- **⚠ THE KILL SEMANTICS, decided deliberately: DRAINED IMMEDIATELY, not next generation.** A paint
  is a user gesture BETWEEN generations, so deferring the death to the next structural phase would
  mean "I clicked erase and nothing happened until I pressed Play" — and on a PAUSED model, never.
  `drainBrushKillRequests` runs at the tail of both handlers, `freeAgentSlot`-ing each flagged agent
  (breaking every bond both ways + bumping the slot epoch, exactly as the structural phase does) and
  CLEARING the flags so a later structural phase cannot see them again.
- **The painted id set is RESOLVED UP FRONT** against the pre-paint population, so an agent the same
  stroke just created is never also painted by it.
- **Worker**: ONE new message **`spawnAgentsBrush { points[], radius, values, mappingId }`** —
  a LIST of points so a drag ships one message per frame (the rAF-batched brush discipline), the fn
  running once per point with `_agentSeedBase` = `highWater` at the start of THAT application. In
  `AGENT_GPU_DEFER_TYPES` like every other agent mutation. Editor paints keep `paintAgentsColor`.
  Each handler REFUSES the other kind's message with a named error rather than running the wrong ABI.
- **Brush UI**: a spawner ignores the brush SHAPE entirely (it gets a centre + a radius, exactly like
  Push/Pull), so the shape row is HIDDEN and a single **Radius** field replaces it — the
  "an enabled control must do something" rule; the cursor becomes a dashed radius ring + a centre
  `+`, the footprint/area-highlight scans are skipped (a spawner touches no existing agent), and the
  two-click Line staging is bypassed. Its tab is marked `⊕`. 2D AND 3D (the 3D plane-pick cell IS the
  world position, the identity Push/Pull already relies on).
- **Validation**: a spawner root has no self, so the Agent-Init-Event footgun walk was generalised —
  `agentInitSelfOnlyNodeIds` now walks EVERY selfless root (`agentInit` + every spawner
  `agentInputMapping`) and the badge NAMES which one. Kill Agent is spawner-valid when its id is
  WIRED (the lane exists there) and reported when unwired. `SetVelocity` / `KillAgent` /
  `SetAgentSprite` degrade an UNWIRED self-write to a NO-OP in a selfless root rather than emitting a
  reference to an `idx` that does not exist.
- **`agentRootHasSelf` / `agentRootRelaxesGuard` ([types.ts](src/modeler/vpl/types.ts))** replaced
  the eight hand-written `agentRoot === 'init' || 'behaviour'` comparisons across the by-id setters.
  Both are byte-identical for the pre-existing roots; adding a kind is now one edit, not eight.
- **The KIND-SWITCH edge cascade**: `removedRootPortIds` generalises `removedChannelPortIds` over the
  WHOLE root port set, so a spawner→editor flip DESTROYS the brush ports and their wires are DROPPED
  by the same drop-never-repoint rule a deleted parameter follows (editor→spawner only ADDS, so it
  destroys nothing and the graphs are not walked). `UPDATE_AGENT_MAPPING` fires it for `brushKind`
  as well as `parameters`; the CELL branch strips any stray `brushKind` so a hand-edited file cannot
  invent ports a lattice root never rendered. `detectDanglingRefs` had to learn the brush ports too,
  or a legitimate spawner wire reads as a stale channel and blocks the compile.
- **⚠ THE LIVE ROOT PORT SET HAS EXACTLY ONE DEFINITION —
  `rootOutputPortIdsForNode` ([inputMappingParams.ts](src/model/inputMappingParams.ts)), DERIVED FROM
  `buildInputParamPorts`** (the builder CaNode and `effectivePorts` render from), so "what the badge
  and the compile gate consider live" cannot drift from "what the canvas draws". **The bug that made
  it shared** (user-reported, fixed 2026-08-11): the brush-kinds work taught `detectDanglingRefs` the
  spawner geometry but left `nodeValidation`'s `inputParamIssues` testing the declared CHANNELS
  alone — so a spawner mapping that declares NO parameters and merely wires `Brush X` (the whole
  point of the kind: the graph places the agents itself) hit the `channels.length === 0` arm and was
  badged *"This mapping declares no parameters — the wired value outputs do not exist"* while
  compiling and painting perfectly. **A spawner's live set is never empty**, so that message can now
  only fire where it is true (an EDITOR root exposing nothing at all), and a stale wire — including a
  brush port left behind by a hand-edited spawner→editor flip — is still named. Adding a port to a
  root means editing the ONE builder; nothing else enumerates them.
  **⚠ Verified nuance**: the prune lands in the MODEL and STICKS (an editor-kind flip stays pruned
  through a full graph reseed, with no compile banner), but flipping BACK to spawner within the same
  editor session re-renders those wires from React Flow's LOCAL state, which then syncs them back —
  harmless, because the ports exist again, and arguably friendlier (an accidental flip does not
  destroy your wiring).
- **Verified in the real UI** (2D + 3D, WASM + WebGPU agent targets, 0 console errors on a clean
  load): a spawner click posts `{points:[{x:60,y:60}], radius:8, values:[5,2.5]}` and creates exactly
  5 agents inside the radius with `energy = 2.5`; a drag lays a 35-agent trail across the canvas;
  editing the parameter widgets changes the next click to exactly 3 agents at `energy = 77.25`;
  **WebGPU** (chip `⚙ agents WebGPU`) spawns 3 per point around both brush points; **3D** spawns with
  a real z spread around `brushZ`; an **EDITOR** mapping sets `energy = 9` on the 3 painted agents AND
  spawns one each at `selfX + 5` (189 → 192), and with its `cull` parameter at 1 the 3 painted agents
  are **gone immediately with NO step issued** (192 → 192: +3 spawned, −3 killed).
- **Gates**: `check-compile-identity` 29/29 unchanged · `test-agent-abi` 607 → **629**
  (the spawner arg list against an INDEPENDENT expectation, `spawner === init + brush + kill`,
  no-self, the prefix rule for the new kind, and both kinds' arity asserts pinned in the shipped
  source) · `test-param-input-mappings` gained **§12** (the resolver, both port shapes, the cascade,
  the two ABIs, and the two fns RUN against a real `AgentStore` through the shipped closures
  asserting exact positions / attribute values / the drain, with three in-harness NEG controls) ·
  `audit-agent-layout` · `parity-agent-wasm` · `verify-agent-render` · `test-c9-gates` ·
  `test-agent-capabilities` · `verify-graph-rewrite` · `test-geometry-taint` ·
  `test-generation-pipeline` · `gen-capability-docs --check`. **Negative-controlled by SOURCE
  MUTATION**: moving `_brushZ` out of the trailing 3D block fails 4 ABI checks; dropping the spawn
  closures from the `input` kind fails the editor-lifecycle check.
- **⚠ A PROCESS LESSON worth keeping: never `git checkout <file>` to undo a source mutation on an
  UNSTAGED file** — it restores from the INDEX and silently destroys the session's work. (It ate the
  whole `agentAbi.ts` change here; the harnesses had already passed, so nothing failed until the real
  UI showed a spawner fn with no brush block. Copy the file aside and restore from the copy.)

### Agent & 3D-simulator control overhaul (10-part UX/behaviour batch)
Plan + illustrated mockup: [docs/PLAN_AGENT_SIM_CONTROLS.md](docs/PLAN_AGENT_SIM_CONTROLS.md) / `.html`. The lattice (2D + 3D, all 3 targets) and every non-agent model are **byte-identical** — all additive/gated.
- **"Use bonding physics" master toggle** (`CenterBasedConfig.useBondingPhysics?: boolean`, Properties › Bond-Graph Agents). DEFAULT OFF for a freshly-enabled Agents topology (`defaultCenterBasedConfig` seeds `false`) — enabling agents no longer silently turns on the engine soft-sphere repulsion/adhesion + growth. OFF ⇒ agents move ONLY by graph-authored Apply Force / Set Velocity (the "agents that have nothing to do with bonds" case); ON ⇒ the full center-based engine (soft-sphere + bond springs + growth ramp + auto-bond) and the panel reveals the Forces + Bonds rows (progressive disclosure). **`usesBondingPhysics(cfg) = useBondingPhysics ?? !customForcesOnly`** ([centerBased.ts](src/model/centerBased.ts)) — the `?? !customForcesOnly` fallback reproduces EVERY existing `.gcaproj` (absent both ⇒ `!undefined` ⇒ true ⇒ engine on, as before; legacy `customForcesOnly:true`/`false` map exactly) so there is **NO migration**. The worker (`runAgentStep`/`runAgentStructuralPhase`) gates soft-sphere (`engineForces = bonding`), bond springs, growth (`growthRate→0`), and auto-bond on the resolved flag; behaviour-preserving because the custom-force shipped models never used springs/growth/auto-bond anyway. Live recompile field (no `needsFullInit`). The hidden `momentum`/`maxSpeed`/`neighbourQueryRadius`/`timeStep`/`drag` are now surfaced too (an always-shown **Motion** section).
- **Per-layer "Simulate" + "Show" toggles** (the simulator **Layers** panel, docked in the right-side Agents section; runtime settings persisted in `genesisca_sim_settings`, NOT the model). **Simulate** gates `runStep`/`runStepWebGPU` (CA grid) and `runAgentStep` (agents) in the generation loop via a new `setSimLayers` worker message + the module booleans `simulateCells`/`simulateAgents` (default true) — freeze either layer mid-run (freezing agents also stops their cell-field deposit, which lives inside `runAgentStep`). **Show** is render-only (both 2D + 3D): `showCaGrid`/`showAgents` refs gate the DRAW (NOT the upload, so re-enable is instant) — 3D via `Viz3D.voxels`/`Viz3D.agents` in `gl3d.render()`, 2D via skipping the colour blit / `drawAgentsOverlay`. **A `Bonds` Show-only row** (`showBonds`, default ON, persisted like the others) toggles the BOND-LINE display on both paths — 2D gates the batched bond stroke in `drawAgentsOverlay`, 3D gates `renderBonds()` via the new `Viz3D.bonds` flag — and is rendered ONLY when the model's Bonds capability isn't Off (`resolveMaxBonds(model.centerBased) > 0`; bonds can't exist otherwise). Display-only: the bond springs keep simulating.
- **Agent brush DOCKED** (was a floating canvas overlay) — moved into the right-panel **Agents** `rightPanelSection` (gated `isAgentModel`), alongside the Layers toggles. All state/refs/handlers are component-scoped (no plumbing change).
- **Clip plane → clip INTERVAL** ([gl3d.ts](src/simulator/render/gl3d.ts)): `ClipPlane3D.value` → `{ lo, hi }` (world coords). Visible iff `lo ≤ w ≤ hi` — two cuts, the gap = the slab thickness. The 3D-view control is a **single dual-thumb range slider with a draggable band** ([ClipIntervalSlider.tsx](src/simulator/ClipIntervalSlider.tsx), controlled — emits `onChange(lo,hi)` into `clip3d`): drag a thumb to move ONE bound (resize the window); **drag the BAND to "swoop" a fixed-width clip window through the volume** (both bounds shift together, width preserved, clamped at the extents); a bare-track click jumps the nearer thumb. Replaced the two separate From/To `<input type=range>` sliders — more convenient for sweeping a set-width window. (Window-level pointermove/up listeners, not setPointerCapture, so a fast drag off the thin track keeps tracking.) Updated in ALL clipping shaders (voxel FS, voxel-pick FS, sphere FS, **sphere-pick FS** [previously unclipped], the new bond clip) + `setCommonUniforms`/`setSphereUniforms`.
- **Bonds now clip** (req 5): bonds render through the LINE program, which gained a world-pos varying + clip uniforms; `drawLines(..., clip)` applies the interval to the bond pass only (axes/grid/bounds/gizmo/brush-plane pass `null`). `renderBonds` passes the active clip.
- **Agents render ON TOP of the grid VOXELS in 3D — now an OPTION, and only vs the voxels** (req 8, refined in the `sim_agent_fixes` batch): `gl3d.render()` clears the depth buffer between the voxel pass and the bond+sphere pass, then RESTORES the helper overlays' depth (axes / floor grid / bounds / brush plane) via a colour-masked depth-only re-draw of `renderOverlays`+`renderBrushPlane` — so "in front" applies ONLY vs the voxels while a brush plane in front of the blob still occludes the spheres (it used to be swallowed by them). Agents keep depth-sorting among THEMSELVES (`gl_FragDepth`). The whole behaviour is the **"Draw agents in front"** checkbox (3D View panel, **shown only when the model has BOTH layers** — `isAgentModel && gridCellsOn`; on an agents-only model there are no voxels to be in front of and the helper overlays get their depth restored either way, so the toggle is a provable no-op and is hidden, like Cell gaps / Occlusion; default ON = historical; `Gl3DRenderer.setAgentsInFront`; persisted as `genesisca_sim_settings.agentsFront3d`) — OFF gives full normal depth for sparse grids where both layers should interleave.
- **Clip / brush-plane slider maxes track a simulator resize** (req 2): the 3D-View controls derive their dims from the LIVE `gridWidth.current || simWidth` (etc.), not the stale `model.properties.gridWidth` (the Resize button never dispatches `updateProperties`). An effect re-clamps `clip.lo/hi` + `plane.pos` into the new extent on a dims change.
- **Auto-orbit reverses** (req 3): the speed slider min `0.05 → -2` (0 = stopped); `yaw += speed·dt` spins the other way for negative speed.
- **Nearby-agent gathering** (req 9) ALREADY uses a uniform CSR spatial hash (O(N), 3D-aware, all 4 query sites) — the appropriate structure for near-uniform agent density (an octree would regress here). No structural change; only the stale `sim.worker.ts:runAgentStep` "all-pairs O(N²)" doc comment was corrected.
- Verified end-to-end in-browser (zero console errors): Boids agents freeze/unfreeze via Simulate-agents; the bonding toggle hides/reveals Forces+Bonds (Boids resolves OFF, Tissue ON); 3D Tissue clip interval slices voxels + spheres + **bonds** to a thin slab; Show-agents hides agents+bonds; resize depth 40→12 updates the clip max 20→6 (+ re-clamps the stale handle); auto-orbit yaw decreases at negative speed.

### Agent brush parity — shapes · Single/Area · Add/Remove/Edit (branch `polish_agents`)
The agent brush now MIRRORS the CA-grid brush (2D + 3D). Plan + illustrated mockup: [docs/PLAN_AGENT_BRUSH_PARITY.md](docs/PLAN_AGENT_BRUSH_PARITY.md) / `.html`. The lattice + the agent engine/compilers are **UNTOUCHED** — only [SimulatorView.tsx](src/simulator/SimulatorView.tsx) (brush UI + handlers), the `paintAgents` worker handler, and a new `decodeAttrValue` helper — so every simulation behaviour is byte-identical (JS↔WASM agent parity re-verified on all 9 samples; lattice unchanged; the brush is a pure UI layer that posts existing worker messages).
- **`AgentBrushMode` = `add`/`remove`/`move`/`edit`/`push`/`pull`/`glue`/`cut`** (session-only state, NOT persisted → no migration). `seed`→`add`, `kill`→`remove` (the `killAgents` worker message + the `genesisca_agent_seed_v1:` config key KEEP their names — the rename is UI-only). The built-in mode buttons are **ICONS** ([brushIcons.tsx](src/simulator/brushIcons.tsx)) with the mode name on their `title` + `aria-label` — see "Brush icons" below.
- **Shapes** — new agent-brush shape state (`agentBrushShape` + `agentBrushW/H/RingWidth/LineWidth`; circle/ring radius reuses `agentBrushRadius`), persisted in `genesisca_sim_settings`. The agent world is CONTINUOUS, so the footprint is a **world-unit GEOMETRIC test** (`agentShapeMetrics` + `shapeContains` + `agentsInShapeAt` + `agentSeedInShape`), NOT the cell stamp the CA-grid brush uses: rect = centred W×H box, circle = disc, ring = annulus |d−r|≤w/2, line = a two-click capsule (`agentLineMembers` / `agentSeedInLine`). Shape selector + adaptive size row in the panel (reuse `styles.brushShapeBtn`/`fieldRow`). The 2D cursor draws the shape outline as the negative-`difference` silhouette (Area scope) or the hovered-agent ring (Single scope).
- **Single / Area** — `agentBrushScope` is **DERIVED from the brush SIZE, NOT a toggle** (the old `[agentBrushScope, setAgentBrushScope]` state + persisted key + the Single/Area button pair were removed): `agentBrushShape === 'rect' ? (W > 1 || H > 1 ? 'area' : 'single') : shape === 'line' ? 'area' : (radius > 0 ? 'area' : 'single')`. So a **zero-size footprint** (circle/ring radius 0, rect 1×1) = **Single** (exactly one agent — Add-one at the cursor / Remove-nearest via `pickAgentAt` / Move-one / Edit-clicked); a **sized footprint** = **Area** (the whole footprint). It's a plain derived `const` in the render (the `agentBrushScopeRef` syncs to it each render, so the paint handlers read the current value); a **`scopeBadge`** (an uppercase Single/Area pill with `marginLeft:auto`) is rendered on the size row so the user sees the current mode next to the number. **The Shape + size rows are placed BEFORE the mode-button row** (define the brush, then pick the action). Line is always Area (a drawn segment; the move+line single override is separate). **Area-move = rigid group drag**: `agentGroupMoveRef` grabs the footprint's agents + the grab world-point at pointer-down, then each drag posts `moveAgents` with `start + foldedDragDelta` per agent (`pendingMovesRef` generalised to an array). The Shape/size block is hidden for Glue/Cut/Bond (inherently two-agent / area-scan). Single-Add places one per click (no drag-stream); Single-Remove drag-erases the nearest.
- **ADD: the seed RADIUS, the packing DENSITY, and the DRAG STEP** — the three settings that decide *what* an Add lays down and *how much of it*.
  - **The Add config carries a synthetic `Radius` row** (`AGENT_SEED_GEOM_ATTR_SPECS`, reusing the Edit panel's `GEOM_RADIUS` id and its Body-capability gate, so a bodyless model shows no row rather than an inert one). **`SeedAgentsMsg.agents[].radius` has ALWAYS existed** (`seedAgents` → `initAgentSlot`) — the main thread simply never filled it in, so a seeded agent could only ever get the model's `defaultRadius`. **So this needed ZERO worker/engine change and lands identically on every agent target and in both dimensions**: `seedAgentsAt` is the ONE funnel (every 2D and 3D Add path — click, drag, the two-click Line — reaches it), and it reads the row at FLUSH time (the Manual Brush's own rule, so a mid-stroke edit applies to the rest of the stroke). **An unchecked row sends NO `radius` field at all**, leaving the worker applying `cbNum(centerBased, 'defaultRadius')` exactly as before — a disabled row is a true no-op, never a guessed value. Velocity is deliberately NOT offered (a momentum-0 model wipes an initial velocity the same step, and the Edit brush already writes it), and position comes from the brush.
  - **DENSITY IS A PACKING FRACTION, NOT AGENTS-PER-UNIT²** (`agentSeedCount`): `n = packing × extent / (2√3·r²)` in 2D and `/ (4√2·r³)` in 3D — the area/volume one disc/sphere owns at the densest lattice packing — so **1.0 = close-packed at the seed radius** and the number means the same thing at every brush size and every agent size. The old formula ignored the agent radius entirely, so one setting gave a sparse dusting for small agents and a solid overlapping mass for large ones (**measured: at the same brush + density, radius 1.2 → 23 agents vs radius 2.5 → 3 in 3D; 0.4 → 91 vs 1.5 → 6 in 2D**). It is a **slider + a fixed-width number** (the `.paramRow` geometry rule in miniature: `.brushSlider` is the only elastic part, `.brushNumber` is fixed at 62px so a digit-count change reflows nothing) over `[AGENT_SEED_PACKING_MIN 0.02, 1]`, with the formula on its `title`. The radius it divides by is the Add config's Radius row when ticked, else the model default (`agentSeedEffRadiusRef`; `agentSeedRadiusOverrideRef` is the separate `number | undefined` that rides the message). **`AGENT_SEED_MAX_POINTS` (4000)** caps ONE stamp, so a huge footprint at a tiny radius cannot lock the main thread building an array the agent ceiling would reject anyway.
  - **⚠ `agentSeedPacking` is a NEW persisted key, deliberately** — it REPLACED `agentSeedDensity`, whose stored number is meaningless under the new rule; an old session starts from the new default (0.25) rather than inheriting a number that would seed a wildly different count. The stale key is neither read nor written, so the first settings save drops it.
  - **"Spacing" was NOT inert — its NAME was lying, so it was RENAMED to "Drag step"** (the key + behaviour are unchanged). **Measured before touching anything**: over a 20-world-unit drag, spacing 2 → 100 agents, 6 → 40, 20 → 10, i.e. exactly the `1 + floor(dist / spacing)` stamp cadence in the `mousemove` handler. It is invisible on a CLICK (which is what made it read as dead) and it is the only guard against a drag dumping one stamp per pointermove — so deleting it would be a regression. What the user actually wanted from a control called "Spacing" (agents that do not stack) is what the packing-fraction Density now delivers.
- **Edit mode** — reuses `ManualBrushPanel` (a THIRD instance) over `model.agentAttributes` PLUS synthetic geometry rows (ids `__geom_radius__` / `__geom_vx|vy|vz__` / `__geom_x|y|z__`; Z rows only in 3D), assembled by `agentEditPanelAttrs`. State `agentEditAttrs` keyed off `agentAttrSig` (NOT `cellAttrSig`), persisted under `genesisca_agent_edit_v1:`. **Single**: click an agent → `editPrefillIdRef` + `getAgentState` → `decodeAttrValue` prefills the panel VALUES (keeping the user's per-row `enabled` toggles) + highlights the target (`editTargetId`) → the **Apply** button writes to it. **Area**: click/drag the footprint stamps the checked rows onto every agent under it. `buildAgentEdit` splits enabled rows into `sets` (attrs via `encodeAttrValue`) + a `geom` object.
  - **⚠ THE PREFILL IS SHORTENED FOR DISPLAY (`formatSeedNumber`)** — agent state round-trips through **f32** on the WebGPU target, so a radius the user set to `0.4` comes back as `0.4000000059604645` and a position as `31.788856506347656`: unreadable in the row's field, and precision f32 never carried (both measured on the shipped path). The rule is *the shortest string that is EXACT in f64 (so a clean `12.5` is untouched), else the shortest that round-trips the same f32, else the full value* — never a lossy guess. It applies to float attributes, the synthetic geometry rows and each component of a vector row. Safe because rows are OPT-IN: an untouched row is never written back, and an enabled one writes the shortened value, which IS the f32 the engine already holds.
- **Worker (the ONE protocol change)** — the existing **`paintAgents`** IS the Edit primitive: `sets` is now OPTIONAL and it gained `geom?{radius,vx/vy/vz,x/y/z}` + `torus?` (radius → `radius`+`targetRadius`; velocity; position via the `moveAgents` `x`+`xNext` wrap/clamp discipline; the `vz`/`z` fields gated on `worldDepth>1`). #### Agent brush: Push / Pull replace Bond (branch `updates`)
The `bond` brush mode (drag a disc, auto-glue every pair inside it already within `formDistance × contact`) was **REMOVED** — it only ever did anything on a bonded model, needed the agents to already touch, and Glue covers the deliberate case. In its place two modes that work on **every** agent model and give a *physical* way to interact with a running population: **Push** / **Pull**. Plan + illustrated mockup: [docs/PLAN_AGENT_PUSH_PULL_BRUSH.md](docs/PLAN_AGENT_PUSH_PULL_BRUSH.md)/`.html`.
- **The law.** For each live agent within `radius` of the brush centre, `d` = torus-shortest distance: `falloff = 1 − d/radius` (1 at the centre, 0 at the rim) · `step = intensity · dt · falloff`; push `x += step·outward`, pull `x −= min(step, max(0, d − deadR))·outward` with **`deadR = 0.01·radius` — a DEAD-ZONE ring pull stops at** (the `min` stops an overshoot; the dead-zone stops CONVERGENCE onto one exact point: coincident agents have no separation direction and feel identical forces, so stacking them onto the centre LOCKED them in place — each agent now halts on its OWN angle of the 1%-radius ring, keeping positions distinct by construction; an agent already inside `deadR` is skipped, not expelled), then wrap (torus) / clamp (bounded). **Contrast Move**: Move translates a whole SHAPE footprint rigidly by the drag delta; Push/Pull act over a RADIAL disc with a magnitude that depends on closeness, and keep acting while the button is held even if the cursor never moves.
- **`Intensity` is WORLD UNITS PER SECOND at the centre** and the SENDER pre-multiplies by the frame `dt` (clamped to 100 ms) — without that a 144 Hz display would push 2.4× faster than a 60 Hz one for the same setting. Persisted as `agentNudgeIntensity` in `genesisca_sim_settings` (default 10).
- **POSITION ONLY — no velocity kick (deliberate).** A kick would feel more like a force but it ACCUMULATES: at momentum 0.9 a sustained hold converges to ~10× the per-frame step, and at momentum 1.0 (Particle Life) boundedness depends entirely on the model's own graph-side friction. A displacement is well defined for every Motion mode (`static`/`velocity`/`force`), every momentum value and every compile target — the same contract Move already has. The write is `x` AND `xNext` (the `moveAgents` discipline; writing only `x` lets the next position commit snap the agent back).
- **ONE worker message, ONE handler, every target**: **`nudgeAgents { x, y, z?, radius, strength, torus, activeViewer }`** (`strength` SIGNED — `+` outward = push, `−` inward = pull — and already dt-scaled). It mutates the CPU agent store exactly like `moveAgents`, so **JS / WASM / WebGPU all work by construction**, and it joins **`AGENT_GPU_DEFER_TYPES`** (deferred during an in-flight GPU readback + sets `agentGpuUploadPending`, so a resident batch re-uploads the nudged positions). **2D and 3D share the handler** — `z` is read only when `worldDepth > 1`, and the 3D brush passes the plane-picked cell (the agent world IS the grid frame 1:1). An agent EXACTLY at the centre has no outward direction: push gives it a DETERMINISTIC golden-angle direction from its id (a 2D angle / a Fibonacci-sphere direction in 3D) so a pile on the cursor still explodes outward reproducibly; pull leaves it (inside the dead-zone ⇒ `move = 0`).
- **A LOOP, not a per-pointermove post** (`startNudgeLoop`/`stopNudgeLoop`/`nudgeTickRef`, shared by the 2D and 3D handlers): the press starts an rAF loop that posts at most ONE message per frame from the last cursor centre; a drag only re-aims `nudgeCenterRef`. So holding still keeps pushing and a 1 kHz pointer stream cannot flood the worker. Released on pointer-up (2D `handleMouseUp`, 3D `onUp` via `active === 'agentNudge'`).
- **They ignore the brush SHAPE** — a radial force needs a centre and a radius, so `NUDGE_BRUSH_MODES` always act over a plain disc (2D) / ball (3D) of `agentBrushRadius`; the panel shows **Radius + Intensity** instead of the shape row. **Because the shape is fixed, Ctrl+LMB-drag becomes TWO-AXIS in these modes: horizontal → Radius, vertical → Intensity (UP = stronger).** `agentsInRadiusAt` / `agentsInRadius3dAt` (originally Bond's scan collectors) SURVIVE as the effect-region collectors for the highlight.
  - **Both resize state machines take a dedicated FIRST branch** (`isResizingBrush.startIntensity` in the 2D `handleMouseMove`, `resizeStart.intensity` in the 3D gl-canvas `onMove`) that runs *before* the per-shape chain, so the selected shape is irrelevant — a ring-shaped brush in Push drags radius+intensity and leaves the ring width alone. That branch REPLACED the old `'circle'` substitution, so every other mode's per-shape math is byte-unchanged. Radius keeps the shared `round(dx / 5)` feel; intensity goes through `nudgeIntensityFromDrag` (below), with the sign convention every other secondary axis uses (up = more).
  - **THE VERTICAL AXIS IS MAGNITUDE-PROPORTIONAL, NOT LINEAR** (`nudgeIntensityFromDrag`, 2026-08-07 — the user reported *"why clamp to 200? I have been using it to 1000 even"*). The ceiling is **`NUDGE_INTENSITY_DRAG_MAX` = 10000**, i.e. four decades, and the shipped `start − round(dy / 5)` would have needed **50 000 px** to cross it while making the low end hypersensitive. The drag now moves in **`u = ln(1 + v / NUDGE_INTENSITY_FLOOR)`** space (`log1p`/`expm1`, floor **1**), stepping `u` by `−dy / NUDGE_INTENSITY_EFOLD_PX` (**150 px per e-fold**) and clamping `u ≥ 0`:
    - `v ≫ floor` ⇒ `du = dv / v`, so a fixed pixel travel is a fixed **RELATIVE** change — **measured ×2.74 at 100 and ×2.72 at 1000 for the same 150 px**, i.e. genuinely the same feel at every magnitude (10 px ≈ ±7% anywhere: 10→11, 1000→1069).
    - `v ≪ floor` ⇒ `du ≈ dv / floor`, a fixed **ABSOLUTE** step. **That linear floor is the whole reason for the `+1`**: a pure `v · exp(−dy/K)` can neither REACH 0 (it approaches asymptotically) nor ESCAPE it (`0 × e = 0`). Measured: 400 px down from 10 lands exactly on **0**, and 50 px up from 0 gives **0.4**. Full 0→10000 travel is **1382 px**; 10→10000 is 1022 px — one long gesture, and gestures COMPOSE because the law is relative (verified round-trip: 10 → 80 → 10 exactly).
    - Rounding is **one decimal below 10, whole units above** (`NumberField` here has no `integer` prop, so decimals commit), which keeps 1–20 finely adjustable without showing `1069.3` at the top.
  - **ONE ceiling, shared by the field and the drag** — `NUDGE_INTENSITY_DRAG_MAX`(10000) is the panel `NumberField`'s `max`, the drag clamp (via the shared `clampNudgeIntensity`), AND the clamp on the persisted value at load. Without the load clamp a legacy `agentNudgeIntensity` above the cap would be SNAPPED DOWN by the first pixel of a retune drag; without the field `max` a typed value could sit outside the range the drag can express. **Ctrl+LMB opens a resize, never a nudge**, so a drag retunes the NEXT hold rather than one already in flight.
- **Visuals**: the cursor is the effect ring — **SOLID for Push, DASHED for Pull** — plus 8 radial ticks with a chevron at the leading end (outward / inward), on the negative-silhouette layer; every agent inside the disc is ringed (**amber** push / **teal** pull) through the same area-highlight path Remove/Move/Edit use. 3D draws the volumetric ball outline + the same per-agent rings.

A value typed into the PANEL has no pointer event behind it, so a small effect (`[agentNudgeIntensity, agentBrushRadius]`) schedules a **cursor-layer-only** redraw — otherwise a parked cursor kept showing the previous footprint.

### FOLLOW MODE — the camera tracks an inspected agent (2D + 3D, 2026-07-29)
The natural extension of the inspect machinery: a PINNED agent inspector's header carries a **`◎` toggle** ([InspectAgentPopover.tsx](src/simulator/InspectAgentPopover.tsx) — `following` + `onToggleFollow` props, `.followBtn`/`.followBtnActive` in `InspectCellPopover.module.css`), and while it is on the camera tracks that agent. **RENDER/UI layer only** — the tracker writes the SAME camera state a manual gesture writes (2D `panRef`, 3D `cam.target`) and then calls `draw()`, so the direct-render camera message, the cursor overlay and the E2 composite all follow for free. Zero engine / worker / compiler change (`git diff --stat` = the popover, its CSS, and SimulatorView).
- **State**: `followAgentId` + `followAgentIdRef` + `setFollowAgent` / `cancelFollow` (+ a `cancelFollowRef` mirror so the 3D pointer effect's stable dep array never re-registers). **The ref LEADS the state** — the same rule `openAgentInspector` documents: the pan/orbit handlers cancel INSIDE a gesture, long before any re-render (verified: a synthetic RMB-down reads `null` in the same tick).
- **NO UI-sync want-term is needed, by construction**: the toggle exists only on a PINNED popover, so follow can never be armed with zero inspectors open, and `agentInspectIds.length > 0` already pins agent UI-sync ON — snapshots keep flowing for a free-running direct-render model. (Follow reads `agentsRef`, the render SNAPSHOT — which is also why it is dimension- and compile-target-agnostic.)
- **THE CONTROLLER — a REST LATCH + a CRITICALLY DAMPED SPRING + a FILTERED VELOCITY FEEDFORWARD** (the standard game-camera composition; rationale, option survey and the full measurement table: [docs/INVESTIGATION_FOLLOW_CAMERA.md](docs/INVESTIGATION_FOLLOW_CAMERA.md)). Frame-rate independent, `dt` clamped to 0.1 s so a tab-away can't fling the camera. Per axis, in world units:
  - **the spring** is what makes it *acceleration*-based — the camera carries a **velocity state** (`followCamVRef`) and is accelerated toward the target, so it picks up smoothly and, being critically damped, never overshoots. `FOLLOW_OMEGA = 6` rad/s, stepped with **Unity SmoothDamp's exact rational form** `exp = 1/(1 + x + 0.48x² + 0.235x³)`, `x = ω·dt` (unconditionally stable — `dt` is only clamped, never fixed).
  - **the feedforward** is what makes it **CATCH UP**. A spring tracking a target at constant speed settles at a lag of *exactly* `2v/ω`, so the target is `agent + (2/ω)·fv` — the lag is cancelled **by construction, with nothing to tune**. `fv` is the agent's velocity **DERIVED from successive render-snapshot positions** (EMA, `FOLLOW_VEL_TAU = 0.35` s) — deliberately NOT the engine's `vx`/`vy`: that needs no worker plumbing, avoids the "an un-requested snapshot field silently reads as 0" trap, and it works for models that move agents with **Set Agent Position** and leave `vx`/`vy` at zero (Ant Necrophoresis).
  - **the raw velocity sample is speed-clamped to ONE WORLD EXTENT PER SECOND** — load-bearing: a teleport implies ~60 worlds/s and the feedforward would fling the camera far past the agent (**144 px of overshoot without the clamp, 0.0 px with it**). No real agent approaches that speed, so the clamp never clips genuine motion.
  - **the deadzone is ONLY a REST LATCH** — it no longer *shrinks* the error and is no longer a set-point; it just decides when the controller may stop writing, gating on the position error **AND** the camera velocity **AND** the filtered agent velocity (so it can't fire mid-flight and can't stall a genuine slow follow). Because the spring drives both to zero it latches in **finite** time, which is what keeps a parked agent at **zero writes and zero draws**. Radii: 2D `FOLLOW_REST_FRAC_2D = 0.03` × min(canvas w, h) screen px + `FOLLOW_REST_V_PX_2D = 1.5` px/s (both screen-defined, so zoom-independent); 3D `min(0.02 × maxGridDim, 0.04 × cam.dist × maxGridDim)` world units + `0.002 × maxGridDim` per second — the `cam.dist` term tightens it when zoomed in (`cam.dist` is a MULTIPLE of the largest grid dimension).
- **What this REPLACED, and why the old law trailed.** The shipped controller was a first-order ease toward the deadzone **EDGE** (`k = 5`/s, `dz = 0.15` of the canvas, `FOLLOW_AIM_INSIDE = 0.9`), whose steady state for a constant-velocity agent is `e_ss = v/k + dz·AIM` — **two structural error terms**, so the followed agent permanently **rode the deadzone boundary** (measured in-browser: **mean 78.40 px against a 78.75 px deadzone**), and at low speed it **saw-toothed between 44 and 79 px** as it latched inside and the agent walked back out. `FOLLOW_AIM_INSIDE` existed only because an exact-edge target is approached asymptotically, so `|e| ≤ dz` never latched and a parked agent wrote every frame forever. **All three are gone**: the rest latch tests a condition the spring actually reaches, so nothing has to aim short of its own target. *(The general lesson survives the rewrite: an easing loop whose stop condition is "inside X" must either aim strictly inside X or stop on a condition it genuinely reaches.)*
- **Torus**: the agent↔camera delta is folded **shortest-way per axis** before the rest test, the spring AND the derived-velocity sample (everything the controller touches is a DELTA, so no absolute position is ever compared across a seam), so a seam crossing never sends the camera the long way across the world. After the move, 2D wraps the camera world-centre into `[0, W)` **only when infinity mode is OFF** — infinity TILES the torus, so a camera walking off the edge still shows the right thing and the pan is left CONTINUOUS (no jump); without tiling the single drawn copy would scroll away from the agent, so the wrap is required (the background jumps by one world width, mirroring the agent's own teleport). 3D always wraps (the volume is drawn once — there is no tiling).
