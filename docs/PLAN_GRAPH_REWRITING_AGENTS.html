Graph-Rewriting Automata on the Bond-Graph Agent tier

Illustrated plan. Design authority: IMPACT_MAP_GRAPH_REWRITING_AGENTS.md · Phases: PLAN_GRAPH_REWRITING_AGENTS.md · Execution: HANDOFF_GRAPH_REWRITING_AGENTS.md

A Graph-Rewriting Automaton evolves the graph itself by local rules. The agent tier is already ~70 % of one. This plan closes four gaps and makes the authoring surface a table and a handful of verbs — never a gluing morphism.

1 · The headline — one node replaces nine

A homogeneous rule on a graph can only read its neighbours as an order-independent multiset of states. Today that means hand-wiring a gather and a counter per state value.

The census node lowers to exactly the nine nodes on the left before any compiler runs — the expandComposites pattern. Zero per-target emit; JS, WASM and WebGPU all work by construction, because each target's capability gate inspects the flattened graph.

2 · The authoring model: census → table → verb

The rule is a table you can look at. Seeded Randomize rolls a new rule; the Overseer sweeps rule space and reports which rules grow, die, or blow up — which is literally the GRA research workflow.

The invariant that makes it correct

I2 — bond symmetry. A bond is one object stored twice. Every write must land in both slots, and every compaction must move all fields together.

The highest-risk edit of P2 is the swap-with-last compaction in breakBond / freeAgentSlot. A field added to the store but missed there corrupts silently on the first bond removal. The 500-generation form/break audit is written first, and watched failing, before the store changes.

7 · How we know it is right — the test oracles

Every oracle below is either a lemma (true by construction, zero literature risk) or a differential test against already-verified shipped code. Nothing in the verification depends on recalling a paper correctly.

O1 — the handshake lemma every phase

Checked every generation. Catches asymmetric bonds, half-applied form/break, and bonds not cleaned up on death — the entire bookkeeping bug class.

O6 — cubic degree preservation P5 · P7

triangle split : ΔN = +2 ΔE = +3 invariant : E == 3N/2 check : 3N/2 + 3 == 3(N+2)/2 ✓

Every new node has 1 external + 2 triangle edges = degree 3; the outer neighbours keep degree 3. So min deg == max deg == 3 and E == 3N/2 hold at every rule step — the end-to-end GRA test, and it only becomes satisfiable once P4 makes the operation atomic.

O7 — the strongest early oracle: differential vs. a shipped model P1

The library already ships Game of Life on Agents, which finds neighbours by proximity. Phase 1 ships Life on Bonds, which finds the same neighbours through bonds and counts them with the new census node. Same neighbour set ⇒ the two must produce cell-for-cell identical state sequences over 200 generations.

Any divergence is a census bug, located immediately. No literature is involved, and the reference is code that is already verified. Backed up by the classic pattern oracles: block stable, blinker period 2, glider translates by (1,1) every 4 generations.

8 · Phases

One fresh session per phase. Each ends with a Completion Report; the orchestrator reads only that to decide whether to continue or re-plan. Phases marked refine get their handoff written just before launch, using what the preceding phase actually found.

The rule every phase obeys: land all three agent targets, or reject cleanly through the existing capability gate with a user-visible reason. Never a silent JS clamp. If an assumption in the handoff proves false — stop and report; the orchestrator re-plans.

9 · Deliberately out of scope

  • Rotation systems / planarity preservation — the bond store is a set with swap-with-last compaction; there is no cyclic order around a node.
  • Genus / Euler characteristic — depends on faces, hence on a rotation system.
  • Motif matching beyond the 1-ring — avoiding subgraph isomorphism is the whole reason this design stays simple.
  • Hypergraph rewriting — hyperedges are not bonds.
  • The cell-grid graph mode — that is INVESTIGATION_GRAPH_CA.md, a different substrate whose CSR adjacency is the wrong structure for mutation. This milestone is the answer to that document's Phase 6.
