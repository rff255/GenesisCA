Generic Agent Platform

Agents become first-class authorable entities. They own their own attributes and own local variables; they read/write the CA grid (the environment/field) under a per-cell-attribute agent-access permission; they reach for the full node catalogue (nearby + bonded sources, filter/join/gather/pick/ set-many) — enough to replicate a totalistic CA on a grid of agents and author stigmergy models; and the user spawns them from the graph (Create → set → Add) in a once-only Agent Init Event.

Companion to docs/PLAN_GENERIC_AGENT_PLATFORM.md. Plan only. SUPERSEDES the earlier scope: cell|agent|both discriminator — "shared" attributes make no sense (no 1:1 cell↔agent).

1 · Agents sit ABOVE the CA (the access model)

Agents → CA: yes. CA → agents: never. Agents read the grid (sense the environment) and write back (deposit/consume) through the field bridge, gated per cell attribute by an agentAccess permission (none / read / read&write). CA cells can never read agent attributes — that's structural (the cell compilers never see agentAttributes). Agent attributes are accessed only by other agents (own-state, or another agent by id).

3 · Local Variables — a parallel agent set

Like attributes, agent variables are a separate array agentVariables[]; the Agents tab's Local Variables section sources them. A load-time migration moves agent-referenced cell variables across (the boids accumulators), which also fixes the agent-WASM array-var false-positive.

5 · Graph-authored spawning + the Agent Init Event

The Init Event runs once per Reset — a zero-agent setup function (no per-agent idx). The user loops and spawns; Create Agent returns a real id used by the Set-by-id nodes; Add Agent To World commits.

Agent Init Event→ Loop(N)→ Create Agent (x,y,type) → id→ Set Agent Attribute(id, …)→ Add Agent To World(id)
Engine-safety (from the adversarial review). (B1/B2) The spawn / staged-request buffers are JS-store-only fields — they must NOT enter computeAgentMemoryLayout's fixed field arrays (that would shift every baked WASM offset and break the shipped JS↔WASM bit-parity); spawn clamps the graph to JS, so the store is non-wasm-backed anyway. (B3/B4) The Init Event is a once-only setup fn, NOT a clone of divisionEvent's per-agent body; it gets its own buildAgentInitParams↔Args ABI pair and fires on Reset only, not recompile. (B5) A graph-spawned agent is unbondable the same step (the bond-request pass precedes spawn-apply) — bond it next generation. In-behaviour Create stages a deferred request applied in the structural phase (mirroring Divide).

6 · Acceptance target — ant necrophoresis (stigmergy)

Ants = agents (carrying bool); corpses = a corpse cell field (agentAccess: read&write). Pick-up/drop probability is sigmoidal in local corpse density — dense piles attract drops (autocatalytic), so piles self-enhance. Pure stigmergy: agents interact only through the field.

Behaviour Step→ Apply Force (random walk)→ Read Cells Under(corpse) → density→ if carrying?
empty-handed: pPick = 1/(1+e^(k(density−d0)))→ Affect Cells Under(corpse −1)→ Set carrying=true
carrying: pDrop = 1/(1+e^(−k(density−d1)))→ Affect Cells Under(corpse +1)→ Set carrying=false

Acceptance: a uniform corpse field concentrates into piles over time (the spatial-frequency histogram goes flat → clustered). The Game-of-Life-on-agents sample (a static grid: Get Nearby Agents → Get Agents Attribute → Group Count → GoL rule → Set alive, with customForcesOnly:true + momentum:0) is the genericity proof.

7 · The #1 hazard — three ABI-mirror pairs
