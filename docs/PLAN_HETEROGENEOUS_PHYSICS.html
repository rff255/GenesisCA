Heterogeneous Agent Physics

Per-agent participation and per-pair interaction classes for the agent engine — illustrated plan. Companion to docs/IMPACT_MAP_HETEROGENEOUS_PHYSICS.md. Design only; nothing is implemented.

1 · Where we are today

Every engine physics knob is a single scalar on the model. The force pass reads only x, y, z and radius for a neighbour — there is no per-agent hook of any kind to consult.

Verified: sim.worker.ts:2647–2673 / 2844–2870 · agentWasm/compile.ts:4928–5017 · agentWebgpu/forcePass.ts:259–286.

Two things that already ARE heterogeneous

works today

Bond springs are per-pair. bondRestLength and bondStiffness are per-slot arrays, and Form Bond exposes both as wired inputs (0 ⇒ default). So Table Lookup[myClass][theirClass] → Form Bond.stiffness already works — but only at formation time.

works today

Contact distance is per-pair, because sij = rᵢ + rⱼ. Bigger agents push apart from further away. Not an opt-out though: at rᵢ = 0 you still get pushed by rⱼ.

A dormant design, found in the tree. CenterBasedConfig.bondSpringMatrixId already exists — documented verbatim as “lookupTable model-attribute id giving per-type-pair bond stiffness λ + rest length L”, with its neighbours calling themselves “used when no spring matrix is set.” A repo-wide grep finds exactly one hit: the declaration itself. The per-pair spring matrix was designed and never implemented. Ask #1 revives it.

2 · The answer to ask #2

Yes — you must turn the engine force off model-wide and rebuild it in nodes. Particle Life is exactly that model. Here is what it costs.

The two corrections to “you’d have to do it manually”: (1) bond springs are the exception — already per-pair; (2) it is not free — 13 nodes per neighbour per agent per step, a duplicated neighbour walk, and the body runs twice per unordered pair because a graph loop has no symmetry.

3 · The proposal — one hook, two modes

The spine. Every engine pair-force coefficient becomes scalar × mij, where mij is resolved from agent i’s and agent j’s own values. Absent modulator ⇒ m = 1 ⇒ byte-identical.
the collapse

agentScale over a bool attribute with product is the participation mask: 1×1=1, anything else 0. So “mask” and “strength” are one mechanism — and one phase closes ask #2.

no new editor

A class matrix is an ordinary lookupTable model attribute with both axes bound to a tag agent attribute — exactly what Particle Life already declares. It inherits the shipped matrix editor, Randomize and the rename cascades.

multiplicative

Not replacing. 1.0 is the byte-identical no-op, the global slider stays meaningful, and a matrix entry in [-1,1] flips repulsion into attraction — Particle Life semantics for free.

6 · ⚠ The ordering hazard

The code already states the invariant this feature would break — verbatim, in agentWebgpuRuntime.ts:1636:
“the force pass touches only geometry/velocity, never a user attribute, so its position here is immaterial.”

Two further correctness items ride along: the Δt clamp must take the table maximum (effectiveAgentDt reads the scalar stiffnesses only — which is already a latent too-loose dt for any bond formed above the config λ), and reach must not be modulated in these phases, or the spatial-hash bin edge silently truncates the stencil.

7 · Phases

H0
Ordering + clamp honesty fold into H1

Move the GPU attr-commit before the force pass; make effectiveAgentDt take the max reachable stiffness. Pure correctness pre-req.

H1
The modulator hook · agentScale mode closes ask #2

One per-agent read (i hoisted, j per pair) + one multiply, on all three targets. Zero new bindings, zero new SoA fields, zero ABI params. Covers repulsion, adhesion, charge and the positional projection — including the bool-attribute participation mask.

gate byte-identity · force parity (JS↔WASM bit-exact) · bench A/B · real-GPU on both force pipelines

H2
The classMatrix mode closes ask #1 (forces)

Widens the same hook. Free on JS/WASM; the one genuinely new WebGPU surface is auxF32 on the force shader — in both force bind-group layouts, with the bufAux predicate widened, and the term emitted from one shared helper so the canonical and mirror pipelines cannot drift.

H3
Implement bondSpringMatrixId closes ask #1 (bonds) independent — can go first

Touches no pair loop: resolves λ/L from a K×K table at Form Bond / auto-bond time into the per-bond slots that already exist. Revives a schema field written for exactly this. Lowest risk of the three.

8 · Deferred & rejected

ItemVerdictWhy
Per-pair range / cutoffdeferred — own phase It alone feeds the spatial-hash bin edge. The mitigation is known and cheap (take the table max), so it is scheduling, not a blocker — but a wider bin edge multiplies the candidate count, which is the perf lever.
Per-agent motion moderejected for now Needs a per-agent branch in the integrate block and the position commit on three targets, and collides with the “skip force + integrate + commit together” rule. agentScale = 0 everywhere plus momentum: 0 gets most of the way.
Per-pair Δt / drag / momentum / maxSpeedrejected Integrator properties of a single agent, not pair quantities. (A per-agent maxSpeed is a separate, easy feature.)
Per-pair growth / lifespanrejected Same reason. Growth already has a per-agent opt-out via targetRadius.
bondTypeLabel driving a live spring lawdeferred The per-bond class slot exists, rides the ABI, and is read by nothing but the inspector. A small step after H3 — but it moves the coefficient back into the per-bond loop, so it needs its own measurement.
Editing a live bond’s λ / L after formationdeferred Set Bond Attribute reaches user bond attributes only. Today the graph route is break + re-form, costing a generation.
Porting Particle Life into the enginefollow-up Its rules matrix is exactly a classMatrix on μ_R — but attractMin/attractMax are range tables, blocked on the deferred row above. Do not re-run its generator: the shipped file has deliberately drifted.
A dedicated per-agent physics SoA fieldrejected Would add a field gate, five mirror sites and per-agent bytes to duplicate storage the user already declares. Reusing an attribute is why the WGSL cost is zero bindings.
Non-multiplicative modulationrejected Replacement makes the global slider inert whenever a modulator is set — the enabled-but-inert control the UI doctrine forbids.
Doctrine-only (build nothing)rejected Declines both asks and leaves per-agent engine-collision opt-out inexpressible at any price. Its one real contribution — documenting the pattern — is kept as the Help FAQ.

9 · Open questions for the owner

  1. Phase order. H3 is independent, lowest-risk, and revives a field already written for it. Ship it first, or does ask #2 (H1) come first?
  2. Default combination rule. product is proposed (it makes bool ⇒ mask fall out). Is min — “the softest agent wins” — wanted for collision instead?
  3. Class attribute type. Tag-only (bounded K, the shipped axis kind), or allow an integer attribute with an intRange axis?
  4. Should H1 modulate adhesion, or leave it alone until it gets a capability of its own (it currently rides only useBondingPhysics)?
  5. The §6 reorder touches shipped GPU dispatch. Part of H1, or its own reviewed change?
